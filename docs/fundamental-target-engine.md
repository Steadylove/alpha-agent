# Fundamental Target Engine · V1

独立基本面估值服务。网站信号台每个 ticker 的“估值”入口及 `/fundamental/TICKER` 只读取已保存结果；2H/4H 共用版本。没有更改买卖点、评分、资金账本、止损、Discord/Telegram 消息或发送流程。

## 已实现的覆盖

V1 支持有足够证据的 USD 盈利公司，使用 **Forward P/E** 情景估值。金融、房地产、ETF/基金、ADR、亏损、无法核实现金流或异常非经营性盈利、有效同行不足的公司显示原因，不能用缺失项补零生成目标价。

数据来自 FMP stable API：公司资料、年度与最新季度利润表、同年度资产负债表/现金流、年度分析师预测、同行候选。公司提交文件的公开链接存在时优先作为财报来源，其他字段保留无密钥的接口来源。来源报告期、披露日期、采集时间分开记录；供应商未提供预测发布时间，所以不将当前预测回填到历史。

FMP 明确 analyst estimates EPS 为 non-GAAP，财报 EPS 为 GAAP。模型中同业和目标公司的前瞻 EPS 都用相同供应商口径，GAAP 财报仅用于盈利质量核验。V1 不擅自生成 Normalized EPS；发现需要调整的情形进入待复核/不可估值状态。

## 可复算的公式与假设

1. 基准日为本次估值的 UTC 日期。6M/12M 目标日期分别向后滚动 6/12 个日历月，月末按实际最后一天截断。
2. 每个目标日期使用其后 12 个月的 non-GAAP EPS。年度预测按所覆盖的实际财年天数分摊，例如跨两个财年的 EPS 为 `FY1 EPS × 覆盖天数 / FY1 天数 + FY2 EPS × 覆盖天数 / FY2 天数`。没有未来财年就留空，不外推；这是均匀摊分假设，不建模季节性。
3. 同行必须为不同发行人、同一 FMP industry、USD、非金融/房地产/ADR/基金，且能计算当前 NTM EPS。每个所需财年至少 3 名分析师覆盖，最多 8 个有效同行。异常 Forward P/E（低于 2 或高于 100）排除而不强行截断到边界。
4. 同行候选先来自 stock-peers；不足时可从已保存 screener 的同目录行业寻找候选，再实时核对 FMP industry。仍不足时尝试 company-screener。目录仅用于发现候选，不读 RPS、涨跌或评分；最多核查 20 个候选。
5. 同业 `当前观测股价 / 当前 NTM EPS` 的 25%、50%、75% 分位数分别为 Bear/Base/Bull 倍数。各情景目标为相应 Low/Avg/High EPS × 对应倍数。
6. 情景加权目标为 `Bear × 20% + Base × 55% + Bull × 25%`。这是未校准的固定情景权重，区间不是价格路径预测、到价承诺或统计置信区间。V1 置信度统一保守标记 low。
7. FCF 只是已实现盈利的质量检查，不伪装成 DCF 或第二套目标价模型。V1 没有把当前市场价强行转换为合理价值。

`12M Target` 指情景加权目标，Base 目标在展开的情景表内展示，避免重复命名。价格空间为 `目标 / 已保存报价 - 1`；可以为负，报价有采集时间且不是实时行情。

### 投资者首屏与模型敏感性

页面同时呈现已保存报价及其时间、最近后台复核、估值证据日期、有效同行数和 V1 预设低置信度。“已保存”不代表覆盖全部市场信息，也不代表目标价经过概率校准。

6M / 12M 的价格位置图对比同一版本的 Bear / Base / Bull 情景与已保存报价。横向位置只是数值比较，不是股价未来路径；报价不在情景区间内时仍完整展示，不截断到边界。

当版本内至少有 4 家有效同行时，研究详情会逐次删除 1 家，用其余同行重新计算原有分位数和 12M 加权目标，展示变化区间和相对原目标的最大绝对变动。EPS、情景权重及已发布目标不变。这衡量样本依赖，不是统计置信区间；只有 3 家时显示样本不足，避免使用低于原模型最低要求的样本。

本地预览可设置 `FUNDAMENTAL_DEMO_SYMBOLS=ACME`。它只添加页面“测试数据”标记，不写入财务归档、目标价或交易输入；不能将真实标的结果标为演示后混入生产研究。

## 更新、失败与 AI

独立 systemd timer 每小时 `:17` 扫描，默认每轮最多 12 只，优先缺档和到期标的。股票范围为已保存信号池、账本持仓、Catalyst 中真实持仓/信号关联，不因估值改变股票池。

- 正常证据每天复核一次；首次/失效时补充。财报、最新季度、盈利预测变化、同行有效样本变化会重算；同一同行样本的 Forward P/E 中位数相对上一估值累计变化至少 15% 会重算；90 天执行兜底复核并滚动预测窗口。
- 目标公司单纯股价变化不会改目标；不足 15% 的同业市场倍数移动不会每天推动目标漂移。
- 已发布的高重要度公司指引、并购、监管、融资等事件会使估值待复核。它们不自动证明盈利变化。未建模的实质影响需人工确认后显式解除；普通财报通过财务输入变化重算，不要求每次人工放行。
- 暂时采集失败保留旧目标并标记 stale，6 小时后可重试。缺数及不支持类型显示 unavailable。来源覆盖问题单独展示，不能把“未收录事件”写成“没有重大事件”。
- DeepSeek 只解释采集到的财务证据和代码计算结果，输出带引用的摘要、1–3 个依赖因素、1–5 个风险。不接收主策略信号，不调整数值/倍数/权重，也不生成 Buy/Hold/Sell 评级。
- AI 失败不影响数字发布。缺失的解释可在下次复核补生成，形成新发布版本，目标、假设和原有效期不变。已有完整解释且基本面未变时不重复付费调用。
- AI 解读保存 `contractVersion`，同时固定提示词和证据输入结构。无该字段的早期归档按 V1 校验；后续升级必须新增版本并保留旧版本，不能因为提示词改动使旧估值解读失效。

## 存储与历史边界

`$MARKET_DATA_DIR/snapshots/fundamental-target/TICKER/` 下：

- `latest.json`：最新复核状态和当前/上一有效估值。
- `history/<version-id>.json`：不可覆盖的估值版本，包括原始输入、情景、来源、可选 AI 解释及修订归因。
- `checks/<check-id>.json`：每次复核的可用/失效状态证据。
- `index.json`：版本与复核索引。

修订的“盈利贡献”和“倍数贡献”使用对称分解，二者之和必须等于新旧加权目标差；这是算术归因，不代表商业因果。模型归档含规则版本和输入指纹，数值及 AI 证据引用在读取时校验。

历史关联需要准确带时区的 `entryAt`。只选当时已发布、当时最近复核仍 ready、复核距离入场不超过 48 小时且未过有效期的版本。只有日期的账本记录不猜入场时刻；初次生成的目标不会补填到更早买点。页面历史接口为 `GET /api/fundamental/TICKER?entryAt=ISO_TIMESTAMP`，无任何生成副作用。

### 只读覆盖诊断

```bash
npm run fundamental:coverage
npm run fundamental:coverage -- --symbol=AAPL,MSFT
```

默认检查 AAPL、MSFT、ADBE、ORCL、CRM；单次最多 10 个显式标的。输出 JSON 包含逐标的缺项、有效同行数、检查时间和无凭据的接口状态，不保存估值、不调用 AI、不推送消息。全部可估值返回退出码 0，覆盖不完整返回 2，参数或运行错误返回 1。HTTP 429 是限流，不能当作公司缺少基本面信息，也不应立即反复运行诊断。

上述实测后增加了本轮限流保护：首次收到 429 后，已发出的有限并行请求允许收尾，后续候选和标的不再发起请求；诊断明确返回 `rate-limited`，新一轮任务才重置。后台保留旧估值并标记 stale，首次无估值则 unavailable，写明限流原因并沿用 6 小时后复核。此修复通过模拟限流测试验证，没有为验证而再次消耗线上额度；上述 48 次请求仍是修复前的原始实测记录。

### 下一轮接入修复与限量复核

复核确认一个采集缺陷：供应商返回的候选曾提前截取前 8 个，把“最多 8 个有效同行”和“最多检查 20 个候选”混用了。当较后位置才有合格同行时可能误报不足。现允许在总共 20 个候选的预算内继续检查，最终仍最多保留 8 家；不放宽行业、币种、发行人或预测口径。

每个 provider 实例现在默认将实际请求的开始时间至少隔开 1000ms，命中本轮缓存不占请求名额。已排队请求在开始前重新检查 429 状态；断路后不再送出，也不计作已发送请求。这只降低本模块的请求突发，不能增加账号总额度或协调其他模块的请求。依据：[FMP 请求限额说明](https://site.financialmodelingprep.com/insights/platform/what-happens-when-you-hit-your-fmp-api-limit)。认证继续使用 [FMP 官方支持的 apikey 请求头](https://site.financialmodelingprep.com/developer/docs)。

## 网站摘要与历史入口

- 信号台和每日复盘的买点行展示 6M / 12M 情景加权目标、Bear–Bull 区间、相对留档报价的空间，以及状态、版本时间和报价时间。摘要明确属于最新留档，可能晚于所查看复盘；不能视为历史买点当时已知。

- 每日复盘的“信号时估值”传递 `JournalSignal.signalTime`；资金账本持仓与买入模拟成交的“模拟入场时估值”分别使用 `entryDate` / `fill.date`。卖出成交不作为新入场，历史账本也可以查询。
- 账本日内时间按已知 UTC 存储口径规范化。仅日期、无效日期、未来时间不补成准确时刻。信号台只掌握 K 线开始标记的信号不推算收盘时间；有模拟持仓时才关联该持仓的准确入场时刻。
- 带 `entryAt` 的抽屉与完整页展示历史核对状态并展开原版本；不存在当时有效留档时明确提示，不用后来版本补填。同一股票切换不同时间会取消旧请求并隔离结果。
