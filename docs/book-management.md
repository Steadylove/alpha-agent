# 资金账本的保存与历史版本

`/fund` 的当前账本按记账池和起点，从空仓重算整个窗口，生成 4H / 2H 两套结果。改名单或起点仍使用这一计算口径，不表示从修改日开始执行真实交易。

- 编辑名单和载入方案只产生草稿。确认差异后，“保存并重算”先保存配置，再统一重算。
- 重算期间保留上次结果并显示状态。保存失败和“配置已保存、重算失败”分别提示，失败后可重试。
- 每笔投入比例是入场时权益的 `1 / N`，不限制持仓只数；现金不足时跳过新信号。当前账本为 10%，历史回看可选择比例。
- 每次成功计算保留独立版本；历史弹窗可查看旧名单、起点、净值、持仓、成交，并与当前结果对照。查看历史不修改当前配置。

## 数据一致性

当前结果只有在起点、规范化名单、投入比例、策略版本和行情版本均匹配时才标为最新。旧格式结果仍可查看，首次重算后升级为带版本信息的新格式。

行情版本来自 `MANIFEST.json`，包括实际最新 K 线时间。本地旧数据布局没有清单时使用 CSV / RPS 文件元数据。每次重算清除准备好的行情及 RPS 内存缓存；计算前后核对输入版本，期间发生变化则保留原结果并报错。

行情发布先创建 `.market-updating`，传完 CSV / RPS 后最后发布清单，再移除标记。标记存在或远程清单不可读时不计算、不标为最新。同步失败时应修复同步并完成清单发布，再移除标记。

修改交易或信号算法时，递增 `src/lib/fund/liveBooksRevision.ts` 的 `LIVE_BOOK_ENGINE_VERSION`；冻结策略参数变化由配置哈希识别。

## 存储与部署

当前结果为 `live-books.json`，历史结果在同级 `book-versions/<版本号>.json`，本地及 VPS 都在归档完成后原子替换当前文件。原版本不可覆盖，保存失败向调用方返回错误。

页面 API：

- `GET /api/fund/live-books`：当前结果和是否过期。
- `POST /api/fund/live-books`：重算并保存，共享进行中的计算。
- `GET /api/fund/live-books?history=1`：版本摘要。
- `GET /api/fund/live-books?version=<id>`：指定版本完整结果。

本次变更需要一起更新网页、计算 worker、`deploy/market-http/desk-http.mjs` 和 nginx 配置；仅更新网页无法提供 VPS 历史读取能力。升级存储服务后再恢复新版 worker / 网页计算。备份 desk 目录时应包含 `book-versions`。

## 验证

自动测试覆盖行情过期、常驻缓存失效、计算期间改配置、重复重算、远程保存失败、不可变历史、旧格式兼容和真实本地 HTTP 存储服务。运行 `npm test`、`npm run typecheck -- --incremental false`，并对改动文件运行 ESLint。
