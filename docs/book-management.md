# 资金账本的连续记账与历史版本

## 2026-09-09：标准 2H 重建

旧 2H 把 13:30–16:00 合成一根的口径已作废。新口径为美东 09:30 / 11:30 / 13:30 / 15:30 四根，末半小时独立成根。网站、回测和 worker 统一从已有 1H 全历史生成 2H，缺少所需 1H 时失败，不回落到旧 2H CSV。行情截至时间也从 1H 换算，兼容短交易日。

账本以 `twoHourVersion: 2h-rth-4bars-v1` 标记新口径。首次更新不继承旧 2H 的收益、持仓、待成交指令或风控状态，而是从当前建账起点、当前股票池重新计算；4H 仍衔接原账本。以后新 2H 继续正常连续记账。旧 2H 不再出现在当前结果、历史比较和已存回看成绩中；混合归档中的 4H 保留，归档文件本身不改写。

`npm run market:rebuild-2h` 可从现有 1H 一次性重建所有 2H CSV（包含扩池），无需访问行情供应商。任意所需股票缺少 1H 或时间轴不合法，整次重建拒绝发布；全部成功才替换目录。日更也先更新 1H，再全量重建 2H，避免新旧棒按时间戳混合。读取端从 1H 生成，因此无需等待旧 CSV 目录重建才开始使用正确行情。

原三根口径的 2H 回测指标和搜参成绩均已失效。交易参数暂时保留，2H 年化基数修正为 252 × 4；不会通过修改 ATR 倍数去拟合某笔 TV 交易。Pine 2H 脚本同步四根时段说明，并只在收盘确认后显示买卖信号。对拍时还需统一行情来源、复权和参数。

`/fund` 的当前账本分别保存 4H / 2H 的现金、持仓股数、成本、止损状态、待成交指令和统计状态。更新或日推只处理上次记账时间之后的 K 线，沿用已有净值。历史回看仍按所选名单从起点重新测算。

## 修改股票池

- 编辑名单和载入方案先产生草稿；“保存并更新”保存池版本，再推进两本账本。
- 每次变更记录名单、版本号与保存时间。CSV 的时间戳为 UTC 的 K 线起点，新名单只作用于保存后新开始的 K 线。
- 新加入的标的不追溯买入旧信号。移出的标的不再新增买入，尚未成交且在移出生效后才执行的买单会取消；已有持仓继续按原策略管理退出。
- 多次改池后再更新，也逐段使用当时生效的名单。清空池子表示关闭后续开仓资格，已有持仓继续管理。
- 远程保存核对之前的版本，两个并发请求只能有一个成功，历史版本不能被覆盖。

例如改池前净值为 1.20，新池子生效后继续在原有现金和持仓基础上记账，不把过去按新名单重新算成另一份成绩。按日展示的当天净值仍会随着当天后续 K 线更新。

## 新建一期与旧账本升级

“新建一期”是独立操作：从所选起点以净值 1、空仓建立新账本，原账本仍归档。仅调整股票池不需要新建一期。

旧格式结果没有恢复状态。首次升级会用原名单和原截至时间复原状态，并核对净值、历史曲线和持仓；核对成功后保留原展示结果并向后记账。不能复原时停止更新并保留原成绩，不以新测算覆盖。升级之后，即使过去行情修订，也不重新处理已记账的时点。

持仓缺少后续报价时保留持仓和最后报价，不按旧价格虚构平仓；缺少恢复持仓所需的数据或内部状态损坏时，更新失败并保留原结果。

## 数据、保存与日推

当前结果只有在起点、建账批次、池版本、投入比例、策略和行情版本均匹配时才标为最新。行情版本来自 `MANIFEST.json` 的发布版本及实际最新 K 线时间。本地旧布局没有清单时使用 CSV / RPS 元数据。

每次更新清除准备好的行情与 RPS 缓存，并核对计算前后的输入版本。行情同步以 `.market-updating` 标记保护，最后发布清单再移除标记；同步中不计算。

当前结果为 `live-books.json`，包括连续恢复状态；每个成功版本在同级 `book-versions/<版本号>.json` 归档后才原子替换当前文件。池时间线保存在 `signal-pool.json` 的 `revisions`。备份 desk 目录时需一起保存这些文件。

页面和日推共用同一个更新入口。重复请求共享进行中的计算；必须保存成功才生成待推送的当前账本。失败时保留上次结果并支持重试。每笔投入仍为当时权益的 1/N，当前账本默认 10%，不限制持仓只数。

## 接口与部署

- `GET /api/fund/live-books`：当前结果和过期状态。
- `POST /api/fund/live-books`：衔接现有账本、推进新行情并保存。
- `GET /api/fund/live-books?history=1`：历史版本摘要。
- `GET /api/fund/live-books?version=<id>`：指定版本结果与当时的池变更记录。

需要一起更新网页、计算 worker 和 `deploy/market-http/desk-http.mjs`；仓库的 `Deploy Market HTTP` workflow 在推送后打包并部署 worker / 存储服务。旧账本升级失败时应检查原行情与策略，不能删掉缓存来冒充连续记账。

修改算法时递增 `src/lib/fund/liveBooksRevision.ts` 的 `LIVE_BOOK_ENGINE_VERSION`；已有连续账本仍保留历史结果，后续推进使用部署的策略。
