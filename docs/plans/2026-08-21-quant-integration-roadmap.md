## 0. 这份文档是什么

`轻量级量化投研/` 下的四份 Pine Script 是一套完整的三层决策系统,目前只能在 TradingView 里跑。
本工作总纲把「移植到 alpha-agent」这件事拆成 6 个阶段,每阶段独立可验证、独立可交付。

每个阶段有自己的详细执行计划文档,列在下面的「计划文档」列里。
总纲只负责:范围划分、依赖顺序、验收门槛。具体代码在阶段计划里。

## 3. 各阶段范围与验收门槛

### Phase 1 · MPR 引擎(纯计算 + 历史校准)

**计划文档:** `docs/plans/2026-08-21-phase1-mpr-engine.md`

**范围:** 纯函数实现五力场 ECDF、三域聚合、传导路径判定、5D 下跌概率、系统风险分。
不碰数据库,不碰前端,不碰 Discord。输入 bars,输出逐日 MPR 序列。

**验收门槛(硬性):**
1. 所有 vitest 单测通过,含手算验证的序列基础函数。
2. **与 TradingView 对拍**:在 MPR 指标里选 10 个不同 Path 的日期,导出
   `path_id / f1..f5 / prob_5d_down / market_risk_score`,TypeScript 实现的
   输出与之逐项吻合(浮点容差 0.5)。这是 Phase 1 唯一的真值来源。
3. 校准表产出:2011-01-04 至今逐日跑出 Path 序列,给出「各 Path 下未来 5 日
   实际下跌频率 + 样本数」的表格。

**为什么门槛 2 不可跳过:** 五力场里有多处 Pine 语义细节(`ta.percentrank` 的
窗口是否含当前 bar、`ta.ema` 的播种方式、`var` 变量的跨 bar 状态),靠读代码
无法 100% 确定。有 TradingView 会员就有真值,不用猜。

#### Task 6 校准结果(2026-08-21,3928 个交易日,2011-01-04 → 2026-08-20)

> ⚠️ 以下数字**未经 TradingView 对拍验证**,推迟原因见本节末尾。
> 可用于判断方向与量级,不可作为硬编码常数的依据。

```
Path            样本   占比    5D下跌频率  5D跌>3%   5D平均收益  模型预测概率
P0 稳态自洽      469   12.8%      42.6%      6.4%      +0.12%       24.9%
P1 跨市场暗流    374   10.2%      29.1%      8.3%      +0.38%       50.0%
P2 相变扩散     1296   35.3%      38.0%      3.2%      +0.25%       79.9%
P3 微观漂移      803   21.9%      44.5%      3.1%      +0.05%       50.9%
P4 破位确认      729   19.9%      37.9%     11.9%      +0.59%       84.1%

全样本基准下跌频率: 39.1%
```

**结论一:路径分级对 5 日方向没有预测力。** 下跌频率在 29%~45% 之间平坦震荡,
不随 Path 序号单调上升。P0「健康顺风」的下跌频率(42.6%)反而高于
P2「相变扩散」(38.0%)与 P4「破位确认」(37.9%)。P1 更是完全反向——
29.1% 显著低于 39.1% 的基准,是个温和看涨信号,与其「暗流预警」的标签相反。

**结论二:概率输出严重高估。** P2 报 79.9%、P4 报 84.1%,实际分别只有 38.0% 与 37.9%,
偏差约 2 倍。HUD 上那个「5D下跌概率」当前不可直接展示给用户。

**结论三:唯一有效的是尾部风险识别。** `5D跌>3%` 一列有真实区分度:
P4 = 11.9%、P1 = 8.3%,而 P2/P3 只有 3.1%~3.2%。P4 捕捉到约 2 倍于常态的大跌概率。
配合 P4 同时拥有最高平均收益(+0.59%),说明 **P4 识别的是「高波动区制」而非「下跌」**——
暴跌与暴涨同时放大。这对仓位管理有用(降杠杆),对方向判断无用。

**结论四:根因是 max 聚合与阈值不匹配。**

```
指标        中位数    >=50 占比   >=75 占比
domVol       45.0       23.7%       18.6%
domCred      68.3       70.1%       41.3%
domSpot      73.4       76.8%       48.0%
```

`domCred = max(F4, F3)`、`domSpot = max(F5, F1)` 取的是两个 ECDF 分位的最大值。
两个独立均匀分布取 max,理论中位数是 70.7 而非 50。但 σ 分级阈值仍沿用 50/75,
导致这两个域天然有 70%~77% 的时间处于「异动」、41%~48% 的时间处于「临界」。
于是 P2 占了 35.3% 的交易日、P4 占了 19.9%——一个「临界扩散」警报每三天响一次,
自然失去信息量。

若要让 max 聚合后的分位保持与单一分位相同的尾部概率,阈值应改为
√0.5 ≈ **70.7** 与 √0.75 ≈ **86.6**。这是 Phase 2 的候选修正,
但**必须等 Task 7 对拍通过后再动**——现在改就无法区分「原版如此」与「我移植错了」。

**结论五:引擎在真实危机日的行为正确。** 8 个历史暴跌日全部命中 Path 4、
risk 100、damage 85,F2 期限结构 98~100、F4 信用 77~100:

| 日期 | 事件 | Path | F2 | F4 |
| --- | --- | --- | --- | --- |
| 2015-08-24 | 人民币贬值闪崩 | 4 | 100 | 100 |
| 2018-02-05 | Volmageddon | 4 | 100 | 77 |
| 2018-12-24 | 圣诞夜暴跌 | 4 | 99 | 100 |
| 2020-02-24 | 新冠开跌首日 | 4 | 100 | 92 |
| 2020-03-16 | 熔断 -12% | 4 | 98 | 100 |
| 2022-06-13 | CPI 爆表进熊市 | 4 | 98 | 100 |
| 2024-08-05 | 日元套息平仓 | 4 | 100 | 91 |
| 2025-04-07 | 关税冲击 | 4 | 100 | 100 |

说明力场计算本身是合理的,问题出在阈值与概率映射,不在数学基建。

#### Task 7 对拍:已决定推迟(2026-08-21)

**决定:** 不做 TradingView CSV 对拍,直接进 Phase 2。

**理由:**

1. Phase 2 唯一要动手改的两处——Path 0 兜底空洞、σ 阈值与 max 聚合失配——
   都是**读 Pine 源码**得出的结论,不依赖移植是否忠实。前者是 `if/else if`
   链的覆盖缺口,后者是 `math.max(f4, f3)` 这一行的数学性质(两个独立均匀分布
   取最大值,中位数为 √0.5 ≈ 70.7)。移植对错不影响这两条。
2. 8 个历史暴跌日 100% 命中 Path 4 且 F2/F4 同时打到 77~100,
   这种吻合度排除了粗粒度的移植错误。
3. 唯一有效信号 P4 由 `spyDamage` 驱动,该式仅含「距 20 日高点回撤」与
   「是否跌破 EMA50」两个判断,出错空间极小。
4. 对拍在 Phase 2 会自然变成零成本:MPR 前端面板展示的字段
   (F1~F5 / Risk / 期限比率 / IEI-HYG 比率)与 TradingView HUD 完全相同,
   两边并排即可核对,无需专门导出 CSV。

**残余风险:** 若 ECDF 窗口边界有偏差,受影响的是 F1/F3/F5 的绝对分位数值,
进而使上面那张校准表的百分比产生位移。结论的**方向**(不单调、概率高估、
仅 P4 有尾部信号)不会因此翻转。

**因此,上表数字一律视为「待验证」,不得作为任何硬编码常数的依据。**

**必须守住的约束:** 「5D下跌概率」字段**不上线**。
它报 79.9%~84.1% 而实际为 37.9%~38.0%,无论移植正确与否都不可展示。
P4 在前端只能标注为「高波动区制」,不得标注方向。

**恢复方式:** 对拍脚本与 Pine 导出补丁已就绪并保留在仓库中。
任何时候想验证,导出 CSV 到 `tmp/mpr-tradingview.csv` 后执行 `npm run compare:mpr` 即可。

**工程决策(均由实测数据决定,非估计):**

| 决策 | 依据 |
| --- | --- |

「敞口 80%~100%」,而校准显示真实历史上 **63.1% 的 Path 0 是判定树兜底落入**
(大盘已回撤且有域承压)。照搬会在最不该满仓的时候建议满仓。

改为展示 `macroPhaseReading()`(`src/lib/scoring/mprReading.ts`)产出的修正判读:

- Path 0 按三域压力区分「三域全静」与「承压未定 · N 个域异动」,后者明确说明
  这是原版判定树的覆盖空洞;
- Path 4 标注为「高波动区制」并附上有统计支撑的尾部风险(5 日跌超 3% 概率 11.9%),

- 一律不输出仓位建议,该约束由 `tests/mprReading.test.ts` 的一条测试守住。

这同时解决了未决问题 4——修正判读是由 `dom*` 与 `pathId` 推导的纯函数,
不落库、不改判定树,因此原版 Path 与修正判读并存,Task 7 对拍不受影响。

### Phase 3 · 4Q-Alpha RS + 对数 MACD 一买/二买 ✅ 已完成(2026-08-21)

**范围:** 4Q-Alpha 动能评分、对数规约 MACD 底背离(一买)、右侧金叉确认(二买)、
40 只标的池回填与历史校准。

**口径裁定:** 用户拍板「以 `轻量级量化投研/` 里做的为准」,即以 Pine 源码为唯一口径。
三份文件里的 RS 其实是**三套结构不同的算法**,不是同一算法的三个参数版本:

| 来源 | 周期与权重 | 基准 | 映射 |
| --- | --- | --- | --- |
| 产品文档第 142 行 | `0.10/0.40/0.30/0.20` @ `21/63/126/252` | 对标 SPY 比率 | 全池截面分位 |
| MPR Pine 第 41 行 | `0.40/0.20/0.20/0.20` @ `63/126/189/252` | 对标 SPX 比率 | 7 段分段映射 |
| **轮动雷达 Pine 第 115 行** | **`0.20/0.40/0.20/0.20` @ `21/63/126/252`** | **无基准,纯绝对涨幅** | **平滑饱和函数** |

MPR 那套是 MPR HUD 自己的个股相对强度,轮动雷达那套才是中层轮动用的。
Phase 3 采用轮动雷达版,标的池同样按 Pine 的 40 只(文档写 100 只)。

**交付物:**
- `src/lib/scoring/rotationRs.ts` —— 4Q 加权涨幅 + 饱和映射
- `src/lib/scoring/logMacd.ts` —— 对数规约底背离,一买/二买
- `src/lib/scoring/rotationUniverse.ts` —— 40 只标的池
- `series.ts` 补充 `crossSeries` / `barsSinceSeries` 两个 Pine 原语
- `scripts/backfill-rotation-history.ts`(`npm run backfill:rotation`)
- `scripts/calibrate-rotation.ts`(`npm run calibrate:rotation`)
- 33 条新测试,累计 86 条全绿

**数据现状:** 40/40 标的回填完成,新增 134014 根日线。
其中 CRWV(351 根)样本不足 400,信号不可信;GEV/CRWV 至今零信号。

**校准结果(134240 个 bar-day,503 次一买 / 277 次二买,信号密度 0.58%):**

和全样本基准直接比,一买只有极弱的正超额(20 日 +0.55pp、60 日 +1.18pp),
在 n≈500 且信号高度时间聚集的情况下,这个差距落在噪声范围内。二买则全程无超额。

但**信号天然集中在低 RS 区间**(一买 RS 中位 39,基准中位 59.8),
直接对照会把「低 RS 标的本身的表现」记在信号头上。改成**同 RS 区间内对照**后
出现清晰的单调结构:

| RS 区间 | 一买 n | 20 日超额 | 60 日超额 |
| --- | --- | --- | --- |
| RS <30 | 87 | **-3.95pp** | **-4.04pp** |
| RS 30-45 | 249 | +1.46pp | -0.27pp |
| RS 45-60 | 129 | +1.02pp | +1.49pp |
| RS >=60 | 38 | +2.65pp | +15.13pp |

**结论:** 底背离在强势股身上是「回调买点」,在弱势股身上是「接飞刀」。
RS<30 区间两个周期都显著为负,是全表最稳健的一条结论(n=87,机理也自洽)。
RS>=60 那格的 +15.13pp 样本只有 38 个,不能当真。

二买没有超额的原因也清楚了:它额外要求 `EMA(high,24) < EMA(low,90)`,
即只在长期深度弱势区触发,恰好锁死在上表最差的那一格(RS 中位 36.8,p90 仅 48.5)。

**由此推翻产品文档的漏斗设计:** 文档第 152 行写「强制只在 RS ≥ 70 中选股,
一票否决 RS < 40」。但一买信号里 RS≥70 的只占 3.8%(19/503),RS<40 的约占一半——
照文档执行等于把这套点火信号整个关掉。Pine 本身没有这道闸门,
它只用 RS 给**已持仓标的**做权重分配,这是自洽的。文档的三层漏斗按字面无法实现。

**Phase 4 的取舍留给下一阶段决定:** 是按 Pine 原样不设 RS 闸门,
还是采纳校准结论加一道 RS≥45 的过滤(可保留约 1/3 信号且两个周期都为正超额)。

**已知的 Pine 原版怪癖(忠实保留,未修):** `buy1_sig = ta.barssince(cond_buy[1]) > 10 and cond_buy`
在 `cond_buy` 首次触发前 `barssince` 为 `na`,而 `na > 10` 在 Pine 中为 false,
因此**每只标的历史上的第一次点火会被静默吞掉**。修掉会与 TradingView 输出不一致,
故保留原样。

**未做:** TradingView 逐点对拍(与 Phase 1 同样的理由,依赖手工导出 CSV)。
当前验证靠 33 条单测 + 真实数据上的信号密度与分布合理性。

#### 方法论教训:未来函数把结论完全颠倒了

第一版回测用 t 日的 Path 缩放 t 日的收益、用 t 日的持仓状态吃 t 日的涨跌。
但 Path 依赖当日收盘价、开仓价就是当日收盘价,两者都要到收盘才知道。
带着这个未来函数时,「仅 Path 4 减仓」在**所有**维度上都优于恒定满仓
(年化 67.5% vs 53.9%,回撤 19.1% vs 29.0%);把敞口与持仓都滞后一天之后,
它变成在所有维度上都更差。差别全部来自「凭空吃到触发当天那根大阴线」。

回测脚本已在注释中钉住这一点,后续任何择时类评估都必须先确认滞后口径。

**Phase 4 收尾状态:** 仓位就是 `RS_i / ΣRS_j`,总敞口恒定 100%。

**验收门槛:** 给定一段历史行情和一笔模拟建仓,止损价逐日演进与手算一致。

### 未决问题 4:Path 0 兜底空洞(移植期间发现的原版缺陷)

**现象:** Pine 的传导路径判定树里,Path 0「稳态自洽」是 `else` 兜底分支,
不是「三域全静」。当 `spyDamage ∈ [60, 70)` 且三域有压力时,四个分支全不匹配:

- Path 4 不匹配 —— 要求跌破 EMA50 **且** `damage >= 70`
- Path 2 不匹配 —— 要求 `damage < 60`
- Path 1 不匹配 —— 要求 `sigmaSpot == 0`
- Path 3 不匹配 —— 要求 `sigmaVol == 0` 且 `sigmaCred == 0`

于是掉进 `else`,被标为「🟢 稳态自洽 · 三大域共振健康顺风 · 建议敞口 80%~100%」。

**严重性:** 在合成数据上,**83.2% 的 Path 0 天数属于兜底落入而非真正全静**。
最坏样本:信用域与现货域双双顶格(99.2 / 99.2,sigma 均为 2)、SPY 已从 20 日高点
回撤 2% 以上,系统仍建议满仓。

**当前处置:** Phase 1 只做忠实移植,不改判定树——改了 Task 7 的 TradingView 对拍
必然失败,就失去了验证移植正确性的唯一手段。缺陷已用
`tests/mpr.test.ts` 里的「已知缺陷:Path 0 是兜底分支」一条钉住,
防止以后被人当成 bug 误「修」。

**处置结果(Phase 2,2026-08-21):** 真实历史上 **63.1%(296/469 天)** 的 Path 0
属于兜底落入,确认高频,因此按预案引入了修正变体。

实现方式与预案略有不同:没有新增 Path 5,也没有改判定树或加数据库列,
而是用一个纯函数 `macroPhaseReading()`(`src/lib/scoring/mprReading.ts`)
从已落库的 `dom*` 与 `pathId` 推导修正判读。好处是原版 Path 原样保留、
Task 7 对拍随时可做,而前端展示的是修正后的含义。

前端表现:兜底落入的 Path 0 显示为「承压未定 · N 个域异动」并注明这是覆盖空洞,
真正三域全静才显示「三域全静」。逻辑由 `tests/mprReading.test.ts` 的 7 条测试守住。
