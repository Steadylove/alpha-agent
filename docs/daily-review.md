# 每日复盘

首页 `/` 与 `/review` 展示按美东交易日归档的收盘复盘；`/?date=YYYY-MM-DD` 读取历史。旧 `/rotation` 永久跳转首页，原轮动页面、读取模块、任务及 API 已移除。原策略账本、共享回测引擎和数据库历史表保留。

## 数据链

VPS 收盘任务顺序：补齐行情 → 宏观/板块快照 → Gamma 抓取 → 2H/4H 账本计算 → `npm run review:build` → 原有推送。

- `scripts/build-daily-review.ts`：生成器，可用 `--date=2026-09-18` 指定已收盘交易日。
- `src/lib/review/`：市场/行业、期权结构、信号评价、账户归因、历史读取及持久化。
- `src/components/review/`：首页、日期切换、强度周期、评分版本/周期/来源/分数/股票筛选、原始理由及事后验证。
- `deploy/market-http/cron/alpha-daily-quant.sh` 与手工补跑的 GitHub workflow 均已接入。
- Web 只读生成的快照，不在请求中回测或调用付费行情接口。更新沿用部署后的每日收盘任务。

在 VPS 仓库手工生成：

```sh
MARKET_DATA_DIR=/var/lib/alpha-agent/market \
MARKET_DATA_BASE_URL='' \
SIGNAL_JOURNAL_DIR=/var/lib/alpha-agent/desk \
LIVE_BOOKS_PATH=/var/lib/alpha-agent/desk/live-books.json \
npm run review:build
```

依赖已有 Alpaca 凭证；生产 `ALPACA_FEED=sip`。不配置行情凭证仍可读取已有价格缓存，但未验证的信号结果保持缺失。`GEX_HISTORY_DIR` 可指定原始 Gamma 留档目录，默认 `.cache/gex`。

持久化位置：

| 文件                                     | 用途                                         |
| ---------------------------------------- | -------------------------------------------- |
| `snapshots/daily-review/index.json`      | 已发布交易日索引，最后写入                   |
| `snapshots/daily-review/YYYY-MM-DD.json` | 市场、期权、行业、当日信号、账户复盘         |
| `snapshots/daily-review/journal.json`    | 全部信号的后续成熟结果                       |
| `snapshots/daily-review/context.json`    | 供新告警记录信号前已知的市场状态             |
| `snapshots/gex-history/YYYY-MM-DD.json`  | 按真实报价日整理的 Gamma 历史                |
| `review-prices/SYMBOL.json`              | 成对的原始/仅拆股复权日线缓存                |
| desk `signal-entries/ID.json`            | 原有不可覆盖的触发快照，继续作为评分唯一来源 |

文件使用临时文件加原子替换。旧日重跑不使最新 journal 回退；已核验结果不会因临时断源被抹除；缺项可在数据补齐后重跑。远程网页读取失败不会退回构建机旧数据。首次上线需要生成一份快照后才有内容；无快照时展示明确空态。

## 计算口径

### 市场状态 v2

页面分成四层，均为收盘描述，不提供上涨概率或仓位指令：

1. **市场体温**：上涨股票 / 有效样本 × 100；变化独立以 pp 展示。
2. **市场状态**：价格、广度水平与变化、VIX、参与结构的规则判断。
3. **市场结构**：成长/小盘/防御/广泛参与；小盘相对 SPY；11 板块扩散。
4. **宏观环境**：利率与美元的共同变化，独立于内部市场状态。

`src/lib/review/engine.ts` 是纯计算模块，版本 `market-state-v2`。所有输出带三日输入、参数、证据、缺项、覆盖样本与名单日期。以下均为**描述性初始参数**，未经收益寻优或盈利验证。

| 维度     | 初始规则                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 价格     | ±0.2% 内为噪音；±1% 为单指数强涨/强跌。SPY/QQQ/IWM 多数表决，三者均超过 ±1% 才称普遍强涨/强跌；SPX 展示及完整性检查，不与 SPY 重复投票 |
| 体温水平 | ≥60% 广泛参与，≤40% 偏弱，中间为均衡；有效覆盖至少 95%，名单至少 100 股                                                                |
| 体温变化 | ±5pp 内稳定；超过 ±5pp 改善/恶化；超过 ±15pp 明显改善/恶化                                                                             |
| VIX 变化 | ±2% 内稳定；超过 ±2% 温和变化；超过 ±5% 明显变化                                                                                       |
| VIX 水平 | <15 低位，15–25 常态，25–35 偏高，≥35 高位；不单独决定市场状态                                                                         |
| 相对表现 | QQQ−SPY、IWM−SPY 使用 ±0.3pp 噪音带；防御取 XLP/XLU/XLV 日均涨幅减 SPY                                                                 |
| 板块扩散 | 仅 11 大板块；日涨幅 >0.2% 的数量与昨日相比增加/减少至少 2 个，定义扩张/收缩；另列 5D 涨幅 >0.2% 的数量                                |

状态优先级与互斥规则：

1. 核心指数/VIX/当前广度缺失 → Unknown。次要字段缺失独立记录，不填 0。
2. 至少两个股票 ETF 明显下跌、体温 ≤40%、VIX >+2% → Risk-Off。
3. 当前有显著冲突且近三交易日至少出现两次 → Transition。冲突为 SPY >+0.2%、IWM <−0.2%、体温下降超过 5pp、VIX 上升超过 2%；或价格中性、体温下降超过 15pp、VIX >+5%、板块收缩。
4. 多数 ETF 上涨但体温 <50% → Narrow Rally。
5. 多数上涨、VIX ≤+2%、体温 ≥50%、升温 >15pp、板块扩张且小盘不落后 → Risk-On Expansion。
6. 三者上涨、VIX ≤+2%、体温 ≥60%、至少 7 板块上涨且小盘不落后 → Broad Risk-On。
7. 多数上涨、VIX ≤+2%、升温 >5pp、体温 ≥40% → Risk-On Recovery。
8. 多数上涨、VIX ≤+2%、体温 ≥50% → Risk-On。
9. 当前存在明显上涨与下跌的 ETF，且近三日至少出现两次这类分化、无上述显著冲突 → Rotation。
10. 其余完整数据 → Neutral，不再默认 Transition。

成长领先是独立结构标签，可以与 Recovery 并存。Small-cap Confirming 仅表示日相对收益位于噪音带内，不表示它上涨。宏观环境不会覆盖这些状态。

### 宏观数据与时间

`npm run review:macro` 可单独刷新；每日 `market:refresh` 已包含该步骤，无额外密钥需求。数据写入 `snapshots/macro-observations.json`，网页只读，不在请求中访问供应商。

| 指标         | 数据源 / 含义                                                                                                      | 方向噪音带  |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | ----------- |
| DGS10 / DGS2 | [FRED 10Y](https://fred.stlouisfed.org/series/DGS10)、[FRED 2Y](https://fred.stlouisfed.org/series/DGS2)，名义利率 | ±3bp        |
| DFII10       | [FRED 10Y 实际利率](https://fred.stlouisfed.org/series/DFII10)                                                     | ±3bp        |
| DXY          | Yahoo `DX-Y.NYB` 美元指数                                                                                          | ±0.3%       |
| WTI / Gold   | Yahoo `CL=F`、`GC=F` 近月连续期货，非现货；换月可能影响变化                                                        | ±1% / ±0.5% |
| BTC          | Yahoo `BTC-USD`，UTC 自然日日线，与美股收盘不同步                                                                  | ±2%         |

- 每个观测记录 `observationDate`、`availableAt`、`fetchedAt`；`availableAt` 为本系统首次取得该数值的时刻，**不冒充供应商原始发布时间**。修订增加新版本，不覆盖旧值首次可见时间。
- 利率 4.00% → 4.05% 是 +5bp。负实际利率是有效值，空值不能变成零。
- FRED 最多允许落后一个股票交易日，标“延后发布”；其他序列必须对应复盘日，否则标过期。变化需要连续观测；不把跨缺失日的变化算成单日收益。BTC 以连续自然日比较。
- 宏观标签只比较 **10Y、2Y、DXY 同一观测日**的变化：至少两个明显上升且没有下降 → Restrictive；至少两个明显下降且没有上升 → Supportive；全部在噪音带内 → Neutral；其他完整组合 → Mixed；缺失或过期 → Unknown。页面标出共同比较日期。
- 标签表示利率/美元压力，不等于完整金融条件指数。实际利率、油、金、BTC 为辅助观察，不单独推断避险资金流，不决定内部市场方向。
- 抓取失败保留旧记录和错误信息；过期检查会使标签降级，绝不把旧值算作当日稳定。Yahoo 日线有延迟风险。
- 历史补算可以使用当前取得的历史宏观序列，必须标记 `reconstructed`，不声称历史逐时可见。新信号只接收 `builtAt <= signalTime` 且属于前一交易日的已发布上下文。

### 行业强度

11 只 SPDR 大板块与 SMH / IGV / KBE 三个细分行业**分别**按 20 个交易日收益作 0–100 截面排名，并计算相对 1/5/20 个交易日前的变化。并列使用中间秩；组内任一 ETF 缺失时不偷偷缩小样本，另一个完整组仍可计算。3 个行业的排名很粗，不与 11 板块的百分位混排。旧版历史记录保留 14 ETF 混排口径，页面注明。

20D 强势板块数量只统计 11 大板块中涨幅为正且跑赢 SPY 的数量；与当日板块扩散分别展示。

日历优先使用已有交易所日历；较早历史覆盖外使用 SPY 日线。广度采用当前留档的标普名单，页面给出名单日期；历史重算存在成分股存活偏差，不声称使用当时成分股。

### 版本与升级

- 外层快照仍为 `version: 1`，新增可选 `market.engine` / `market.macro`，旧文件保持可读。
- 重跑保留 `publishedMarket`（首次发布状态与时间）；老日重算标记 `reconstructed`。旧信号的 `marketContext` 永远保留首次记录，不根据新引擎重写。
- 新信号上下文包含完整规则版本、输入、维度、宏观和数据质量。Signal Journal 按市场状态 **与规则版本**分组，避免口径混合；缺历史上下文不事后填补。
- 首次部署后，在既有行情任务环境（`MARKET_DATA_DIR` 等）中执行 `npm run review:macro`，然后 `npm run review:build`，即可初始化最新页面。不需重算账户或发送消息。
- 历史补算可使用 `npm run review:build -- --date=YYYY-MM-DD`。应先备份旧归档；它更新页面研究结果并保留首次状态，不改变原始买点评分。
- 后续评估应分开看标签切换频率、Unknown 比例、各状态成熟信号表现；需要累计前向样本，不能凭标签更细就声称交易更赚钱。

### 期权结构

沿用已有 Cboe GEX 算法，不新增方向预测。仅使用实际报价日匹配的快照；只有前一交易日及相同 DTE 范围才比较 Flip / Walls / Net GEX，标注正负转换。原抓取脚本的按时间留档可恢复相邻日结构，缺档时显示缺失。

### 信号留档与结果

- 不读取 previews / research 目录，不从历史 K 线重新找买点冒充当时推送。
- 原交易身份（symbol、周期、strategyKey、entrySignalTime）及第一份评分继续不可覆盖。页面按原始版本展示；V4 风险维度不会当作 V5 Sector，V4 CVD 名称不会误判为缺失。
- 触发后 15 分钟内留档的记录归实时，其他迟到/重放记录单列。此分类说明到达及时性，不能单独证明策略好坏。
- T+1/3/5 从信号后的交易日开始，使用该日收盘价相对触发价。停牌或缺行情不顺延，不填 0。
- MFE/MAE 为后续五个完整交易日最高/最低变化，包含基线 0；不包含触发当日，因为日线高低点可能发生于信号之前。未满五日显示观察中，窗口缺失不声称完整。
- 不能把全复权日线与原始告警价直接相除。生成器成对拉取 raw 与 split 日线，以信号当日 `raw.close / split.close` 为比例，把之后价格还原到触发时股数单位。结果处理拆股，但不含现金分红。
- 收益是信号之后的价格表现，不等于能按该价格成交的策略盈亏，不计成本、滑点和退出规则。
- 历史页面屏蔽所选日期之后的结果与当时尚未收到的信号。
- ≥80/≥90、2H/4H、市场状态及板块统计仅比较同评分版本、同来源的完整评分；未成熟与缺数据分别报告。相关性最少 20 个成熟样本，常量因子不计算；相关不代表因果，重复标的/日期不是独立样本。
- 市场状态只记录信号前已发布、且日期与 RPS 前一交易日一致的复盘，不把当日事后状态塞回入场记录。

### 现金策略账本

沿用原连续记账净值，明确是模型账户而非券商实盘。日收益以相邻交易日净值比计算；月收益必须有上月最后一个交易日的净值，缺失保持空缺。2H 沿用现有版本有效性检查。

持仓、现金、最大仓位只读对应日真实账本快照。可从既有不可变 `book-versions` 恢复历史，不用当前持仓倒推。归因使用前后快照中全天未交易且股数未变的仓位：`股数 × 价格变化 / 昨日净值`；剩余当日交易等归入未归因差额。首页显示主要三项、其余全天持仓及残差。

## 验证

核心测试：`tests/dailyReview.test.ts`、`tests/marketStateEngine.test.ts`；既有告警与 desk HTTP 测试覆盖原始留档不可覆盖、鉴权及推送逻辑。

真实数据联调使用 2026-09-17/18 行情、Gamma 和账本归档，以及服务器原始 23 条信号。9/18 共 7 条实时买点；尚无 T+5 成熟记录，不能据此形成五日胜率结论。数据位于忽略目录 `.cache/daily-review-smoke`，不提交进仓库。
