# 每日复盘

首页 `/` 与 `/review` 展示按美东交易日归档的收盘复盘；`/?date=YYYY-MM-DD` 读取历史。旧 `/rotation` 永久跳转首页，原轮动页面、读取模块、任务及 API 已移除。原策略账本、共享回测引擎和数据库历史表保留。

## 数据链

VPS 收盘任务顺序：补齐行情 → 宏观/板块快照 → Gamma 抓取 → 2H/4H 账本计算 → `npm run review:build` → 原有推送。

- `scripts/build-daily-review.ts`：生成器，可用 `--date=2026-09-18` 指定已收盘交易日。
- `npm run review:check`：按真实交易日历检查复盘日期、指数/广度/板块、账户、信号覆盖与到期结果，以及下一交易日期权上下文。结果写入 `snapshots/daily-review/health-review.json`。
- `src/lib/review/`：市场/行业、期权结构、信号评价、账户归因、历史读取及持久化。
- `src/components/review/`：首页、日期切换、强度周期、评分版本/周期/来源/分数/股票筛选、原始理由及事后验证。
- `deploy/market-http/cron/alpha-daily-quant.sh` 与手工补跑的 GitHub workflow 均已接入。
- Web 只读生成的快照，不在请求中回测或调用付费行情接口。更新沿用部署后的每日收盘任务。

VIX / VIX9D / VIX3M 日线以 Cboe 官方历史 CSV 为主；当目标已收盘交易日尚未到齐（包括 HTTP 200 但内容滞后），主任务尝试 Yahoo 对应指数日线补缺，并在采集日志记录备用来源。只接收目标日及以前的有效 OHLC，不覆盖 Cboe 同日值；两源均缺失则仍报缺日。期权链另行校验报价日，不能以旧日链替代。12:30 的宏观补采不包含波动率 CSV 或期权链。

### 每日一次额外补采

`alpha-review-macro.timer` 在北京时间每天 **12:30** 额外运行一次（不是每小时）。08:30 主任务维持原样。

- 只检查最近 5 份已发布复盘的宏观缺项、延迟或过期观测；全部齐全时跳过外部采集。
- 每次补采任务只发起一轮采集。有新观测才更新对应复盘的宏观部分，保留首次发布状态；纯抓取时间变化不重写页面。
- 最新复盘上下文更新仅影响之后的新信号，已留档信号及评分、期权结构、板块和账户均不改写，不发送任何消息。
- 与主任务共用 `daily-quant.lock`；主任务尚在运行则跳过。接口失败保留已有观测，记录错误；供应商仍无数据时继续显示其真实日期。
- 任务使用独立打包脚本，不依赖服务器仓库即时更新。`npm run review:macro:bundle` 后由部署脚本安装，手工补采可执行 `npm run review:macro:retry`（使用上文 VPS 环境配置）。
- 查看状态：`systemctl list-timers alpha-review-macro.timer`；日志：`/var/lib/alpha-agent/logs/review-macro.log`。

宏观采集优先使用美国财政部的 2Y / 10Y 名义收益率、10Y 实际收益率，以及 Alpaca US 的 BTC/USD 完整 UTC 日线。主源失败或未更新时再比较 FRED / Yahoo 备用源的日期；实际来源随每条观测保存，来源变化作为新版本保留首次可见时间。日变化只在相邻、同源观测间计算，不将场所差异误报为价格涨跌。DXY、WTI、黄金仍沿用原来源。

08:30 主任务生成复盘后也会运行已安装的独立补采 worker，沿用主任务持有的锁；12:30 是唯一新增的定时触发。这样不依赖服务器仓库更新就能持续使用新来源，且补采不会重复推送消息。

### 重试与完整性检查

08:30 主任务中 Gamma 采集、复盘生成分别最多执行三次，间隔 45 秒（`REVIEW_RETRY_SLEEP` 可配置）。Gamma 必须通过真实报价日、四标的覆盖、有效合约、来源版本和时间校验后才能替换公共快照或推送卡片；不存在 Flip 交点可保留为未知，不伪造数值。

复盘生成的进程成功退出仍需经过 `review:check`；发现核心数据缺失或信号结果逾期就重试。DXY 等宏观供应商延迟、账户月收益缺基准列为 `degraded` 警告，不填零、不反复重跑整个行情池。两类步骤重试后仍失败，主任务最终返回非零状态；其余正常账户推送维持原流程，失败的 Gamma 卡片不发。消息发送不进入重试循环，避免重复通知。宏观补采后会再次刷新检查报告。

单独检查 Gamma：`npm run review:check -- --stage=gex --file=.cache/gex/latest.json`，报告在 `health-gex.json`。这两个报告只记录检查结论，不会修改原始信号、评分或账户。

在 VPS 仓库手工生成：

```sh
MARKET_DATA_DIR=/var/lib/alpha-agent/market \
MARKET_DATA_BASE_URL='' \
SIGNAL_JOURNAL_DIR=/var/lib/alpha-agent/desk \
LIVE_BOOKS_PATH=/var/lib/alpha-agent/desk/live-books.json \
npm run review:build
```

依赖已有 Alpaca 凭证；生产 `ALPACA_FEED=sip`。不配置行情凭证仍可读取已有价格缓存，但未验证的信号结果保持缺失。`GEX_HISTORY_DIR` 可指定原始 Gamma 留档目录，默认 `.cache/gex`。

持久化位置：

| 文件                                     | 用途                                         |
| ---------------------------------------- | -------------------------------------------- |
| `snapshots/daily-review/index.json`      | 已发布交易日索引，最后写入                   |
| `snapshots/daily-review/YYYY-MM-DD.json` | 市场、期权、行业、当日信号、账户复盘         |
| `snapshots/daily-review/journal.json`    | 全部信号的后续成熟结果                       |
| `snapshots/daily-review/context.json`    | 供新告警记录信号前已知的市场状态             |
| `snapshots/gex-history/YYYY-MM-DD.json`  | 按真实报价日整理的 Gamma 历史                |
| `review-prices/SYMBOL.json`              | 成对的原始/仅拆股复权日线缓存                |
| desk `signal-entries/ID.json`            | 原有不可覆盖的触发快照，继续作为评分唯一来源 |

文件使用临时文件加原子替换。旧日重跑不使最新 journal 回退；已核验结果不会因临时断源被抹除；缺项可在数据补齐后重跑。远程网页读取失败不会退回构建机旧数据。首次上线需要生成一份快照后才有内容；无快照时展示明确空态。

## 计算口径

### 市场状态 v2

页面分成四层，均为收盘描述，不提供上涨概率或仓位指令：

1. **市场体温**：上涨股票 / 有效样本 × 100；变化独立以 pp 展示。
2. **市场状态**：价格、广度水平与变化、VIX、参与结构的规则判断。
3. **市场结构**：成长/小盘/防御/广泛参与；小盘相对 SPY；11 板块扩散。
4. **宏观环境**：利率与美元的共同变化，独立于内部市场状态。

`src/lib/review/engine.ts` 是纯计算模块，版本 `market-state-v2`。所有输出带三日输入、参数、证据、缺项、覆盖样本与名单日期。以下均为**描述性初始参数**，未经收益寻优或盈利验证。

| 维度     | 初始规则                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 价格     | ±0.2% 内为噪音；±1% 为单指数强涨/强跌。SPY/QQQ/IWM 多数表决，三者均超过 ±1% 才称普遍强涨/强跌；SPX 展示及完整性检查，不与 SPY 重复投票 |
| 体温水平 | ≥60% 广泛参与，≤40% 偏弱，中间为均衡；有效覆盖至少 95%，名单至少 100 股                                                                |
| 体温变化 | ±5pp 内稳定；超过 ±5pp 改善/恶化；超过 ±15pp 明显改善/恶化                                                                             |
| VIX 变化 | ±2% 内稳定；超过 ±2% 温和变化；超过 ±5% 明显变化                                                                                       |
| VIX 水平 | <15 低位，15–25 常态，25–35 偏高，≥35 高位；不单独决定市场状态                                                                         |
| 相对表现 | QQQ−SPY、IWM−SPY 使用 ±0.3pp 噪音带；防御取 XLP/XLU/XLV 日均涨幅减 SPY                                                                 |
| 板块扩散 | 仅 11 大板块；日涨幅 >0.2% 的数量与昨日相比增加/减少至少 2 个，定义扩张/收缩；另列 5D 涨幅 >0.2% 的数量                                |

状态优先级与互斥规则：

1. 核心指数/VIX/当前广度缺失 → Unknown。次要字段缺失独立记录，不填 0。
2. 至少两个股票 ETF 明显下跌、体温 ≤40%、VIX >+2% → Risk-Off。
3. 当前有显著冲突且近三交易日至少出现两次 → Transition。冲突为 SPY >+0.2%、IWM <−0.2%、体温下降超过 5pp、VIX 上升超过 2%；或价格中性、体温下降超过 15pp、VIX >+5%、板块收缩。
4. 多数 ETF 上涨但体温 <50% → Narrow Rally。
5. 多数上涨、VIX ≤+2%、体温 ≥50%、升温 >15pp、板块扩张且小盘不落后 → Risk-On Expansion。
6. 三者上涨、VIX ≤+2%、体温 ≥60%、至少 7 板块上涨且小盘不落后 → Broad Risk-On。
7. 多数上涨、VIX ≤+2%、升温 >5pp、体温 ≥40% → Risk-On Recovery。
8. 多数上涨、VIX ≤+2%、体温 ≥50% → Risk-On。
9. 当前存在明显上涨与下跌的 ETF，且近三日至少出现两次这类分化、无上述显著冲突 → Rotation。
10. 其余完整数据 → Neutral，不再默认 Transition。

成长领先是独立结构标签，可以与 Recovery 并存。Small-cap Confirming 仅表示日相对收益位于噪音带内，不表示它上涨。宏观环境不会覆盖这些状态。

### 宏观数据与时间

`npm run review:macro` 可单独刷新；每日 `market:refresh` 已包含该步骤，无额外密钥需求。数据写入 `snapshots/macro-observations.json`，网页只读，不在请求中访问供应商。

| 指标         | 数据源 / 含义                                                                                                      | 方向噪音带  |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | ----------- |
| DGS10 / DGS2 | [FRED 10Y](https://fred.stlouisfed.org/series/DGS10)、[FRED 2Y](https://fred.stlouisfed.org/series/DGS2)，名义利率 | ±3bp        |
| DFII10       | [FRED 10Y 实际利率](https://fred.stlouisfed.org/series/DFII10)                                                     | ±3bp        |
| DXY          | Yahoo `DX-Y.NYB` 美元指数                                                                                          | ±0.3%       |
| WTI / Gold   | Yahoo `CL=F`、`GC=F` 近月连续期货，非现货；换月可能影响变化                                                        | ±1% / ±0.5% |
| BTC          | Yahoo `BTC-USD`，UTC 自然日日线，与美股收盘不同步                                                                  | ±2%         |

- 每个观测记录 `observationDate`、`availableAt`、`fetchedAt`；`availableAt` 为本系统首次取得该数值的时刻，**不冒充供应商原始发布时间**。修订增加新版本，不覆盖旧值首次可见时间。
- 利率 4.00% → 4.05% 是 +5bp。负实际利率是有效值，空值不能变成零。
- FRED 最多允许落后一个股票交易日，标“延后发布”；其他序列必须对应复盘日，否则标过期。变化需要连续观测；不把跨缺失日的变化算成单日收益。BTC 以连续自然日比较。
- 宏观标签只比较 **10Y、2Y、DXY 同一观测日**的变化：至少两个明显上升且没有下降 → Restrictive；至少两个明显下降且没有上升 → Supportive；全部在噪音带内 → Neutral；其他完整组合 → Mixed；缺失或过期 → Unknown。页面标出共同比较日期。
- 标签表示利率/美元压力，不等于完整金融条件指数。实际利率、油、金、BTC 为辅助观察，不单独推断避险资金流，不决定内部市场方向。
- 抓取失败保留旧记录和错误信息；过期检查会使标签降级，绝不把旧值算作当日稳定。Yahoo 日线有延迟风险。
- 历史补算可以使用当前取得的历史宏观序列，必须标记 `reconstructed`，不声称历史逐时可见。新信号只接收 `builtAt <= signalTime` 且属于前一交易日的已发布上下文。

### 行业强度

11 只 SPDR 大板块与 SMH / IGV / KBE 三个细分行业**分别**按 20 个交易日收益作 0–100 截面排名，并计算相对 1/5/20 个交易日前的变化。并列使用中间秩；组内任一 ETF 缺失时不偷偷缩小样本，另一个完整组仍可计算。3 个行业的排名很粗，不与 11 板块的百分位混排。旧版历史记录保留 14 ETF 混排口径，页面注明。

20D 强势板块数量只统计 11 大板块中涨幅为正且跑赢 SPY 的数量；与当日板块扩散分别展示。

日历优先使用已有交易所日历；较早历史覆盖外使用 SPY 日线。广度采用当前留档的标普名单，页面给出名单日期；历史重算存在成分股存活偏差，不声称使用当时成分股。

### 版本与升级

- 外层快照仍为 `version: 1`，新增可选 `market.engine` / `market.macro`，旧文件保持可读。
- 重跑保留 `publishedMarket`（首次发布状态与时间）；老日重算标记 `reconstructed`。旧信号的 `marketContext` 永远保留首次记录，不根据新引擎重写。
- 新信号上下文包含完整规则版本、输入、维度、宏观和数据质量。Signal Journal 按市场状态 **与规则版本**分组，避免口径混合；缺历史上下文不事后填补。
- 首次部署后，在既有行情任务环境（`MARKET_DATA_DIR` 等）中执行 `npm run review:macro`，然后 `npm run review:build`，即可初始化最新页面。不需重算账户或发送消息。
- 历史补算可使用 `npm run review:build -- --date=YYYY-MM-DD`。应先备份旧归档；它更新页面研究结果并保留首次状态，不改变原始买点评分。
- 后续评估应分开看标签切换频率、Unknown 比例、各状态成熟信号表现；需要累计前向样本，不能凭标签更细就声称交易更赚钱。

### 期权结构

沿用已有 Cboe GEX 算法，不新增方向预测。仅使用实际报价日匹配的快照；只有前一交易日及相同 DTE 范围才比较 Flip / Walls / Net GEX，标注正负转换。原抓取脚本的按时间留档可恢复相邻日结构，缺档时显示缺失。

### 信号留档与结果

- 不读取 previews / research 目录，不从历史 K 线重新找买点冒充当时推送。
- 原交易身份（symbol、周期、strategyKey、entrySignalTime）及第一份评分继续不可覆盖。页面按原始版本展示；V4 风险维度不会当作 V5 Sector，V4 CVD 名称不会误判为缺失。
- 触发后 15 分钟内留档的记录归实时，其他迟到/重放记录单列。此分类说明到达及时性，不能单独证明策略好坏。
- T+1/3/5 从信号后的交易日开始，使用该日收盘价相对触发价。停牌或缺行情不顺延，不填 0。
- MFE/MAE 为后续五个完整交易日最高/最低变化，包含基线 0；不包含触发当日，因为日线高低点可能发生于信号之前。未满五日显示观察中，窗口缺失不声称完整。
- 不能把全复权日线与原始告警价直接相除。生成器成对拉取 raw 与 split 日线，以信号当日 `raw.close / split.close` 为比例，把之后价格还原到触发时股数单位。结果处理拆股，但不含现金分红。
- 收益是信号之后的价格表现，不等于能按该价格成交的策略盈亏，不计成本、滑点和退出规则。
- 历史页面屏蔽所选日期之后的结果与当时尚未收到的信号。
- ≥80/≥90、2H/4H、市场状态及板块统计仅比较同评分版本、同来源的完整评分；未成熟与缺数据分别报告。相关性最少 20 个成熟样本，常量因子不计算；相关不代表因果，重复标的/日期不是独立样本。
- 市场状态只记录信号前已发布、且日期与 RPS 前一交易日一致的复盘，不把当日事后状态塞回入场记录。

### 现金策略账本

沿用原连续记账净值，明确是模型账户而非券商实盘。日收益以相邻交易日净值比计算；月收益必须有上月最后一个交易日的净值，缺失保持空缺。2H 沿用现有版本有效性检查。

### Tomorrow Map：变化筛选与每日跟踪

`tomorrow-v1` 完全使用确定性规则，不调用 AI。界面分为 Market Structure、Portfolio & Signal 和 Tomorrow Focus：先列重要变化与原始证据，再列下一交易日需要跟踪的事实。最多五项、同类最多两项；不足五项不补齐，SPX / SPY 的重复结构事件只保留一项。

| 变化来源 | 入选条件                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 市场状态 | 相邻交易日、同引擎版本的有效状态改变；Unknown 不参与                                                         |
| 期权结构 | 同来源、方法版本、DTE 及相邻报价日；Flip / 墙位置 / GEX 状态改变，或关键价位移动至少 0.3%                    |
| 板块强度 | 同一分组与名单，RPS 变化至少 20 点，且当日相对 SPY 同方向变化至少 0.5 个百分点                               |
| 模型账户 | 同周期、相邻交易日有效账户快照的新增 / 移出；缺数据不当作清仓。只描述日末净变化                              |
| 信号跟踪 | 相邻每日快照出现 RPS 走弱 / 回升、板块失去领先且相对收益非正、或收到关联退出记录；仍在持仓的走弱事件优先     |
| 新买点   | 当日实时留档、完整 `quality-v5` 评分 ≥70，且未收到退出记录；同股多周期合并展示                               |
| 宏观异动 | 新鲜、可用的同日变化：名义 / 实际收益率 ≥10bp，DXY ≥0.8%、VIX ≥8%、原油 ≥3%、黄金 ≥2%、BTC ≥5%（均取绝对值） |

这些是用于减少信息噪声的初始描述性阈值，没有通过收益优化，不是交易门槛或盈利概率。价格相对 Flip 的位置与 GEX 正负独立表述。

**每日状态与初始评分分开保存：**

- `daily-review/followups/YYYY-MM-DD.json` 保存 `signal-followup-v1`；复盘内也嵌入相同数据。覆盖最近 20 个交易日的实时信号及当前模型持仓，2H / 4H 分开关联。
- 初始分数继续取不可变的入场快照。每日观察只记录真实可取得的 RPS、板块、关联退出记录和模型持仓，不每天重打五因子评分。
- RPS 同日下降至少 10 点记为走弱，走弱后回升至少 5 点记为回升；≥80 记为强势。判定变化必须有同规则、相邻交易日快照。
- 信号状态区分新触发、已收到退出记录、待复核；没有退出消息不能推导为仍然有效。信号状态与模型持仓分别展示，也不把模型仓位称作券商实盘。
- RPS 必须对应复盘日、来源 / 生成时间有效；不把当前排名填入历史。暂时断源可保留同交易日已归档观测，跨日不复制。退出记录只读，不改原始记录、不发消息。

**发布、补采与次日对照：**

- `review:build` 随既有北京时间 08:30 主任务生成每日跟踪和观察清单；不增加定时器。
- 12:30 宏观补采仅更新宏观候选与最终筛选，保留此前版本。它不重算信号、持仓、初始评分或非宏观候选。
- 清单保存首次生成时间、更新时间、修订序号和旧版内容；无内容变化时重跑不产生新版本。
- 次日对照使用目标交易日美东 09:30 前最后一份实际发布的清单，只记录后来发生的事实。历史重算清单不进入该对照，不制造事前预测胜率。
- 完整性检查要求最新复盘含有效 Tomorrow Map、下一交易日与每日跟踪；历史无新字段仍可阅读，界面临时推导时标明历史重算。

**已有归档初始化：**

```sh
npm run review:tomorrow:init -- \
  --root=/var/lib/alpha-agent/market \
  --journal-root=/var/lib/alpha-agent/desk
```

默认仅预览；加 `--write` 才写入。只初始化缺失的派生字段，写前备份到行情目录 `backups/before-tomorrow-*`。保留原复盘时间、市场、期权、账户、信号及评分；不会访问行情供应商或发送消息。所有初始化清单标注历史重算，历史 RPS 缺档继续显示缺失。部署新版后执行一次即可，后续由原收盘任务持续维护。

持仓、现金、最大仓位只读对应日真实账本快照。可从既有不可变 `book-versions` 恢复历史，不用当前持仓倒推。归因使用前后快照中全天未交易且股数未变的仓位：`股数 × 价格变化 / 昨日净值`；剩余当日交易等归入未归因差额。首页显示主要三项、其余全天持仓及残差。

## Options Market Map：结构状态第一阶段

- `src/lib/options/structure.ts` 提供网页与 Discord 共用的确定性计算。Flip 上下、墙位关系、GEX 正负三者独立，不输出价格或收益预测。
- 默认“接近”阈值为 **0.2%（含边界）**，距离分母是关键价位：`(spot - level) / level * 100`。这是展示规则而非回测优化参数；支持双墙同时接近、单字段缺失、Flip 扫描无解、重合/倒置墙位。
- 页面包含四标的 Gamma Landscape、各关键位距离、原始数值与 Structure Shift。SPX/SPY 不当作独立投票；不把 GEX 符号当作 Flip 位置，也不将墙位迁移解释成新增资金。
- Python 采集器附带 `method_version`、逐字段 `quality`、有效合约数及 Flip 扫描范围；无有效链不发布新的 latest。现价 GEX 使用链上 Gamma，Flip 使用模型重算；正负符号与交点上下不一致本身不算采集错误。
- `gex-history` 保留来源、方法、抓取时间、合约覆盖与校验信息。每日复盘 `options` 新增 `structure` / `shifts` / `meta` / `previousMeta` / `comparison`。外层仍兼容 `version: 1`；结构规则版本为 `options-structure-v1`。
- 结构迁移只对相邻交易日、同 DTE 且来源/方法无冲突的快照计算。缺少历史方法信息会明确标记“仅供参考”；缺失字段不按零计算。
- 旧复盘可直接显示，状态标记为“历史快照补算”；它们不能视为当时实时发出的信号。五因子评分保持原规则；新增信号的期权留档与研究见下方第二阶段。

### 安全补算已有归档

默认只预览，`--write` 才保存。脚本只改 `options` 字段，备份原始复盘到指定数据目录的 `backups/options-structure-*`，不更改信号、账户、市场判断、发布日期，也不发送推送。

```bash
npx tsx scripts/backfill-options-structure.ts --root /path/to/market
npx tsx scripts/backfill-options-structure.ts --root /path/to/market --write
```

部署前运行本次期权相关测试与生产构建；部署后在 VPS 对持久数据目录执行补算。网站有旧数据兼容层，未补算也可展示；后续每日构建会自动保存新状态。补算与每日任务应使用同一个 `daily-quant.lock`，避免同时覆盖复盘。

## 第二阶段：期权结构留档与买点验证

### 数据链路与时间边界

1. 最新交易日复盘构建成功后，发布独立的 `snapshots/daily-review/options-context.json`。从真实交易日历取得下一交易日，保存 SPX / SPY / QQQ / IWM 的原始 GEX、结构、DTE、来源和方法版本。没有下一交易日日历时不发布，不能简单用自然日加一。
2. 发布日期使用**本次实际执行时间**，不能借用旧复盘 `builtAt`。期权上下文与宏观上下文分开保存，宏观补采不会重置它的发布时间。
3. 新买点首次留档时读取上述上下文。它必须是前一交易日快照，报价、抓取和发布时间均不得晚于信号；有 RPS 日期证据时还须一致。纽约无时区报价按夏令时/冬令时转换，歧义时间拒绝。
4. 保存 `EntrySnapshot.optionsContext`（`signal-options-v1`），记录信号时间、冻结时间和完整快照。晚到超过 15 分钟、过期、未来、无法读取等情况保存缺失原因，不阻断原买点处理。
5. `evaluateEntry` 将它带入 `JournalSignal`；以后只更新成熟收益，重复告警和复盘重跑都不覆盖首份结构。旧信号没有留档就继续缺失，不用后来补算的状态填历史。

这研究的是**前一交易日期权结构与下一交易日股票买点的后续表现**。它没有盘中实时 Gamma，也不是在信号时刻重新计算期权链。

### 页面与统计口径

- Signal Journal 新增“期权结构与买点表现”，沿用上方周期、评分版本、最低分、股票、来源和日期筛选。另可选择参考指数、T+1 / T+3 / T+5、计算口径。每个指数分别研究，同一买点不会当四条独立记录。
- 只纳入实时捕获、评分完整、时间校验通过、来源和方法信息齐全的信号。按评分版本、结构规则版本、源、GEX 方法/版本、DTE、接近阈值分开统计。
- 分组为 Flip 位置、墙位关系、GEX 符号三个独立维度。缺失单项进入“未知”组；整份无效、未留档、评分不齐和重放分别列出排除计数。
- 每组列出成熟/待成熟/缺行情数、成熟交易日数、收益均值/中位数、上涨比例、交易日等权均值。后者先对同一天的信号求均值，再对各交易日求均值，降低单日密集信号的权重。
- 5D MFE / MAE 只计算完整五个交易日的观察，使用独立样本数；历史日期视图不读取之后的收益。T+1/T+3/T+5 是信号之后第 N 个交易日收盘，相对原告警价并处理拆股。MFE/MAE 沿用原 Journal，仅覆盖之后五日，不包含信号当日剩余盘中走势。
- 少于 20 条成熟记录或 10 个成熟交易日提示“样本较少”；这只是显示阈值，达到后也不代表统计显著。相同股票及相邻日期仍相关。
- 这些是股票价格变动，不含交易成本、现金分红，不代表期权组合利润或赚钱概率，也不自动调整五因子权重。

### 启用与验证

VPS 每日复盘构建和接收买点的服务需一起更新到本版本。部署后沿用现有每日任务，首次最新复盘构建发布上下文后，新买点才开始累计，不新增定时任务。手动重建也只从实际发布时间起生效，不能补造今天更早信号的证据。

`tests/optionsSignalContext.test.ts` 覆盖节假日日历、时区、发布先后、延迟告警、首次留档不可覆盖、宏观 Unknown 的独立性、历史视图、分组口径及成熟分母。旧真实行情预览仍可能显示 0 条有效冻结记录，这是保留历史真实性的预期结果。
