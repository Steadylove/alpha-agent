# 四份规格的实现对照

记录 `轻量级量化投研/` 下四份文档的落地情况：哪些照搬、哪些改了、哪些没做以及为什么。

四份文档分别是：

| 简称         | 文件                                                    | 性质             |
| ------------ | ------------------------------------------------------- | ---------------- |
| 轮动 Pine    | `美股动能满仓轮动雷达 (全口径NAV精准核算·旗舰版) 1.txt` | 可执行           |
| MPR Pine     | `Market Phase Radar - 市场相变雷达 (专业交易版).txt`    | 可执行           |
| Compass Pine | `MarketCompass量化估值与市场相变决策系统.txt`           | 可执行           |
| 商业化文档   | `商业化产品架构闭环（三层决策漏斗）.txt`                | 产品愿景，无代码 |

**总口径：Pine 为准。** 三份 Pine 是能在 TradingView 上跑出图的东西，商业化文档是一份还没被验证过的设计稿。两者冲突时按 Pine 实现，商业化的说法做成默认关闭的开关（见 `src/lib/config/commercialSpec.ts`），需要时逐项打开。

## 一、四处直接冲突

### 1. RS 算法：截面分位 vs 逐股饱和映射

商业化文档第 146 行要求 `RS_i = PercentileRank(AlphaScore_i, Universe)`，即全池截面排名。三份 Pine 用的都是逐股独立的饱和映射——一只股票的分数只取决于它自己相对基准的表现，与池子里其他股票无关。

Pine 拿不到全池数据（TradingView 单图表限制），这个差异是环境造成的而非设计分歧。项目里两套都有：

- 生产路径用饱和映射（`relativeRs.ts`、`mprAlphaRs.ts`），与 Pine 一致
- 截面分位实现在 `percentileRs.ts`，开关 `COMMERCIAL_SPEC.percentileRs` 默认关

两者的实质区别是：同样的绝对涨幅，在强势市场里截面 RS 会给更低的分。这不是精度问题，是两种不同的选股哲学。

两套的回看周期与权重相同（21/63/126/252、.1/.4/.3/.2），差别在饱和映射除基准而截面分位用绝对涨幅，见后文「截面 RPS 改用绝对涨幅」。

### 2. 入场门槛：RS≥70 / RS<40 一票否决

商业化文档第 148~152 行的硬门槛。**两份 Pine 都没有这条**——轮动 Pine 只有一个默认关闭的 `RSI > 30` 过滤，跟 RS 评分完全是两回事。

项目现状是 `minRs = 30`，这个数**既不在 Pine 里也不在商业化文档里**，是回测校准出来的自加项：30 是唯一让胜率、均值、盈亏比三项同时改善的档位（629 笔 52.8%/+7.07%/2.47 → 508 笔 53.7%/+7.24%/2.70）。往上加会适得其反，RS≥45 砍掉 69% 的成交而均值反降到 +6.32%。

商业化版本实现为 `COMMERCIAL_SPEC.rsEntryVeto`，默认关。

### 3. 保本触发：+5% 提前档

商业化文档第 217 行：常态 +10%，但 Path 2 或 5 日下跌概率 ≥60% 时提前到 +5%。两份 Pine 都只有 +10%。

实现在 `rotationTrade.ts` 与 `stockRisk.ts` 的 `useEarlyBreakeven`，宏观条件由调用方通过 `earlyBreakevenActive(index)` 注入，默认关。

### 4. 组合权重：E_macro 敞口缩放

商业化文档要求 `W_i = E_macro(Path) × RS_i/ΣRS_j`，Pine 只有 `RS_i/ΣRS_j`。

**这一项有反向证据。** 组合层回测（3927 日、已去除未来函数）显示照 E_macro 机械减仓会让收益/波动从 1.18 降到 0.95。已实现为 `COMMERCIAL_SPEC.macroExposureScaling`，默认关；打开前请重跑回测。

## 二、Pine 内部的矛盾与死代码

### 低吸带的 `upside >= 15%` 门槛是死代码

Compass Pine 里先算了一个带 15% 上行空间门槛的低吸带，但紧接着的每个 stage 分支都会无条件覆写它，这个门槛实际上永远不生效。

按 Pine 的**实际行为**实现（门槛不参与计算），同时在 UI 上把 upside<15% 做成提示性标注，让用户看得到这个信息但不改变信号。

### 阶段消歧的两套优先级

Compass Pine 的显示阶段和低吸带用的阶段走的是不同的优先级链。低吸带用 A>E>D>W>C，与显示阶段不同。实测两者有 7.35% 的日子会分歧，主要是显示 Stage W（震荡）但低吸逻辑该用 Stage E（混沌筑底）的情况。

`stockStage.ts` 暴露原始 `StageFlags`，`dipStageOf()` 单独实现低吸口径。

### MPR 的 `act_text` 与本项目的证据结论相反

MPR Pine 的 `act_text` 会根据 Path 给出明确的方向性和仓位建议。但本项目对 MPR 路径做过校准，结论是**没有预测力**，因此 `mprReading.ts` 刻意不给方向性建议。

两者都保留：`mprGuidance.ts` 忠实移植了 Pine 原文并在 UI 上标为「原版指引」，`mprReading.ts` 的证据结论并列展示，附上预测力的说明。用户看得到原版说了什么，也看得到我们为什么不照做。

## 三、数据源替换

### short interest 走 FINRA + SEC，而非 Pine 的 TradingView 财务字段

Compass Pine 用 `request.financial(..., "SHORT_INTEREST", "FQ")`，这是 TradingView 的季度财务字段，项目外拿不到。替换为两个免费源：

| 数据         | 来源                                   | 说明                                                |
| ------------ | -------------------------------------- | --------------------------------------------------- |
| 空头持仓股数 | FINRA `consolidatedShortInterest`      | 免费无鉴权，覆盖全美股 22341 只，轮动池 40 只无缺口 |
| 在外股本     | SEC XBRL companyconcept / companyfacts | 免费，需 User-Agent；仅 ETF 无申报                  |

**比 Pine 原版更新鲜**：Pine 是季度口径，FINRA 是双月度（每月 15 日与月末结算，结算后第 7 个交易日发布，滞后 2~3 周）。

实测轮动池档位分布：`extreme` 2 只（IREN 27.5%、ASTS 19.0%）、`warning` 3 只（IONQ 13.2%、CRWD 10.0%、LITE 9.5%）、其余 `swing`。大盘股普遍在 1% 上下。

两个实现细节值得记一笔：

- SEC 在概念不存在时返回 **HTTP 200 但 body 是 XML**，只看 `res.ok` 会踩空
- 多类别股公司（META、GOOG）不报封面页合计股数，只能回落到加权平均稀释股本。这类都是万亿级大盘、空头占比约 1%，离 8% 档差一个数量级，近似误差不改变档位

**已知失真：** 发过大额可转债的标的（IREN、NBIS），空头持仓里含做市商的中性对冲仓，不是方向性空头，占比会系统性虚高。Pine 的算法照实移植，UI 上对 >=8% 的标的给出提示，判断留给使用者。

### MarketCompass 的 MPR 变体（未实现）

Compass Pine 里内嵌了一套简化版 MPR，与 MPR Pine 的完整版口径不同。没有单独建模块——两套并存只会让用户困惑，且完整版是超集。差异点记录在此，不做实现。

## 五、每日调度

`.github/workflows/daily-quant-jobs.yml`，00:30 UTC 周二至周六（美股收盘后约 4.5 小时，日线已定稿）。

先跑三个 backfill 补日线，再由 `npm run jobs:daily` 按依赖顺序执行：

```
macro-phase → short-interest → rotation-radar → stock-panel → stock-valuation
```

顺序约束有两条：`macro-phase` 的产出被后面三个读取（低吸带 Path 4 冻结、估值的 fsmState/pathId、提前保本的宏观条件）；`short-interest` 必须早于 `stock-valuation`，否则轧空档位读到上一期。

`short-interest` 是唯一的软失败步骤——它依赖 FINRA 与 SEC 两个外部免费接口且双月才换一期，挂掉时估值沿用上一期缓存即可，不该拖垮整条链。

### 调度相关的已知问题

- **日线更新用 `skipDuplicates`,不修正历史。** 发生拆股时旧价不会被重算，需手工清库重跑 backfill。这是 backfill 脚本的既有设计，不是调度引入的
- **`backfill:sectors` 的行业归属部分对全部 40 只标的报「FMP 无行业数据」**，当前订阅不覆盖该接口。ETF 日线正常，板块时钟走的是 `SECTOR_UNIVERSE` 而非逐股归属，因此不受影响；脚本退出码为 0，不会中断 workflow

## 六、调参实验室（/lab）

线上四个面板跑的是 40 只固定标的，那份名单是按今天的认知挑的，回测动能策略会严重虚高。`/lab` 换成标普 500 的时点成分池，专门用来诚实地评估买点。

### 数据

|          | 来源                                                   | 落库                              |
| -------- | ------------------------------------------------------ | --------------------------------- |
| 成分资格 | fja05680/sp500 的成分快照，2718 个变更日、1996-01 至今 | `IndexMembership`，1259 段区间    |
| 日线     | Yahoo，20 年                                           | `BacktestPanel`，653 只、296 万根 |

成分快照压成区间而非逐日展开：展开后是 130 万行，压成区间只有 1259 行，而「某日是否为成分」两种形式都能回答。52 个 ticker 多次进出指数（如 AMD 1996 进、2013 剔除、2017 回归），所以一个 ticker 会有多行。

时点正确性的交叉印证：NVDA 于 2001-11-30 入指，Enron 于 2001-11-26 离开——历史上 NVIDIA 正是顶替安然进入标普 500。

日线不复用 `DailyBar`：296 万行在那张表的逐行结构下约 900MB 且冷加载上百秒，而回测要一次读全池。`BacktestPanel` 按 Float32 打包，单只 80KB、全池约 56MB。两张表的访问模式相反（面板查单只的日期区间，回测读全池），刻意不共用。

### 三条防自欺的约束

1. **时点成分**：某日只在当日成分中选股，截面 RPS 也只在当日成分间排名
2. **同池基准**：每个结果并排给出同一时点池的等权收益，两个口径都给——`benchmark` 每根把全池拉回等权，`buyHold` 首个成分根买入后不动。策略与基准吃同一批数据、同一个窗口，幸存者偏差大体相抵，可信的是二者之差而非任一方的绝对水平。两条基准差一个再平衡溢价，详见「两条基准的口径差」
3. **样本内外分离**：2020-01-01 切分，保留区在 UI 上默认盖住，点开次数计数

### 已知残留偏差

287 个 ticker 在 Yahoo 取不到价格（404 或无数据，串行重试后确认为持续性，非限流），全部排除，覆盖率 653/940。被收购者多以溢价离场（排除后偏低），破产者清零（排除后偏高），净偏差符号不定。因排除同时作用于策略与基准，对二者之差的影响远小于对绝对水平的影响。

### 性能与面板落盘缓存

冷启动原本约 17 秒，其中 **DB 读取 13.5 秒、信号与截面计算仅 1.8 秒**——瓶颈是 47MB 二进制的跨区传输，不是计算。单次回测 190~260ms，常驻 245MB heap。

这批面板是不变的存量行情：整块读走、从不按条件筛选，本质是文件而非数据库内容。
放在云 Postgres 里意味着每跑一次回测就重新下载一遍完整历史。Neon 免费档
**5GB/月出站额度**按 47MB 一次算只够约 106 次，调参搜索期间确实被打满，
超额后 Neon 直接挂起整个 compute（连 `SELECT 1` 都返回 `53000`，线上站点一并失效）。

因此加了本地落盘缓存 `src/lib/backtest/panelCache.ts`：

- 缓存文件 `.cache/backtest-panel.v8`（已 gitignore），用 `v8.serialize`，
  原生支持 `Uint8Array` 与 `Date`、零依赖。格式不保证跨 Node 大版本稳定，
  故读取失败、版本号不符一律当作未命中重新拉取，不抛错
- 快照**与选哪个池无关**，一份服务三个池子：面板查询本就没有 where 条件
  （要哪些标的靠成分区间在本地筛），成分表也小，于是连 `IndexMembership`
  一起整表取回、在内存里按 `index` 过滤
- `BACKTEST_PANEL_REFRESH=1` 强制重新拉取，日线回填之后用它刷新
- 写入失败只返回 false 并打日志：Vercel 之类的部署环境工作目录只读，
  那里本就不该依赖磁盘缓存（函数实例文件系统是临时的，进程内缓存已覆盖
  同一实例的重复请求），退回原有行为即可，不该让一次回测直接失败

效果：本地出站流量降到「首次一次」，准备段 17.7 秒 → **3.4 秒**（省掉的正是那 13.5 秒传输，
剩下的是信号与截面计算本身）。

注意这主要修的是**本地开发**——出站流量正是被反复的本地回测与参数搜索烧掉的。
线上若要同样免流量，需另做决策（面板提交进仓库让构建时打包，或放
Cloudflare R2——它出站永久免费），目前线上访问量低，未处理。

### 绕过数据库重建缓存

`npm run panel:cache`（`scripts/build-panel-cache.ts`）直接从公开源重建缓存，全程不碰数据库。

存在的理由：这批数据原本就是从公开源抓来的——日线来自 Yahoo，时点成分区间来自
GitHub 上那两个 CSV 仓库。所以配额打满、compute 被挂起时不必等下个计费周期。
抓取口径（20 年窗口、`MIN_BARS = 400`、失败即跳过）与 `backfill-sp500-panel` 完全一致，
区别只是终点从 Postgres 换成缓存文件，且不写 `hasBars`——缓存里只放抓到价格的标的，
这本身就等价于 `hasBars = true`。

可中断续跑：进度写在 `.partial` 暂存文件里，重跑跳过已抓到的。**只有完整跑完才
rename 到正式缓存路径**——否则中断会留下一个「可用但不完整」的缓存，回测静默地少一批标的。

实测 1024 个目标、并发 6，**2 分 39 秒**跑完，成功 701 只、失败 323 只（退市或样本不足），
缓存 59.8MB。

与数据库那份的等价性验证（对比同日从 DB 加载的同一配置）：

- 池内标的 **701 = 701**，日期轴 **5027 = 5027** 天，训练/保留区切分逐日相同
- 同池等权基准净值 **4.18x / 1.46x 逐位相同**——这是最强的一条：基准只取决于
  价格数据与成分区间，与 RPS 公式无关，它一致即说明面板等价
- 策略侧数字有差异（信号 2998 vs 3146）是因为两次之间 RPS 口径按规格退回，非数据差异

### 与线上策略的差异

`/lab` 的入场闸门是截面 RPS，`minRs` 置 0；线上 `rotation-radar` 用的是 `rotationRs` 的绝对饱和映射、闸门 30。两者不是同一口径：RPS≥50 会砍掉 84% 的成交，而 rotationRs≥30 只砍掉 19%。

### 参数搜索的结论

`npm run lab:search` 跑 1260 组网格，切分点固定在五年前。两张排序表指向完全不同的答案，这本身就是结论：

- **按最近五年超额排序**：前十二名全是二买 + RPS50，只有 192 笔，最好一组近五年 +27.21% 而早期十四年 **-7.51%**。且不同止损值给出逐位相同的结果，说明落在了参数不起作用的退化角落。这一列不可信
- **按两窗口较小值排序**：候选集中在一买 + RPS30 + 吊灯 2~2.5，样本 1100~1200 笔

细扫每个参数（`--stability`）后落在：**一买、RPS≥30、止损 4×ATR、吊灯 2×ATR、止盈 3R**

> 止盈随后已改为**不止盈**，见文末「出场砍到只剩一条规则」。本节其余数字是那次改动之前测的。

细扫结果决定了其中每一项，各轴形态很不一样：

- **RPS 门槛**是真平台。20~35 四档两窗口同时为正，30 在早期窗口是局部最高（+8.14%）。0 和 60 两端都转负，说明"只做强势股"这个方向本身有效，不是拟合出来的
- **初始止损**几乎不起作用。3.5 以上早期窗口一直在 +8% 附近、近五年一直在 +5.7% 附近，因为吊灯设在 2×ATR 比它紧得多，实际出场几乎总由吊灯触发（1792 笔里 1779 笔走止损通道）
- **吊灯止损**是最尖的一条轴，也是唯一需要小心的。上一轮选参把网格下界设在 2 而最优正好落在边界，这一轮把轴延伸到 1 重扫，确认 2 是内部最优：1.25 近五年 -0.71%、1.5 +0.03%、1.75 +2.73%、**2 +6.10%**、2.5 +5.67%、3 +0.09%。只有 2 和 2.5 两档站得住，是条窄脊而非平台
- **止盈**在 2.5R 以上是平的，6R 起与不止盈逐位相同。3R 折算成 12×ATR，1792 笔里只触发 13 次。取 3 是按判据落下来的，这一项本身不承载信息
- **转弱离场**（RPS 跌破阈值平仓）仍然不值得开。5~15 档近五年略好（+6.2~+6.5% vs 不开的 +6.10%）但早期窗口同时变差，两窗口方向不一致，是噪声

### 第一阶段标的池初筛（已实现，默认关闭）

对应「全市场标的池流动性初筛」规格。面板加了 `volume` 列（654 只全覆盖、11MB），

**市值 ≥ 20 亿那条没实现**：面板只存价量，没有历史股本，而标普成分极少跌破 20 亿，

训练区的全部增益来自 2007 与 2008 两年（2008 成交 248→11 笔，超额 +4.03%→+21.28%），
即「熊市里躺平」。保留区它从未降低过组合敞口（持仓日仍是 100%），
于是那五年它纯粹作为选股过滤器工作，结果是**亏 1 个点**。

分年度看，加闸门后 7 年改善、13 年变差。我原先的机制假设是「治 V 型反转」，
**这个假设被否掉了**：2009 从 −17.29% 恶化到 −23.28%（成交 98→20），

结论：它的价值集中在尾部事件，而样本里只有 2008 一次。**N=1 的证据无法验证一条防崩盘规则。**
但机制是清楚的（不在下跌趋势里抄底，等价于熊市自动降敞口），
且训练区把回撤从腰斩压到三分之一、同时年化还升了 2 个点，这个量级不能忽略。
默认关闭，因为按「两窗口同号且量级相近」的标准它不合格；
要开的话理由应该是控回撤，不是提收益。

另有一处口径缺陷需要记住：本引擎空仓日收益记 0（不计息），而基准始终满仓，
所以**任何降低敞口的规则都会在下跌年显得好、在上涨年显得差**。
趋势闸门主要就是一个敞口旋钮，用超额指标评价它天然有偏。

### RPS 转弱离场（实测无效，但已实现）

原策略只在入场看 RPS，开仓后完全不看。加了可调阈值的转弱离场（`rsExitBelow` / `rpsExit`）后实测：

紧吊灯（2.5×ATR，平均持仓 20 根）下，两个窗口不同意——早期十四年越用越差（无 +6.03% → 门槛 25 时 +2.93%），最近五年大致持平略好。松吊灯（8×ATR，平均持仓 82 根）下确实有一点用（门槛 30 时早期 −0.02% → +0.66%，持仓缩到 51 根），但量级远不及紧吊灯本身能做到的 +6.03%。

机制解释：RPS 由四个季度的回看加权而成，转向很慢；吊灯止损直接盯价格，反应快。两者做的是同一件事——尽早离场——而价格止损做得更好。**出场上快的打败慢的。**

保留该参数是为了让这个结论可复核，默认关闭。

### 交易层的一个机制耦合

`stopMult` 有两重作用，用 `/lab` 时要知道：

1. 只有 `stopMult < trailMult` 时它才是真正生效的止损。否则退出条件 `close < stop || close < trail` 中吊灯位更高、总是先触发，初始止损永不生效
2. 它同时定义 `1R = stopMult × ATR`，因此决定止盈距离

推论：关掉止盈且 `stopMult >= trailMult` 时，拖动止损滑块结果**逐位不变**（已验证：止损 3/3.5/4/5/6/8 全部给出 +0.92% / +2.62%）。UI 上按当前取值动态提示了这一点。

### 截面 RPS 改用绝对涨幅（已实现）

策略规格「阶段二」要求的是**绝对区间涨跌幅**加权后做全市场截面排名：

```
Score_raw = 0.10×Perf_21D + 0.40×Perf_63D + 0.30×Perf_126D + 0.20×Perf_252D
RPS_i     = PercentileRank(Score_raw_i, Universe) ∈ [1, 99]
```

原实现的周期与权重本就符合规格，唯一偏差是**每段都多除了一次 SPY 同期涨幅**，已改为绝对涨幅。

为什么不该除基准：相对强弱由**截面排名**那一步产生，不需要再除一次。
且除基准并不等价于一次单调变换——同一日里四段除的是四个**不同**的基准增长因子，
等于按 `1/gf_bench(L)` 重新加权四项，排名会因此改变。实测新旧排名的 Spearman
在 0.956~0.990 之间，`RPS>=30` 闸门上 6.1% 的股票日发生翻转：是口径校正，不是策略重构。
默认参数的含义因此不变，没有借机重新调参。

两处口径细节：

- 四段都是**累计**区间涨幅（`Perf_126D` = 收盘价 ÷ 126 根前的收盘价），
  不是各区间的分段涨幅。已加单测钉住这一点——两种理解在「长期横盘 + 末段拉升」
  的形态下会差出二十多个分点
- 实现用涨幅比 `close/base × 100`（走平得 100）而非规格里的 `Perf`。
  因权重和为 1，两者恒差常数 100 且对每只标的相同，截面排名完全一致，已加单测
- 分位映射保留「严格小于 + 半个并列」的中位排名法并夹到 [1, 99]，
  未照搬规格里的 `Floor(超越数量 / 总数 × 100)`：后者会让同分标的拿到不同分数，
  且给最弱的标的算出 0，与规格自己标注的 1~99 范围矛盾

连带影响：SPY 退出这条链路。`prepareUniverse` 与 `percentileRsBySymbol` 不再收基准参数，
`load.ts` 的 `BENCHMARK_TICKER` 与 `rotationRadar.ts` 的 `loadBenchmark` 一并删除。
SPY 现在被自然排除在池外——它不是任何指数的成分，没有 `IndexMembership` 行。
这也让下面那个「基准双下标」的 bug 类别彻底不存在了。

线上数据校验（`UNION` 池，701 只，5027 个交易日）：

- 逐日重算：NVDA 的 RPS 从 2015 年的 59.0 走到 2024 年的 99.0，AAPL 88.5 → 79.3 → 94.9 → 59.6
- 引擎的 `percentileRanksFast` 与参考实现 `percentileRank` 最大偏差 **4e-6**（Float32 存储精度）
- 分位分布均匀：p25 = 25.0 / 中位 49.9 / p75 74.7；越界 0 个；非成分被排名 0 只
- 历史合理性：2020-03-23 最弱是 APA/FANG/HAL/OXY/NCLH（能源 + 邮轮），
  2024-01-02 最强是 NVDA/CRWD/PDD/UBER、最弱是 PFE/PARA——对得上真实历史

上面这组数字（含 Spearman 与闸门翻转率）是在 **63/126/189/252、.4/.2/.2/.2** 的
IBD 官方口径下测的：那一版一度替换了规格口径，后按规格退回 21/63/126/252、.1/.4/.3/.2。
两版都是绝对涨幅，所以「除基准 vs 不除」这一结论不受影响；但逐日分位的**具体取值**
属于 IBD 那一版，未在规格口径下重测——当时 Neon 的数据传输配额已用满。

因此把原先靠一次性脚本验的那几条性质固化成了不依赖数据库的单测
（`tests/backtestEngine.test.ts` 的「截面 RPS 的逐日重算」）：

- 同一只标的在不同日期拿到不同分位，且强弱反转会被跟上
  （构造先弱后强与先强后弱两只，验证 21/63 日的大权重确实把反转打出来）
- 某一日的分位逐位等于按当日四周期加权分独立排名的结果
- 预热不足 252 根不评分；非成分日不评分，即便回看已齐
- 有数据但从不是成分的标的不参与排名，且不改变其他标的的分位

### 曾经的基准双下标 bug（已随上一节消失）

`percentileRs.percentileRsBySymbol` 算出了基准下标 `bi` 却把标的自己的下标传给 `alphaScoreAt` 去索引基准序列，晚上市 200 天的标的会读到 200 天前的基准价，涨跌结论可能整个反转。该路径在 `COMMERCIAL_SPEC.percentileRs` 开关后面且默认关闭，线上从未触发。

先用 `benchIndex` 参数修好，之后改成绝对涨幅口径，基准整个退出了计算，这类错位不再可能发生。

### RPS 回看落空的处理（已修）

原实现里，回看窗口不够长时那一段按 `perf = 1`（走平）计入。这等于断言
「这只股票在它上市之前走平」：牛市里基准同期涨 15%，那一段就变成跑输 15% 计入，
新上市或新分拆的标的（ABBV、ALLE 之类，标普池内 156 只起始日晚于日期轴起点）
在入池头一年会被系统性压低分位，熊市则反向抬高。

改为四段回看任一落空即不评分（`alphaScore` 返回 NaN，该标的当日不进截面）。
两处实现口径已统一：`backtest/engine.ts` 与 `scoring/percentileRs.ts`。

没有采用「按剩余权重归一化」这个更宽松的方案：那样一只刚上市 22 天的标的会拿
21 日动量冒充四周期复合分，而新上市标的初期常有暴涨，会被系统性推高——
只是把偏差换了个方向。四周期复合分就该等四段都齐了再算。

配套的两个细节：

- 入场闸门加了 `rps >= 1`（分位下界被夹到 1，故此即「已排名」）。
  只写 `rps >= rpsMin` 的话，`rpsMin = 0` 会把未排名的也放进来
- `rpsExit` 的取值把未排名日填 100 而非 0，否则转弱离场会在预热期无条件触发

### 交易日缺口（已定性，不修）

CVG 在 20 年窗口里缺 102 个交易日，但那是 **100 个互不相邻的单日缺口**，
成交稀疏当天没有成交、Yahoo 返回 null 被抓取层过滤掉了，不是数据错误。
影响是回看窗口被拉长约 2%（252 根 ≈ 257 个交易日），653 只里 4 只有此现象。

不做前向填充：凭空造出的走平 K 线会直接污染 ATR 与 MACD，代价大于收益。
改为在回填脚本里报告缺口异常的标的，让它从静默变成可见。

## 标的池换成纳斯达克 100（已实现，实测不适用）

时点成分数据来自 unliftedq/index-constitution，313 段区间 / 276 个 ticker，
2007–2026 每年都有真实变动记录（年均约 10 次，符合 NDX 实际换手率）。
已验证是真时点数据而非当前成分快照——NFLX 记录为 2010-12 入指、2012-12 被剔除、
2013-06 重新纳入，幸存者偏差的数据集不可能记录到那次剔除与回归。
可用标的 219/313 段有价格（70%），高于标普池的 55%（NDX 换手慢、成分更可能仍在交易）。

用标普池上调出来的那组默认参数实测：

|                      | 标普 500   | 纳斯达克 100 |
| -------------------- | ---------- | ------------ |
| 池内标的             | 653 只     | 193 只       |
| 采纳信号             | 2812 个    | 604 个       |
| 训练区超额           | **+6.10%** | **−13.21%**  |
| 保留区超额           | **+5.47%** | **−15.43%**  |
| 训练区持仓日         | 97%        | 68%          |
| 同池基准年化（训练） | +10.61%    | +14.73%      |

20 组参数扫描（RPS 0/50/70/80/90 × 止盈 无/1R/2R/3R）里**没有一组**两窗口同时为正。
看起来最好的几格（RPS 80，保留区 +8.92%~+13.18%）只有 22 笔成交，训练区全在 −7% 附近，
是小样本凑出来的数字。

两个结构性原因，都不是 bug：

1. **仓位填不满**。193 只标的、截面上同时只有 70~100 只，训练区持仓日只有 68%
   （标普 97%）。空仓日收益记 0，于是错过基准的复利，持仓时又照样吃满回撤
2. **基准本身就是动量篮子**。等权 NDX 训练区年化 +14.73%，比等权标普高 4 个点。
   NDX 是 100 只预先筛选出来的强势科技股，用动量策略去打一个已经满载动量的基准，
   等于跟自己的选股逻辑对赌——策略的超额本来就来自「在分散的池子里挑强势股」，
   池子本身即强势时这层价值就没了

因此默认池仍为标普 500，纳斯达克在 `/lab` 里可切换。注意基准恒为**同一池子**的
等权收益，所以两个池子的「超额」不能直接比大小。

## 买点回到通达信原式（已实现，卖点未做）

轮动 Pine 本身是从一份通达信公式移植来的。拿到原式逐条比对后，发现 Pine 在移植时
引入了两处失真，都在买入侧。已按原式修正，`logMacd.ts` 的对齐基准从此是**通达信原式**
而不是 Pine。

映射关系：原式的 `COND_BUY`（图上 'BUY'）对应本项目的**一买**，
`COND_BUY1`（图上 'B'）对应**二买**。

### 修正一：`INTPART` 不是 `math.floor`

原式量级规约用的是 `INTPART`（向零截断），Pine 写成了 `math.floor`（向下取整）。
通达信另有 `FLOOR` 可选，作者选的是前者，这不是笔误。两者在负数上差 1
（`INTPART(-37.5) = -37`，`floor(-37.5) = -38`），而底背离要求 `MACD < 0`、
DIF 通常也在零轴下方，所以这个差别几乎每次判断都会碰上。

**实测在当前池子上近乎无感**：信号数 2998 不变，成交 1792/1201 笔不变，
训练区超额 +8.14% → +8.13%。原因是比较式两侧都是负数、同向各偏 1，
绝大多数情况下比较结果被保留。真正会出事的是 `|LV_D2| < 1` 时——
`INTPART(LOG(0.5)) = 0` 而 `floor(-0.301) = -1`，规约位数整体差一个数量级——
但 DIF 是 `100 × (EMA12 − EMA26)`，百元股的量级在几十，700 只大盘股里碰不到。
换低价股池会显出来。

### 修正二：二买少了顶背离否决项

原式的 `COND_PSVN_DIS` 是四项合取，Pine 只实现了前三项，漏掉 `TOP_DAYS > DC_D1`，
即**死叉之后不许出现过顶背离**。Pine 里根本没定义 `TOP_D`，所以这条无从实现。

现已补上 `TOP_D`（`divergenceTop`）：`TP_DEA_D` 那根上实体上沿创 4 日新高而 DIF 未创新高。
`TOP_D` 本身不是卖点，只作二买的否决项。

从未出现过顶背离时 `barsSince` 为 null，比较取 false 即**否决**而非放行。这与本模块
其余 na 语义一致，实践中只影响序列开头的预热段（5000 根里顶背离出现上百次）。

实测（RPS≥30、止损 4、吊灯 2、止盈 3R、仅二买）：

|                   | 补否决前         | 补否决后             |
| ----------------- | ---------------- | -------------------- |
| 采纳信号          | 1408             | 1250                 |
| 训练区成交 / 超额 | 851 笔 / −10.62% | 725 笔 / **−10.34%** |
| 保留区成交 / 超额 | 557 笔 / −0.83%  | 525 笔 / **−2.65%**  |
| 保留区盈亏比      | 2.01             | 2.05                 |

砍掉约 11% 的信号，两窗口一升一降，方向不一致，属噪声级变化。**结论是这条否决项
不改变二买没用这个事实**——二买单独跑在两个窗口都是负超额，所以默认仍是
`useBuy2: false`。补它的理由是对齐规格，不是为了提升表现。

### 未做：整个卖出侧

原式有一套完整的 'S' 信号——`TOP_D_DIRECT` / `TOP_D_INDIRECT`（底背离的镜像，走 `HHV` 与金叉）、
`COND_BTM_SELL`、以及趋势破位的 `COND_TOP_SELL`（收盘跌破 `EMA(L,25) × 0.99` 且此前长期站稳）。
本项目用 ATR 吊灯止损 + 初始止损 + R 倍数止盈替代，原式里没有这套东西。

这是全部偏离里最大的一处，而且第六节调的那些参数调的正是这套**原式中不存在**的出场机制。
形态出场与波动率出场哪个更好没有实测过，是个待办。

### 也未做：`FILTER` 的去重语义

原式 `FILTER(X,10)` 按**已发出的信号**计抑制窗口，Pine 的 `ta.barssince(cond[1]) > 10`
按**原始条件成立**计。举例，原始条件在第 0/5/11 根成立：原式发出第 0 与第 11 根，
Pine 一个都不发（第 0 根 `barssince` 为 na；第 11 根距上次成立只有 6 根）。

Pine 版本明显更严，第一个信号永远不发，密集出现的原始条件会互相永久压制，
因此本项目的信号数少于原策略。此处按用户决定不改。

### 面板加了 `open` 列

`TP_P := MAX(C, O)` 要开盘价，而回测面板原本只存高/低/收。已加 `open` 列
（缓存 59.8MB → 71.8MB，`panelCache` 版本号 1 → 2），Prisma 侧为可空，
与 `volume` 同一套先例。为空时实体上沿退化为收盘价，只影响二买的否决项。

## 成交时点改为次日开盘（已实现）

来源是一份出场规格的截图，其第 4 条写「盘中收盘价跌破当前动态止损/止盈线时触发平仓事件，
**次日开盘无条件市价清仓**」。这条指出了此前实现的一个真问题。

### 为什么原来的填价拿不到

点火条件（底背离）与出场条件（`close < max(sl, trail)`）全部取自收盘价，而收盘价要等收盘
之后才存在。Pine 以及本项目此前的实现都按信号当根的收盘价成交，等于在知道收盘价的同时
还能按它成交。挂 MOC 单也做不到——MOC 必须在不知道收盘价时提交，无法以「收盘破线」为条件。

两腿同向偏乐观，而**开仓那腿更重**：底背离的信号根通常是局部低点，这个策略的全部优势就在买得低。

### 改法

`rotationTrade` 改成挂单模型：收盘产生 `pendingEntry` / `pendingExit`，次日开盘按
`bar.open ?? bar.close` 成交。ATR 一并留存（`pendingEntryAtr`），因为开盘时只知道到前一根的
ATR，止损与吊灯初值按真实成交价而非信号根收盘价计。`TradeDay.entered` / `exited` 的语义
随之从「触发日」变为「成交日」。

组合层的日收益口径必须同步改，否则会算错：建仓日只吃 `open→close`，清仓日只吃
`prevClose→open`，中间才是收盘到收盘。基准不涉及成交时点，仍按收盘到收盘计。

> 清仓日那一段当时漏了：它算出来了却进不了持仓表，因为那一根 `sigType` 已归 0。
> 见「清仓根那一跳曾被丢掉」。

### 单笔风险约束（已实现，实测有害，默认关闭）

规格第 1 条：「按止损点位距离计算头寸，单笔最大允许风险 ≤ 基金总净值的 0.8%」。
已实现为 `riskBudgetPct`：仓位 = 该值 ÷ 止损距离占开仓价的百分比，权重之和封顶 1（不加杠杆），
不足的部分记现金、收益为 0。`null` 表示退回每日等权。等权走的是同一条加权路径
（各持仓权重记 1，缩回后正好是除以只数），已验证能精确复现改动前的数字。

| `riskBudgetPct` | 训练敞口 | 训练年化 | 训练超额 | 训练回撤 | 保留敞口 | 保留年化 | 保留超额 | 保留回撤 |
| --------------- | -------- | -------- | -------- | -------- | -------- | -------- | -------- | -------- |
| null（等权）    | 95%      | +16.48%  | +5.69%   | -40.1%   | 99%      | +11.34%  | +3.51%   | -25.2%   |
| 0.8（规格值）   | 53%      | +6.66%   | -4.13%   | -23.8%   | 75%      | +8.68%   | +0.86%   | -14.4%   |
| 5.0（敞口对齐） | 90%      | +11.45%  | +0.66%   | -45.9%   | 99%      | +11.40%  | +3.58%   | -21.2%   |

0.8% 是**基金级**风险政策，隐含假设并发持仓多到能铺满资金。本策略并发持仓不够
（止损距离约 10~16%，单笔权重 5~8%，要 12~20 个并发才满仓，训练区实际只有七八个），
于是一半时间在现金里而基准恒满仓。那一行看似风险调整后漂亮，但同样效果把一半钱存银行、
剩下一半跑等权也能得到，而且现实中现金还有利息（本引擎记 0）。**那不是定仓规则的功劳，
是降杠杆的功劳。** 要归因就得把敞口对齐。

对齐后（budget 5.0，敞口 90%/99%）结论是负的：训练区收益更低、回撤还更大，严格被支配；
保留区收益打平，只换到回撤从 -25.2% 到 -21.2%。

机制是清楚的。按止损距离（即波动率）把单笔五等分：

|         | 止损距离 | 风险平价相对权重 | 单笔均值 | 最好一笔 | 收益 >30% 占比 |
| ------- | -------- | ---------------- | -------- | -------- | -------------- |
| 训练 Q1 | 5.9%     | 0.169            | +1.06%   | +22%     | 0.0%           |
| 训练 Q5 | 26.5%    | 0.038            | +2.46%   | +45%     | 3.1%           |
| 保留 Q1 | 6.9%     | 0.146            | +1.08%   | +25%     | 0.0%           |
| 保留 Q5 | 17.5%    | 0.057            | +4.15%   | +63%     | 6.7%           |

单笔均值随止损距离单调上升，收益超过 30% 的交易全部落在后两组，最好那笔 +63% 在 Q5。
风险平价按定义给 Q5 最小权重（训练区比 Q1 低 4.4 倍），即系统性压低唯一产生大赢家的那一桶。

一个反直觉的细节，否则这个结论看着过于顺理成章：换成 R 倍数排序是反过来的
（训练 Q1 约 0.18R、Q5 约 0.09R），每单位风险的效率是紧止损的票更高。所以风险平价不是「错」，
它买到的是单笔风险效率、卖掉的是右尾；对一个靠右尾赚钱的策略这笔交易不划算。

副作用是 `stopMult` 第一次有了真实作用：启用风险预算后它决定每笔下多少钱，
而不再只经由 `takeProfitR × stopMult` 影响止盈距离。但既然默认关闭，第 307 行那个耦合仍然在。

### 新执行模型下的重搜（结论：不换默认值）

同一张 1260 组网格在次日开盘成交下重跑一遍。整体水平明显下移：近五年超额中位
+0.84%、p75 +2.61%、p90 +4.45%，两窗口同时为正的组从旧模型的比例掉到 28%。

按两窗口较小值排序的榜首是 `RPS40 止损3 吊灯4 止盈2R 二买`（早期 +5.67% / 近五年 +12.89%，
323 笔）。这一组不可用：RPS 轴上它是尖峰而非平台，相邻档 30 / 35 / 50 分别是 -0.32% /
-0.36% / -0.91%（早期），把 RPS 挪到 20 则只剩 +0.81% / +1.50%。优势在门槛取值上，不在二买信号上。

一买分支的整个面又平又低，各轴基本在 ±2% 内。分支内最好的一组是
`RPS30 止损4 吊灯2.5 止盈2R 一买`（早期 +4.25% / 近五年 +5.53%，1199 笔），邻域比二买那组
干净得多。它与现行默认值只差两档：吊灯 2 → 2.5、止盈 3R → 2R，代价是早期从 +5.69% 降到 +4.25%。
这个量级落在 1260 组搜索的 p75~p90 之间，与噪声不可区分，且保留区已是第三轮被用于择优，
故不换——换了只是把第四轮拟合叠上去。

一个容易过度推广的读数：二买分支的稳定性扫描显示吊灯轴单调偏好放宽（1 → -1.29%，
6 → +17.10%，近五年），但这不是普遍结论。一买分支上该轴的峰在 2~2.5，放宽到 4 掉到 +0.96%。
两个分支的最优吊灯宽度不同。

`stopMult` 仍然结构性失效：在 `止盈无 + 吊灯4` 的扫描里，初始止损从 4 到 8 的四档超额
完全相同（+0.68% / +1.61%），因为止损一旦松过吊灯位就永不触发。它在止盈开启时之所以看起来
有影响，是经由 `takeProfitR × stopMult × ATR` 这个耦合传导的，不是止损本身在起作用。

## 出场砍到只剩一条规则（已实现）

出场侧一直挂着五样东西，实测只有一样在干活。1792 笔的离场归因是止损 1779 / 止盈 13，
即吊灯移动止损做了 99.3% 的工作，其余是装饰：

- 初始止损 `stopMult=4` 比吊灯 `2` 宽，**永不触发**，只经由 1R 的定义影响止盈距离
- R 倍数止盈 `3R` 折算成 12×ATR，1792 笔里只碰到 13 次
- 阶梯收紧的四个常数，换成规格值也没差别（见上文）
- RPS 转弱离场、风险定仓，已经默认关闭

于是把止盈关掉，`takeProfitR` 默认值 3 → null。三组对照：

|                                      | 训练年化 | 训练超额 | 保留年化 | 保留超额 | 保留回撤 |
| ------------------------------------ | -------- | -------- | -------- | -------- | -------- |
| 止损4 吊灯2 止盈3R（旧默认）         | +16.48%  | +5.69%   | +11.34%  | +3.51%   | -25.2%   |
| **吊灯2 + 保本锁，无止盈（现默认）** | +16.20%  | +5.41%   | +11.19%  | +3.37%   | -25.2%   |

不是因为它在起作用；`/lab` 的滑块提示里已写明此时拖动它不会有任何变化。

## 清仓根那一跳曾被丢掉（已修）

`rotationTrade` 把清仓根的 `riskPct` / `entryRps` / `entryDate` 在清空状态前留了一份，
注释写着「组合层还要用它给这半天定权重」。但组合层的入账判据是
`sigType !== 0 && entryPrice != null`，而清仓根这两个字段正是被清空的那两个——
后门留了，没接上。于是 `ret = open / prev - 1` 每根都算出来，然后丢掉。

漏掉的是每笔交易的最后一段：信号根收盘跌破吊灯，次日开盘成交，这一跳不进净值。
`ClosedTrade.pnlPct` 一直是含它的，所以逐笔统计对、组合净值不对，两者长期不一致。

方向与直觉相反：这一跳的均值是**正的**，止损总是卖在隔夜反弹之前。

| 池 / 周期                  | 跳空均值 | 为负占比 | 修复前年化 | 修复后    |
| -------------------------- | -------- | -------- | ---------- | --------- |
| Small Fund 日线（cap 15%） | +0.18%   | 39%      | 24.4%      | **25.5%** |
| Small Fund 4H（cap 15%）   | +0.13%   | 42%      | 32.8%      | **33.7%** |
| 标普保留区（默认配置）     | —        | —        | +11.19%    | +11.22%   |

标普池上只值 0.03 个点，因为并发持仓多、单票权重 2~3%，那一跳被摊薄；Small Fund 是
195 只小池加 15% 单票上限、平均持仓九只出头，同一个 bug 值一个百分点。

清仓根现在单列进 `exitHolds`，参与当根的权重分母与收益，但不进持仓表——那一根收盘它
已经不在手上，混进去会让当日持仓列出已卖掉的票。它占的那一份钱在开盘后变成现金，
当根剩余时间不计息，与「空仓收益记 0」的既有口径一致。

测试钉的是一个单票满仓场景：建仓 @100、收盘跌破吊灯、次日开盘 90 平仓，组合净值必须
正好等于 0.9。漏掉那一跳会停在 0.95。

## 两条基准的口径差

`benchmark` 这个名字下面一直是「每根把全池拉回等权」，而多处注释和本文件早先都写成
「等权买入持有」。两者不是一回事，差值不小，且**符号取决于池子**：

| 池 / 窗口                 | 每根等权 | 买入持有 | 差    |
| ------------------------- | -------- | -------- | ----- |
| Small Fund 日线 2021-2026 | 31.5%    | 28.1%    | +3.5  |
| Small Fund 4H 2021-2026   | 34.3%    | 29.1%    | +5.2  |
| 标普保留区 2021-2026      | 7.74%    | 8.96%    | -1.22 |

Small Fund 上再平衡赢，那 195 只票齐涨互跌、波动收割吃得到；标普池上再平衡输，池里
有一批长期趴着的票，每根拉回等权等于持续给它们加钱。

于是 `WindowResult` 加了 `buyHold`，两条并排出。默认那个大字超额仍对每根等权（本文件
的历史结论都建在它上面），但买入持有才是实盘照做得到的那条——「每根调全池近两百只票」
这个操作的交易成本和冲击，两条基准都没算。

这一改动翻转了 Small Fund 4H 档的结论：对每根等权是 -0.6，对买入持有是 +4.6。

## 资金账本与每日清单（已实现）

回测的仓位是「权重法」：每根把持仓拉回等权、开新仓时按比例摊薄旧仓，敞口永远贴满
100%。它对参数搜索够用，但**照它下不了单**——真实账户没有「按比例摊薄」这个操作，
钱花完就是花完了。

所以实盘侧单独做了一套现金账本，`src/lib/fund/`：

- `bookLogic.ts` 记真实成交。现金由「注资 − 买入 + 卖出」推出来，刻意不存 cash 字段：
  两处记账迟早对不上，而对不上的账本比没有账本更坏。取不到报价的持仓按成本计价，
  宁可让权益显得不动，也不用一个猜的价去标记它——那会直接歪掉下一笔的开仓金额。
- `plan.ts` 出清单。每笔投当时权益的 12.5%（满仓约八只），现金不够就不开；满仓时拿新
  信号的 RPS 跟最弱持仓比，高出 20 分才置换。
- `track.ts` 从**实际成交价**逐根推出每只的吊灯位。这是它和 `/desk` 的根本区别：
  后者推演的是「从头严格照做会持有什么」，前者是「你手上实际有什么」。

### 三个参数都是实测定的

全部在现金账本口径下、成本 10bps、两段各自评分再取差的那段。

| 每笔 \ 门槛 | 不置换 | +0 | +15 | +20 | +25 | +30 |
| ----------- | ------ | -- | --- | --- | --- | --- |
| 6%          | 9.3    | 12.8 | 13.3 | 12.2 | 11.4 | 12.1 |
| 10%         | 12.0   | 19.8 | 18.1 | 19.2 | 17.1 | 17.2 |
| **12.5%**   | 11.3   | 22.5 | 22.0 | **23.8** | 20.7 | 18.9 |
| 15%         | 7.5    | 25.4 | 20.8 | 21.3 | 20.9 | 18.7 |

（表内为取差那段的 CAGR%）

- **每笔 12.5%**：上限八只，但信号密度撑不满，实际均持仓 5.3 只、敞口七成。6~8% 把钱
  摊太薄只剩 13~15%；20% 以上均持仓掉到 3.4 只，回撤冲到 37% 而收益腰斩。

即便按 30bps 算，MAR 0.86 仍等于权重法在**零成本**下的表现。

### 一处曾经算错的置换资金

早先的模拟脚本里有一行 `free += slotAmount - slotAmount`，注释写的是「腾出的现金可乐观
计入」，实际恒等于零。后果是同一根里第二个信号也被迫走置换路径，而不是用刚腾出的钱
直接建仓，置换次数被系统性高估。

修正后（受害者市值扣掉成本后计入当根可用）最优点没动，仍是 12.5% + 20，但「挑最弱」
的结论被翻过来了：修正前它对随机组 1 胜 2 负 1 平，看着像装饰；修正后是全胜。

### 吊灯口径只有一份

吊灯是路径依赖的——只上移、浮盈过档收紧、保本锁——所以拿今天的价格反推不出今天的
止损位，必须从开仓那根逐根推过来。实盘账本和回测状态机因此共用
`rotationTrade.ts` 里的 `openPositionRisk` / `advancePositionRisk` / `riskAtrSeries`：
口径要是分成两份，实盘会在另一个价位离场，回测数字全部作废，而且这种不一致是静默的。

对账方式是拿回测里的吊灯出场交易反推：账本推出的触发日必须和回测判出场的那根严格
对上。最近 200 笔全部一致，无提前触发也无遗漏。

### 账本存在文件里，线上记不了账

`data/desk/fund-book.json`，进 git——账本是这套东西里最不能丢的资产，跟着仓库走顺带
就有了版本历史。但 Vercel 文件系统只读，所以**线上环境不能记账**，那边只跑无状态的
信号转发。要把记账搬上去得先换数据库，`FUND_BOOK_PATH` 留了口子但解决不了持久化。

## 全矩阵对比：策略的超额来自哪里

现金账本口径（12.5% + 置换门槛 20，成本 10bps）与各条基准并列，同一个池、同一段窗口：

| 口径                | 前半 2021-08→2024-02 | 后半 2024-02→2026-08 | 全段          |
| ------------------- | -------------------- | -------------------- | ------------- |
| 现金账本 12.5%+20   | 23.8% / 回撤 21%     | 24.3% / 回撤 24%     | 24.1% / 24%   |
| 权重法（引擎默认）  | 20.2% / 回撤 23%     | 28.3% / 回撤 22%     | 24.5% / 23%   |
| 池内每根等权        | 14.7% / 回撤 27%     | **51.0%** / 回撤 24% | 31.5% / 27%   |
| 池内买入持有        | 14.4% / 回撤 26%     | **57.9%** / 回撤 31% | 28.1% / 28%   |
| SPY 买入持有        | 5.2% / 回撤 25%      | 18.2% / 回撤 19%     | 11.4% / 25%   |
| QQQ 买入持有        | 6.4% / 回撤 36%      | 21.9% / 回撤 23%     | 13.8% / 36%   |

三件事值得盯着看。

**池内基准 28.1% 对 SPY 11.4%，这个 2.5 倍的差距就是生存偏差的量级。** 池子是 2026 年
挑的 195 只票，「过去五年年化 28%」这个数字只有在 2026 年回头看才存在。策略跑在这个池
子上，赢 SPY 的部分里有多少是选股池的后见之明、多少是买卖时机，这张表分得清：**池内
买入持有就是「选对池子」的全部贡献，策略在它之上是负的。**

**后半段策略被基准甩开三十多个点**（24.3% 对 57.9%）。这不是 bug，是趋势跟踪的定义
特征：它会止损离场、会有现金闲置（敞口只有七成），单边牛市里必然跑输满仓不动。前半段
反过来——含 2022 那轮熊市，策略 23.8% 对基准 14.4%，超额 +9.4。

**所以这套东西的价值在回撤和一致性，不在收益上限。** 两段 23.8% / 24.3% 几乎持平，
而基准是 14.4% / 57.9% 的剧烈摆动；全段回撤 24% 对基准 28%。换句话说它把一个「熊市
亏、牛市暴涨」的池子磨成了一条比较平的线，代价是牛市里少赚很多。

拿它规划实盘时，年化预期该按 15% 打底而不是 24%：五年样本、生存偏差、且后半段的
基准涨幅本身不可持续。

### 执行口径是主变量，不是妥协

四种执行方式（门槛10/止损5/吊灯6，每笔 8%，格式 CAGR/回撤/全期MAR/三段最差）：

| 执行方式 | 结果 |
| -------- | ---- |
| 信号即下单 / 即止损 | 22.8 / 23 / 1.00 / 0.48 |
| 信号即下单 / 收盘止损 | 26.0 / 25 / 1.04 / 0.34 |
| **收盘下单 / 即止损** | **27.8 / 18 / 1.55 / 0.84** |
| 收盘下单 / 收盘止损 | 28.4 / 19 / 1.49 / 0.80 |

两个方向相反的结论：

- **入场限制在美东收盘那根反而更好**（MAR 1.55 对 1.00），不是为了不熬夜而付的代价。
  美股 6.5 小时被切成 9:30–13:30 的整根和 13:30–16:00 的 2.5 小时残根，盘中那批信号
  成交后只剩 2.5 小时就收盘，残根让 ATR 和吊灯失真。上一节那张「噪声主导」的网格就是
  这么来的。
- **出场慢半天是纯损失**：10% 档最大回撤从 23% 掉到 16%，三段最差 MAR 从 1.07 升到 1.16。
  出场因此需要自动化——美东 13:30 那个检查点是北京时间凌晨 1:30，靠 TV 在每根 4H 收盘
  推信号、程序下单。不做自动化就退回「收盘下单 / 收盘止损 + 每笔 8%」，MAR 几乎不变
  （1.49 对 1.55），代价是回撤多 3 个点、最坏子区间明显更弱。

### 各参数的落点理由

**门槛 10。** 收盘入场 + 即时出场下的门槛轴（止损5/吊灯6）：8% 档 0→27.1/1.48、
10→27.8/**1.55**、20→21.0/1.26、30→17.5/1.17；10% 档 0→23.6/1.11、10→25.2/**1.53**、
20→21.3/1.00、30→16.7/0.91。门槛 0 反而不如 10，说明「剔除最弱一小撮」有价值，但再往
上卡就开始亏——4H 的收益有相当部分来自深度回撤后的反弹，那些票当时 RPS 恰好不高。
日线是 40、4H 是 10，两边差这么远不是矛盾。

**止损 5。** 这个参数在 5~8 之间几乎是钝的（吊灯 6 上分别是 1.15/1.10/1.10/1.10）：
6×ATR 太宽，基本总是吊灯先触发。3 明显更差。取 5 是略优的那一档。

**吊灯 6。** 在所有门槛、所有仓位下都是那一列的峰（4/5 和 7/8 都塌），是整套参数里最
稳的一个。

**每笔 10% 对 8%。** 8% 全期 MAR 略高（1.55 对 1.53）、年化高 2.6 个点；10% 最大回撤
低 2 个点（16% 对 18%）、三段最差 MAR 明显更稳（1.16 对 0.84）。取 10%。

**成本敏感性**（全收盘口径）：0/10/20/30/50 bps 下 MAR 1.58 / 1.49 / 1.40 / 1.32 / 1.15，
50bps 仍有 23.2% 年化。开仓 308 笔 / 5 年，单笔胜率 47%，持仓中位 10 只、峰值 12，
前 5 笔占毛利 15%（不靠少数几笔撑）。

### 搜参过程的教训：顺序搜索被咬了三次

同一个错误犯了三次——固定住 A 去搜 B，而固定的那个 A 值本身是错的：

1. 把仓位固定在 12.5% 去扫门槛，得出「4H 在现金账本下不可用」。
2. 把门槛固定在 40 去扫仓位，推荐了每笔 10%（当时的门槛已经不是 40）。
3. 把执行口径固定成「全收盘」、仓位固定 8% 去扫门槛和吊灯，选出门槛 20。而门槛 20 是
   在更早的「每根下单 + 10%」下选的，从没在最终口径下复核。

第三次是被「这套就是最佳吗」这个问题问出来的。补完之后门槛从 20 落到 10，年化差 8 个
点。**教训是：任何「固定某维」的搜索，在其它维定稿后都必须回头复核一遍**，尤其是那些
被当成「外生约束」而非「可调参数」的维度——执行口径就是这么被漏掉的。

### 局限

- 数据只有五年，4H 面板从 2021-08 起，样本比日线短。
- 六个维度（门槛、止损、吊灯、仓位、置换、执行窗口）都在同一份数据上搜过，最优点必然
  掺了运气，实盘预期应当打折。门槛 10 相对 20 的 8 个点改进在全期、三段和五个成本档上
  方向一致，可信度较高；但 0.05 量级的差别（如 8% 与 10% 的三段）基本是噪声。
- 超额集中在 2022（+22% 对指数 -20%/-34%）和 2025（+58% 对 +20%/+17%）两段，2023 明显
  跑输纳指。
- 池子有生存偏差（195 只是 2026 年挑的），见「全矩阵对比」一节。
- 2H 不是冻结档。曾有一份继承 4H 参数的默认配置，已删。横评数字只从 `scripts/fund-rotate.ts` 复现。

## 多周期组合：六个方向全部无效（未改默认值）

结论先放前面:**4H 这套已经是多周期嵌套的**——4H 的 Vegas 通道一天两根,EMA576/676 实际覆盖 288 / 338 天,本身就是长周期趋势过滤器;RPS 取的是标普池的日线口径(21/63/126/252 四段加权);入场信号来自 4H 的 log-MACD 背离;决策节奏是每天一次(只在美东收盘那根定策)。再叠一层日线指标,加进去的是冗余不是信息。

下面五个方向都在「门槛10/止损5/吊灯6、每笔10%、收盘入场+即时出场、成本 10bps」上跑,全期 2021-08→2026-08。

### 三、日线状态调节仓位（被安慰剂否掉）

先看指标本身：池内「日线 Vegas 多头」广度的分布是 **最低 49% / 10 分位 57% / 中位 78% / 最高 84%**，2022 最深处也只到 49%。**这个池子上广度没有区分度**——195 只票是 2026 年挑的，过去五年永远有一半以上处于长期多头，这是生存偏差的又一个后果。所以「广度低于 30%/40% 就停手」的规则从未触发，结果与基线逐位相同（同样 257 笔、同样 1.53），那不是「无效」，是「没跑过」。

唯一亮眼的是线性档（`slotPct = 4% + 10% × 广度`）的 MAR 1.70 对基线 1.53。安慰剂对照：

| 规则 | CAGR | 回撤 | MAR | 三段最差 |
| ---- | ---- | ---- | --- | -------- |
| 基线 固定 10% | 25.2% | 16% | 1.53 | **1.16** |
| 对照 固定 9.8%（同均值） | 26.9% | 17% | 1.61 | 1.09 |
| 真广度 线性档 | 26.1% | 15% | **1.70** | 1.11 |
| 安慰剂A 广度打乱时序 | 27.8% | 19% | 1.44 | 0.88 |
| 安慰剂B 纯随机仓位 ×6 种子 | — | — | 1.32 / 1.48 / 1.48 / 1.54 / **1.88** / 1.66 | 中位 0.91 |

真广度的 1.70 在随机分布里排第 5，有一个随机种子跑出 1.88 比它更高；相对同均值固定档（1.61）只高 0.09，而随机档跨度 1.32~1.88 足有 0.56。**广度信息价值为零**，那点改善是「仓位会浮动」本身制造的噪声。所有浮动方案的三段最差都劣于基线的 1.16（中位 0.91）——固定仓位反而最稳。

| 日线入场 + 4H 风控（最优） | 24.4% | 18% | 1.33 | **0.37** | 151 |
| 同上 每笔 13% | 18.8% | 23% | 0.82 | 0.29 | 127 |
| 同上 每笔 20% | 6.7% | 24% | 0.28 | 0.25 | 76 |

整张止损×吊灯网格里三段最差没有一格超过 0.45。那个 MAR 1.33 也不可信：吊灯 10 一列（1.33/1.33/1.32）两侧全塌（吊灯 8 是 0.97，吊灯 12 是 1.01），孤立尖峰。

**失败的机制恰好推翻了「快出」的前提。** 日线冻结档五年只有 373 个买点日（摊到 195 只票是每票每年 0.38 次），信号本就稀，再用 4H 的紧尺度频繁踢出局就补不回来，开仓从 257 掉到 151。最说明问题的是网格方向：**吊灯越松越好**（10 全线优于 4~8），即在日线信号密度下正确做法是让持仓活得更久。这个组合把两个周期的缺点凑齐了——入场机会少是日线的缺点，止损频繁是 4H 风控的代价。

反观现档为什么成立：4H 入场提供了足够密的信号，紧风控踢出去之后马上有新的填进来。**风控节奏必须和信号密度匹配**，这是这一轮真正的收获。

### 五、放弃率 82% 不是缺陷，加坑位解决不了

池子 195 只、坑位 10 个，19.5 : 1，用 5% 的资金容量接 100% 的信号流，放弃大部分是算术必然。把单笔调小以增加坑位：

| 每笔 | 理论坑位 | 持仓中位 | 敞口 | 放弃率 | CAGR | MAR | 三段最差 |
| ---- | -------- | -------- | ---- | ------ | ---- | --- | -------- |
| 2%   | 50 | **11** | 24% | 66% | 8.8% | 1.15 | 0.44 |
| 5%   | 20 | **11** | 54% | 69% | 20.8% | 1.36 | 0.57 |
| 6%   | 16 | 10 | 59% | 72% | 25.0% | **1.58** | 0.69 |
| 8%   | 12 | 9 | 65% | 77% | 27.8% | 1.55 | 0.84 |
| 10%（现值） | 10 | 8 | 67% | 82% | 25.2% | 1.53 | **1.16** |
| 15%  | 6 | 5 | 69% | 87% | 22.9% | 1.16 | 0.82 |

坑位从 10 加到 50（五倍），放弃率只从 82% 降到 66%，**持仓中位只从 8 只变成 11 只**——五十个坑实际装满十一个。限制因素不是坑位数，是信号在时间上的聚集：买点扎堆出现在同几根 K 上，被放弃的绝大多数是「和已执行信号挤在同一根」的，不是独立机会。

所以**放弃率和敞口是一对矛盾**：66% 放弃率对应 24% 敞口，82% 对应 67%。高放弃率其实是信号供给充足的表现（坑位一空立刻有新的填上）；真该担心的是放弃率低，那说明坑位长期空着。

### 六、市场状态调节吊灯宽度（被安慰剂否掉，且方向为负）

第三节的广度指标在这个池子上没有区分度，换成指数状态重试：SPY 站上 MA200 的天数占 77%（其中距 52 周高点 5% 以内占 67%），跌破占 23%，区分度够。规则是牛市放宽吊灯让盈利单活久、熊市收紧保住回撤，宽度在**开仓那一根锁定**（吊灯只上移，逐根重算的话放宽会被 `Math.max` 挡掉、收紧却立刻生效，只剩单向效果）。

## 年化基数 bug：2H 曾被高估三分之一

`barsPerYearOf` 里 `TWO_HOUR_BARS_PER_YEAR = 1008`（按 252×4 算），但常规时段 6.5 小时**每天只有 3 根 2H bar**，实测 754 根/年。年化基数高 34%，2H 的 CAGR 被系统性放大（`final^(1/T)`，T 被压缩到 0.75 倍）。

实测校正：4H 每天 1.99 根（504 对实测 500，偏差 0.8% 可忽略）、日线 1.00 根（252 正确）、2H 3.00 根（应为 **756**）、1H 6.02 根（应为 **1512**）。**只有 2H 受影响，此前所有 4H 与日线结论不变。**

修正前后的差距足以改变结论：2H 最优档全期从 42.7% / MAR 1.58 落到 **30.5% / MAR 1.13**，而 4H 是 25.2% / 1.53。修正前 2H 的 MAR 看着略胜 4H，修正后全面落后。

### 2H 有没有「属于自己的最优参数」——没有

上面那版网格只动了 4 个维度，`stopMult` 钉死在 5、止盈从没开过、RSI 阈值和 RS 转弱离场也没扫。把风控与过滤旋钮全部放开重扫（信号定义 Vegas/MACD 不动）：

**第一轮 256 组联合网格**：止损 {3,4,5,6} × 吊灯 {5,6,8,10} × 止盈 {无, 3R} × 门槛 {10,30} × 仓位 {8%,10%} × 入场窗口 {每根, 收盘}。上限是三段最差 **0.23**、全期 MAR **1.23**。

## 完整参数复核：三个从未测过的维度，以及一个更值钱的教训

> ⚠️ **本节的 4H 部分是在坏数据上做的**：4H 当时只有 2021 起点，缺席 2022 跌段（见文末
> 「口径审计」）。其中「维持单笔 10%」这条已被「4H 重定档」直接推翻——在补齐的数据上
> 重搜，最优正是当年被否掉的 8%。日线部分不受影响（日线数据一直完整）。
>
> `minRsi` 与 `rpsExit` 这两维后来在修好的 4H 数据上重搜了 20 组，方向与本节一致
> （RSI 30、不开 RS 离场仍是最优），见「4H 重定档」末尾一节。所以本节两条陷阱的
> 方法论结论仍然有效，只有 4H 的具体取值不能用。

此前对 4H 的搜索只覆盖六个维度（门槛、止损、吊灯、仓位、置换、执行窗口）。`takeProfitR` 一直是 `null`、`minRsi` 一直是 30、`rpsExit` 从没开过——**止盈这一整块从未验证，只是沿用了既有纪律**。日线更早期，门槛 40 / 止损 4 / 吊灯 5.5 定下后再没在同一套网格里复核。

按「买点定义与 Vegas 开关固定、其余全部放开」重做，每个周期 1800 组联合网格（止损5 × 吊灯6 × 止盈4 × 门槛5 × 仓位3），加阶段二的 RSI / RS离场 / 双执行窗口 / 置换。

### 陷阱一：用全期数据选参 = 数据窥探

4H 全期 MAR 榜首是「止8 吊10 盈3R 门30 12.5%」，MAR 2.31、三段最差 1.52，两个口径同时第一，冻结档只排第 25/1800。看起来是重大发现。

改成**只用训练期前三年选参、再看样本外**，真相反转：

| | 训练 MAR | 样本外 MAR |
| --- | --- | --- |
| 训练期 Top1 | 2.83 | 0.96 |
| 训练期 Top2 | 2.83 | 0.57 |
| 训练期 Top10 中位数 | — | **0.96** |
| 冻结档（训练期排 409/1800） | 2.09 | **1.86** |

**训练期排名对样本外几乎没有预测力。** 那个 2.31 是用包含样本外的全期数据选出来的，它连训练期前十都进不去。

### 陷阱二：样本外窗口是单一牛市，「样本外 MAR」测的是牛市表现

改用维度边际分析（不挑单点，看每个取值在 1800 组上的中位数）后，日线显示应该把吊灯 5.5 放宽到 8、仓位 12.5% 降到 8%、开 4R 止盈，样本外 MAR 从 1.44 涨到 2.35。摊到子窗口：

| 日线配置 | 第1段（熊） | 训练前3年 | 样本外后2年 | 全期 |
| -------- | ---------- | --------- | ----------- | ---- |
| 冻结档 止4吊5.5无盈门40 12.5% | **0.45** | 0.98 | 1.44 | 0.99 |
| 「改进版」止6吊8盈4R门40 8% | **0.10** | 0.75 | 2.35 | 1.21 |

样本外窗口 2024-08→2026-08 **整段是单边牛市**，所以「样本外 MAR」这个指标测的不是稳健性而是牛市表现，用它选参必然选出牛市参数。唯一跨越了熊市的判据是三段最差（第1段含 2022）。按它：日线冻结档 0.45 对改进版 0.10，4H 的 10% 仓位 1.16 对 8% 的 0.84，**现值都赢**。

### 结论：两个周期的冻结档都不动

- **止盈无系统性优势**：4H 上 4R 的样本外中位数 1.29 对无止盈 1.19，差 0.10 落在噪声内，而 2R 反而更差（1.08）。「不止盈」的纪律不必推翻。
- **RSI 30 / 不做 RS 离场 / 收盘入场每根出场 / 不置换**：阶段二 78 组全部确认现值最优。
- **日线门槛 40 踩在最优档**：样本外达标率 92%，门0 只有 12%。
- 唯一真实的候选是 4H 单笔 10% → 8%（全期与样本外略好），但熊市段 MAR 从 1.56 掉到 1.33。这套策略立身之本是熊市韧性，维持 10%。

## 四个周期横评：4H 是甜蜜点，两侧都在恶化

1H 数据补齐后（196 只、每天 6 根、实测 1508 根/年），四个周期在熊市段（2021-08→2023-04）的对比：

> **⚠️ 本节结论已作废，见文末「口径审计」。** 4H 数据当时只从 2021-01 开始，676 根 Vegas
> 慢线在窗口起点 2021-08 尚未播种，`vegasOk` 恒为 0，4H 因此被迫空仓到 2022-05-11，
> **整段缺席了 2022 熊市主跌段**。下表「4H 熊市段 +17%」有很大一块是缺席而非韧性。
> 2H 的年化还额外受基数错误影响（实测 3.52 根/天，常量按 3 算，年化被压低 15%）。

每个周期都取「各自网格里的最好一档」，而不是套用 4H 的参数：

| 周期 | 各自最优参数 | CAGR | 最大回撤 | 全期 MAR | 三段最差 | 熊市段年化 / MAR |
| ---- | ------------ | ---- | -------- | -------- | -------- | ---------------- |
| 日线 | 止4 吊5.5 无盈 门40 12.5%＋置换 | 24.0% | 24% | 0.99 | 0.45 | +10% / 0.45 |

**唯一一个在四个口径上同时不输的是 4H。** 2H 和 1H 能拿到更高的绝对年化（30.5% / 40.1%），代价全部落在同一处：熊市段从 +17% 塌到 +6% 甚至 -4%，三段最差从 1.16 塌到 0.21 / -0.20。日线方向相反——熊市不亏但回撤 24%、机会太少，MAR 卡在 0.99。

1H 试了五种差异很大的风控（紧/宽/开止盈/换执行窗口），**熊市段无一例外负收益**。1800 组全网格进一步确认这不是选点问题：

**每个维度每个取值的训练期中位数都是负的**（唯一例外是吊灯 10 的 +0.07），训练期含 2022 熊市。样本外 MAR 过 1.5 的占比在 0~2% 之间，同一指标 4H 是 15~41%、日线门槛40 档达 92%。

机制：bar 越短噪声越大，熊市下跌途中抄底信号不断出现又不断被止损打穿，周期越短消耗越致命；但周期太长（日线）信号又太稀疏接不住机会。**4H 是这条曲线的顶点。**

### 当前配置的持仓画像（实操参考）

2501 根 4H K 上：持仓**中位 8 只**，众数 9 只（占 32.5% 时间），7~9 只覆盖 64.5% 的时间，均值 6.4（被空仓期拉低），峰值 10 只但仅占 1.3%，**完全空仓占 14.4%**（主要落在 2022），平均股票敞口 **67%**。五年开仓 257 笔、因现金不足放弃 1133 次。

### 方法论：安慰剂基线

这一轮最有价值的产出不是任何结论，是这条基线：**在这份数据上，仅让仓位随机浮动就能把全期 MAR 搅动 ±0.3**。因此任何仓位类规则若改善幅度不到 0.3，都无法与运气区分。

回头看，8% 对 10%（1.55 对 1.53）、6% 对 10%（1.58 对 1.53）这类比较都在噪声地板之下——真正有信息的差别在回撤深度和三段稳健性，不在 MAR 本身。**以后新增任何仓位或状态规则，先跑打乱时序和纯随机两个安慰剂，过不了就不要采纳。**

## 口径审计：四个周期的计算方式逐项核对

起因是「各级别的计算方式是不是一样的」这个问题。逐项实测下来有三个真问题，其中一个
推翻了 4H 的核心结论。审计口径：窗口固定 2021-08→2026-08，四个周期用**同一组参数**
（门槛10 / 止损5 / 吊灯6 / 不止盈 / 每笔10% / 不置换 / 每根进出），使差异只来自周期本身。

### 致命：4H 缺席了 2022 熊市主跌段

4H 数据起点 2021-01-04，窗口起点是全局第 322 根。Vegas 慢线是 **676 根 EMA**，
`prepareUniverse` 的规则是「四条 EMA 任一未播种则 vegasOk = 0」，即未播种等于全池禁止入场。
实测逐月：

| 月份 | 2021-08 ~ 2022-04 | 2022-05 | 2022-06 | 2022-07 |
| ---- | ----------------- | ------- | ------- | ------- |
| Vegas 通过率 | **0%** | 37% | 44% | 36% |
| 持仓只数 | **0.0** | 5.2 | 7.8 | 8.9 |

首次开仓 **2022-05-11**，距窗口起点 8.6 个月。标普 2022 年高点在 1 月 3 日，到 5 月中已跌
约 18%——4H 整段没参与。四个周期的预热情况：

| 周期 | 数据起点 | 窗口起点处预热根数 | 676 根够不够 | 首次持仓 |
| ---- | -------- | ------------------ | ------------ | -------- |
| 日线 | 2013-08-27 | 2012 | 够 | 窗口第 2 根 |
| **4H** | **2021-01-04** | **322** | **不够** | **+8.6 个月** |
| 2H | 2021-01-04 | 556 | 不够 | +3.5 个月 |
| 1H | 2021-01-04 | 966 | 够 | 窗口第 9 根 |

**只有 4H 在熊市跌段缺席，而 4H 恰好是此前推荐的周期。** 日线和 1H 全程在场，2H 缺的
3.5 个月不在跌段。所以「4H 熊市 +17%、回撤 16%、MAR 1.53 是唯一甜蜜点」这个结论，
其熊市部分来自缺席而非策略韧性，四周期横评在此前提下不可比。

**修法**：把 4H 的 30 分钟棒起点拉到 **2016-01**（`scripts/fetch-smallfund-4h.ts` 的
`FROM`）。注意 `fetchOne` 有缓存短路，必须 `SMALLFUND_REFETCH=1` 才会真的重抓，否则会
读本地旧文件并报「成功」。

补数据时踩到的三件事，都会让「补过了」变成假象：

**一、播种线 676 根不是够用线，2000 根才是。** 4H 实测精确 2.00 根/天，676 根只要 338
个交易日（1.4 年）。但 EMA 的首值种子按 (1−2/677)^n 衰减，窗口前 n 根递推后残留：

| 窗口前根数 | 起点 | 种子残留 | 后果 |
| ---------- | ---- | -------- | ---- |
| 575 | 2020-07 | — | 未播种，`vegasOk` 恒 0，全池禁止入场 |
| 1332 | 2019-01 | **14%** | 能入场，但慢线被 2019 年低价拖低 |
| 2270 | 2017-01 | 2% | 可用 |
| 2822 | 2016-01 | 0.2% | 干净 |

14% 这档不能要：种子是 2019 年初的价格，远低于 2021-08，会把 576/676 慢线**压低**，
使 `min(fast) > max(slow)` 更容易成立，即**入场偏多、熊市表现偏乐观**——与上面这个
bug 同向。所以只把 146 只未播种的补到 2019 是不够的，30 只已有票也一起重抓。

**二、`resolvedFeed` 是全局变量，一次 429 会静默把全池锁进短历史。**
`fetchAlpacaIntraday` 原先在降级成功后记忆 feed，而 429（临时限流）和 403/subscription
（永久无权限）走同一条降级路径。于是任一只票被限流一次，`resolvedFeed` 就锁成 iex，
**后续所有票静默拿 iex 的短历史**（30Min 只到 2020-07）——这正是 146 只票起点是
2020-07 的原因，它不是账户权限问题。已在 `alpaca.ts` 修：只记忆首选 feed 的成功，
永久错误才记忆降级，并加 `ALPACA_FEED` 强制指定绕过自动降级。

**三、吞吐是账户级硬限制，提并发只换来失败。** 实测（197 只、11 个年 chunk/只）：

| MAX_INFLIGHT / 并发 | 结果 |
| ------------------- | ---- |
| 3 / 3 | 约 1.1 分钟/只，0 失败 ← 可用上限 |
| 3 / 4 | 约 2.0 分钟/只，0 失败 |
| 5 / 5 | **5/5 全失败**，HTTP 429 |
| 12 / 10 | 大量 429 |

强制单 feed 时 429 没有退避重试、直接判失败，所以并发超限不是变慢而是整批报废。
全量重抓约 3.6 小时，这是没法压缩的成本。

### 严重：2H 的 bar 相位随票而异，年化基数因此错 15%

| 周期 | 常量 bpy | 实测 bpy | 偏差 | 每天根数实测 |
| ---- | -------- | -------- | ---- | ------------ |
| 日线 | 252 | 252 | 0.0% | 1 根 × 1255 天 |
| 4H | 504 | 503 | +0.2% | 2 根 × 1248 天，1 根 × 5 天 |
| **2H** | **756** | **887** | **-14.8%** | 3根×857 / 4根×194 / 5根×149 / 6根×54 |
| 1H | 1512 | 1512 | 0.0% | 6 根 × 1254 天 |

单看 AAPL 是规整的 3 根/天，问题在**票与票之间**。异常日的时间戳集合形如
`14:00 15:00 16:00 17:00 18:00 19:00`——`aggregateTo2H` 是「1H 每两根配对」，配对相位
取决于每只票当天的首根时间：某票首根 14:00 配成 14/16/18，另一票首根 15:00 配成
15/17/19，全池并集就是 6 个。**2H 的 bar 边界依赖各票自身数据起点而不是绝对时钟，
不同票的 2H bar 代表不同的时间窗口，截面不同步。** 4H 不受影响，因为它按固定的
9:30–13:30 / 13:30–16:00 从 30 分钟棒切分。

因此 2H 的问题不止年化：bar 本身没对齐，全部 2H 结论应视为不可信。要修得让
`aggregateTo2H` 改用绝对时钟切分，而不是相对配对。

**已修**：`aggregateTo2H` 改为按美东墙钟 9:30 / 11:30 / 13:30 绝对分桶，每天恒定 3 根。

### 严重：1H 每天缺开盘后半小时，而上表判它「0.0% 偏差」

上表给 1H 的结论是「6 根 × 1254 天，年化偏差 0.0%」，看着最干净的一档。但常规时段
9:30–16:00 是 6.5 小时，**每天 6 根整点棒根本盖不满**。审计只验了「每天根数是否恒定」
和「年化基数对不对」，没验「这些根加起来是否覆盖完整交易时段」——相位一致但整体缺了
一块时，前两项全部通过。这是那轮口径审计的盲点。

根因在 `isNyRegularHours`：它拿 **bar 的起始时间戳**比对 9:30–16:00。Alpaca 的
`1Hour` 按整点分桶，承载 9:30–10:00 开盘交易的那根时间戳是 **9:00**，于是被当作盘前
丢弃，每天首根变成 10:00。而 30 分钟棒的起始戳正好是 9:30，能通过——**同一个过滤函数
对 30M 正确、对 1Hour 错误**，4H 一直没事纯粹因为它走的是 30M。

实测 AAPL 2023-06-15：被丢的那根成交 9,377,986 股，占全天 21%，是当天第二大的一根。
保留的 6 根合计 43.73M 与 1H CSV 完全一致，补回被丢的那根为 53.11M，与 4H CSV 的
52.95M 对上，链路闭合。

受影响范围：1H 全部结论作废；2H 由 1H 聚合而来，同样作废（它的首桶标着 13:30，里面
第一笔却是 14:00 的）。4H 与日线不受影响。**注意方向**：开盘后半小时是全天波动与成交
最集中的时段，短周期对它最敏感，此前「1H 三段最差仅 0.44，说明周期越短噪音越大」的
解释站不住——它垫底也可能只是因为数据缺了一块。

**已修**：1H 改为 `fetchAlpaca30MBars` + `aggregateTo1H`，与 4H 同一条链路；2H 由新
1H 再聚合。三个周期的切点统一从 9:30 起算，11:30 / 13:30 同时是 2H 与 4H 的桶边界，
bar 层层嵌套。`tests/aggregateTo1H.test.ts` 锁住了首根覆盖 9:30–10:30、以及
「先合 1H 再合 2H/4H」与「直接由 30M 合 2H/4H」结果全等。

校验（QQQ，重抓后）：每日恒定 7 根，首根 13:30 EDT / 14:30 EST，逐日成交量与 4H 在
2680 个交易日里 2679 天完全相等，唯一不一致的 2026-08-31 是两次抓取时点不同导致的
盘后修正，在回测窗口之外。

### 已修：收益与回撤改为日频口径，不再依赖 barsPerYear

根因是「拿每根 bar 折年」这个做法本身依赖一个易错的常量。`runRotate` 的统计已改为
**每个交易日取收盘净值、按 252 折年**，这样任何 bpy 常量错误结构上都影响不到结果，
且四个周期与 SPY/QQQ 基准同采样频率。同参数下两种口径的差：

| 周期 | bar 级 CAGR/回撤/MAR | 日频 CAGR/回撤/MAR | 回撤差 |
| ---- | -------------------- | ------------------ | ------ |
| 日线 | 21.6% / 21.4% / 1.01 | 21.6% / 21.4% / 1.01 | 0.0pt |
| 4H | 25.1% / 24.5% / 1.03 | 25.0% / 24.5% / 1.02 | 0.0pt |
| 2H | 23.4% / 29.6% / 0.79 | **28.0%** / 28.6% / **0.98** | 1.0pt |
| 1H | 7.1% / 28.8% / 0.25 | 7.1% / 27.6% / 0.26 | 1.2pt |

顺带否掉了一个担心：短周期 bar 采样更密会不会把回撤测得系统性更深。实测只有 1 个点，
不是结论的来源。

### 确认无误的部分

- **RPS 跨周期完全一致**：NVDA 2023-06-15 在日线是 99.00，4H 两根、2H 三根、1H 六根
  全部 99.00。日线标尺统一确实落实了。
- 日线 / 4H / 1H 的年化基数与实测吻合（偏差 ≤ 0.2%）。
- 盘中周期窗口末尾少一天：`windowBounds` 用字符串比较，`"2026-08-24T13:30" > "2026-08-24"`
  成立，故盘中周期的 `to` 当天被整天剔除，日线保留。只差一天，可忽略但需知道。

### 不是 bug，但让「周期横评」变成混合比较

Vegas 的 166/169/576/676 与 ATR 的 14 都是**根数**，四个周期共用，所以同一条规则的
日历跨度差 6 倍：

| 周期 | Vegas 慢线 676 根 | ATR14 |
| ---- | ----------------- | ----- |
| 日线 | 676 交易日（2.7 年） | 14 天 |
| 4H | 339 交易日 | 7 天 |
| 2H | 192 交易日 | 4 天 |
| 1H | **113 交易日（半年）** | 2.3 天 |

1H 的趋势过滤器只回看半年，熊市里一波反弹就转多头放行入场；止损 5×ATR 在 1H 上也只是
2.3 天波动的 5 倍，绝对宽度远小于 4H。此前把 1H 的失败归因为「周期短、噪声大」，但它
同样可以由「过滤器太短」解释——**1H 的全部网格里 Vegas 长度从未动过**。要区分这两个
解释，需把 1H 的慢线按日历对齐到 676×6 = 4056 根，而那需要约 2.7 年预热，因此 1H 数据
也得补到 2018-08（否则重演上面 4H 的空仓 bug）。这项待办已排入。

### 票级集中度：超额不依赖头部票，但基准选错会低估策略

问题是「35.9% 里有多少来自池子恰好装了几只神股」。全池 188 笔平仓涉及 126 只票，
净贡献合计 157% 权益，其中 54 只是净亏的。集中度看着很高：前 1 只（CLS）占净贡献
16%、前 5 只 43%、前 10 只 62%。

**第一版测法是错的。** 剔掉「策略自己贡献最大的 N 只」，CAGR 从 35.9% 掉到 23.8%（N=10）
和 17.5%（N=20），而随机剔同样只数几乎无影响（34.8~38.0%）。看着像「业绩全靠神股」，
但这是**按结果反选**：任何策略剔掉自己最赚的那几笔都会塌，收益分布本就右偏。

换成外生标准——剔掉「池子自身涨幅前 N」，两边都剔同一批票：

| 剔除 | 策略 CAGR/回撤/MAR | 买入持有 CAGR/回撤/MAR | 超额 | MAR 倍数 |
| ---- | ------------------ | ---------------------- | ---- | -------- |
| 0 | 35.9% / 17% / 2.09 | 26.9% / 26% / 1.02 | 9.0pt | 2.04x |
| 3 | 29.4% / 15% / 1.96 | 23.9% / 25% / 0.94 | 5.5pt | 2.07x |
| 10 | 28.8% / 15% / 1.94 | 21.0% / 25% / 0.85 | 7.8pt | 2.30x |
| 20 | 28.5% / 19% / 1.50 | 17.6% / 25% / 0.71 | 10.8pt | 2.10x |
| **40** | 22.5% / 16% / 1.39 | 13.4% / 25% / 0.54 | **9.1pt** | **2.57x** |

**剔掉 22% 的头部票，超额仍有 9.1pt、MAR 仍是 2.57 倍，且无衰减趋势。** MAR 倍数反而
随剔除量上升，说明风控的价值在弱势池子里更突出。这是目前对策略最强的稳健性证据，
比样本外那一段（单一牛市）更有说服力。

顺带纠正一个基准错误：此前拿「池内每根等权日频再平衡 31.6%」当基准，得出「策略只贡献
4.2pt」。那个基准不可执行（每天给 195 只票等权再平衡），且自带再平衡收益。换成买入
持有这个真实的被动基准后，归因是：

标普 11.3% → **池子选择 +15.6pt** → 买入持有 26.9% → **策略纪律 +9.0pt** → 35.9%，
同时把回撤从 26% 压到 17%。

结论：策略贡献 9pt 而非 4.2pt，且经剔票检验稳健。**剩下不可复制的是池子那 15.6pt**
——池子是 2026 年回看维护的手工列表，没有可复现的入池规则，这 15.6pt 无法分离，
因此 35.9% 这个数字不能对外使用。做基金的缺口在选股规则和实盘记录，不在策略。

### 补搜最后两维：RSI 闸门与 RPS 出场，都确认冻结档

重搜用的 576 组网格没覆盖 `requireRsi`/`minRsi` 和 `rpsExit`——这两维只在补数据之前
搜过，而本章的教训正是「同一网格只因少了五年历史，三项全部反向」，没理由认为它们
免疫。在冻结档基础上交叉扫 5×4 = 20 组（`fund-rotate.ts 4h rsi`；交叉而非各扫一遍，
因为两者都在过滤弱势票、可能互相替代），冻结档排第 1/20。

`rpsExit` 开了明确有害，而且单调：

| RPS 出场门槛 | 关 | 10 | 20 | 30 |
| ------------ | -- | -- | -- | -- |
| 三段最差 | **1.77** | 1.05 | 0.99 | 0.81 |
| 全期 CAGR | **35.9%** | 28.2% | 27.2% | 23.8% |
| 开仓次数 | 200 | 230 | 294 | 411 |

单调、幅度大、机制自洽，是这轮里形状最可信的一维：出场已经由吊灯负责，再叠一层 RPS
出场只会在回撤途中把仍在有效持仓期的票提前踢出、再买回来，纯增摩擦。与前面「转弱
离场」那一节的结论一致。

RSI 闸门是肩部，不是孤峰：

| | 关 | ≥20 | **≥30** | ≥40 | ≥50 |
| --- | -- | --- | ------- | --- | --- |
| 三段最差 | 1.60 | 1.60 | **1.77** | 0.73 | -0.48 |
| 开仓次数 | 199 | 199 | 200 | 195 | 49 |

左平右陡。「关」与「≥20」逐位相同，说明 4H 买点处 RSI14 从未跌破 20，闸门的有效区间
就在 20–30 之间。≥50 那四档三段最差全为负、开仓只剩 49 次——门槛抬高等于杀死策略本身，
这符合机制：抄底买点天然出现在 RSI 低位。

**「≥30 比关闭好 0.17」不是单笔运气。** 两者开仓数只差 1（200 对 199），一度让人怀疑
这 0.17 落在噪声里；但按票比对成交笔数，188 笔中有 35 笔不同（19%）。净数看不出来是
因为满仓要放弃新信号，滤掉一个弱信号会把坑位让给后面的票，一进一出相互抵消。

至此 4H 的九个可调参数（止损、吊灯、止盈、RPS 门槛、仓位、入场窗口、出场窗口、RSI
闸门、RPS 出场）都在补齐的数据上搜过了，冻结档在每一维上都是第一或落在平台上。残留
的不确定性仍是上面那两个孤峰，补搜没有改变它：**实盘预期按 MAR 1.3~1.5 折算，不是 1.77。**

### 教训：数据缺陷会让参数搜索指向系统性错误的方向

同一个网格、同一套判据，只因 4H 少了五年历史，选出的止损/吊灯/门槛三项全部反向。
缺席熊市的历史里，窄止损没有代价（因为没有大跌可躲），门槛也显得有用（因为样本里
只有牛市，弱势票确实该剔）。**参数搜索不能校验数据本身是否完整，它只会在给定数据上
找最优。** 补数据前后的两轮搜索都收敛得很好，但只有一轮是对的。
