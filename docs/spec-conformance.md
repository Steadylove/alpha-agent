# 四份规格的实现对照

记录 `轻量级量化投研/` 下四份文档的落地情况：哪些照搬、哪些改了、哪些没做以及为什么。

四份文档分别是：

| 简称 | 文件 | 性质 |
| --- | --- | --- |
| 轮动 Pine | `美股动能满仓轮动雷达 (全口径NAV精准核算·旗舰版) 1.txt` | 可执行 |
| MPR Pine | `Market Phase Radar - 市场相变雷达 (专业交易版).txt` | 可执行 |
| Compass Pine | `MarketCompass量化估值与市场相变决策系统.txt` | 可执行 |
| 商业化文档 | `商业化产品架构闭环（三层决策漏斗）.txt` | 产品愿景，无代码 |

**总口径：Pine 为准。** 三份 Pine 是能在 TradingView 上跑出图的东西，商业化文档是一份还没被验证过的设计稿。两者冲突时按 Pine 实现，商业化的说法做成默认关闭的开关（见 `src/lib/config/commercialSpec.ts`），需要时逐项打开。

## 一、四处直接冲突

### 1. RS 算法：截面分位 vs 逐股饱和映射

商业化文档第 146 行要求 `RS_i = PercentileRank(AlphaScore_i, Universe)`，即全池截面排名。三份 Pine 用的都是逐股独立的饱和映射——一只股票的分数只取决于它自己相对基准的表现，与池子里其他股票无关。

Pine 拿不到全池数据（TradingView 单图表限制），这个差异是环境造成的而非设计分歧。项目里两套都有：

- 生产路径用饱和映射（`relativeRs.ts`、`mprAlphaRs.ts`），与 Pine 一致
- 截面分位实现在 `percentileRs.ts`，开关 `COMMERCIAL_SPEC.percentileRs` 默认关

两者的实质区别是：同样的绝对涨幅，在强势市场里截面 RS 会给更低的分。这不是精度问题，是两种不同的选股哲学。

两套的回看周期与权重相同（21/63/126/252、.1/.4/.3/.2），差别在饱和映射除基准而截面分位用绝对涨幅，见后文「截面 RPS 改用绝对涨幅」。

### 2. 入场门槛：RS≥70 / RS<40 一票否决

商业化文档第 148~152 行的硬门槛。**两份 Pine 都没有这条**——轮动 Pine 只有一个默认关闭的 `RSI > 30` 过滤，跟 RS 评分完全是两回事。

项目现状是 `minRs = 30`，这个数**既不在 Pine 里也不在商业化文档里**，是回测校准出来的自加项：30 是唯一让胜率、均值、盈亏比三项同时改善的档位（629 笔 52.8%/+7.07%/2.47 → 508 笔 53.7%/+7.24%/2.70）。往上加会适得其反，RS≥45 砍掉 69% 的成交而均值反降到 +6.32%。

商业化版本实现为 `COMMERCIAL_SPEC.rsEntryVeto`，默认关。

### 3. 保本触发：+5% 提前档

商业化文档第 217 行：常态 +10%，但 Path 2 或 5 日下跌概率 ≥60% 时提前到 +5%。两份 Pine 都只有 +10%。

实现在 `rotationTrade.ts` 与 `stockRisk.ts` 的 `useEarlyBreakeven`，宏观条件由调用方通过 `earlyBreakevenActive(index)` 注入，默认关。

### 4. 组合权重：E_macro 敞口缩放

商业化文档要求 `W_i = E_macro(Path) × RS_i/ΣRS_j`，Pine 只有 `RS_i/ΣRS_j`。

**这一项有反向证据。** 组合层回测（3927 日、已去除未来函数）显示照 E_macro 机械减仓会让收益/波动从 1.18 降到 0.95。已实现为 `COMMERCIAL_SPEC.macroExposureScaling`，默认关；打开前请重跑回测。

## 二、Pine 内部的矛盾与死代码

### 低吸带的 `upside >= 15%` 门槛是死代码

Compass Pine 里先算了一个带 15% 上行空间门槛的低吸带，但紧接着的每个 stage 分支都会无条件覆写它，这个门槛实际上永远不生效。

按 Pine 的**实际行为**实现（门槛不参与计算），同时在 UI 上把 upside<15% 做成提示性标注，让用户看得到这个信息但不改变信号。

### 阶段消歧的两套优先级

Compass Pine 的显示阶段和低吸带用的阶段走的是不同的优先级链。低吸带用 A>E>D>W>C，与显示阶段不同。实测两者有 7.35% 的日子会分歧，主要是显示 Stage W（震荡）但低吸逻辑该用 Stage E（混沌筑底）的情况。

`stockStage.ts` 暴露原始 `StageFlags`，`dipStageOf()` 单独实现低吸口径。

### MPR 的 `act_text` 与本项目的证据结论相反

MPR Pine 的 `act_text` 会根据 Path 给出明确的方向性和仓位建议。但本项目对 MPR 路径做过校准，结论是**没有预测力**，因此 `mprReading.ts` 刻意不给方向性建议。

两者都保留：`mprGuidance.ts` 忠实移植了 Pine 原文并在 UI 上标为「原版指引」，`mprReading.ts` 的证据结论并列展示，附上预测力的说明。用户看得到原版说了什么，也看得到我们为什么不照做。

## 三、数据源替换

### short interest 走 FINRA + SEC，而非 Pine 的 TradingView 财务字段

Compass Pine 用 `request.financial(..., "SHORT_INTEREST", "FQ")`，这是 TradingView 的季度财务字段，项目外拿不到。替换为两个免费源：

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 空头持仓股数 | FINRA `consolidatedShortInterest` | 免费无鉴权，覆盖全美股 22341 只，轮动池 40 只无缺口 |
| 在外股本 | SEC XBRL companyconcept / companyfacts | 免费，需 User-Agent；仅 ETF 无申报 |

**比 Pine 原版更新鲜**：Pine 是季度口径，FINRA 是双月度（每月 15 日与月末结算，结算后第 7 个交易日发布，滞后 2~3 周）。

实测轮动池档位分布：`extreme` 2 只（IREN 27.5%、ASTS 19.0%）、`warning` 3 只（IONQ 13.2%、CRWD 10.0%、LITE 9.5%）、其余 `swing`。大盘股普遍在 1% 上下。

两个实现细节值得记一笔：

- SEC 在概念不存在时返回 **HTTP 200 但 body 是 XML**，只看 `res.ok` 会踩空
- 多类别股公司（META、GOOG）不报封面页合计股数，只能回落到加权平均稀释股本。这类都是万亿级大盘、空头占比约 1%，离 8% 档差一个数量级，近似误差不改变档位

**已知失真：** 发过大额可转债的标的（IREN、NBIS），空头持仓里含做市商的中性对冲仓，不是方向性空头，占比会系统性虚高。Pine 的算法照实移植，UI 上对 >=8% 的标的给出提示，判断留给使用者。

### MarketCompass 的 MPR 变体（未实现）

Compass Pine 里内嵌了一套简化版 MPR，与 MPR Pine 的完整版口径不同。没有单独建模块——两套并存只会让用户困惑，且完整版是超集。差异点记录在此，不做实现。

## 五、每日调度

`.github/workflows/daily-quant-jobs.yml`，00:30 UTC 周二至周六（美股收盘后约 4.5 小时，日线已定稿）。

先跑三个 backfill 补日线，再由 `npm run jobs:daily` 按依赖顺序执行：

```
macro-phase → short-interest → rotation-radar → stock-panel → stock-valuation
```

顺序约束有两条：`macro-phase` 的产出被后面三个读取（低吸带 Path 4 冻结、估值的 fsmState/pathId、提前保本的宏观条件）；`short-interest` 必须早于 `stock-valuation`，否则轧空档位读到上一期。

`short-interest` 是唯一的软失败步骤——它依赖 FINRA 与 SEC 两个外部免费接口且双月才换一期，挂掉时估值沿用上一期缓存即可，不该拖垮整条链。

### 调度相关的已知问题

- **日线更新用 `skipDuplicates`,不修正历史。** 发生拆股时旧价不会被重算，需手工清库重跑 backfill。这是 backfill 脚本的既有设计，不是调度引入的
- **`backfill:sectors` 的行业归属部分对全部 40 只标的报「FMP 无行业数据」**，当前订阅不覆盖该接口。ETF 日线正常，板块时钟走的是 `SECTOR_UNIVERSE` 而非逐股归属，因此不受影响；脚本退出码为 0，不会中断 workflow

## 六、调参实验室（/lab）

线上四个面板跑的是 40 只固定标的，那份名单是按今天的认知挑的，回测动能策略会严重虚高。`/lab` 换成标普 500 的时点成分池，专门用来诚实地评估买点。

### 数据

| | 来源 | 落库 |
| --- | --- | --- |
| 成分资格 | fja05680/sp500 的成分快照，2718 个变更日、1996-01 至今 | `IndexMembership`，1259 段区间 |
| 日线 | Yahoo，20 年 | `BacktestPanel`，653 只、296 万根 |

成分快照压成区间而非逐日展开：展开后是 130 万行，压成区间只有 1259 行，而「某日是否为成分」两种形式都能回答。52 个 ticker 多次进出指数（如 AMD 1996 进、2013 剔除、2017 回归），所以一个 ticker 会有多行。

时点正确性的交叉印证：NVDA 于 2001-11-30 入指，Enron 于 2001-11-26 离开——历史上 NVIDIA 正是顶替安然进入标普 500。

日线不复用 `DailyBar`：296 万行在那张表的逐行结构下约 900MB 且冷加载上百秒，而回测要一次读全池。`BacktestPanel` 按 Float32 打包，单只 80KB、全池约 56MB。两张表的访问模式相反（面板查单只的日期区间，回测读全池），刻意不共用。

### 三条防自欺的约束

1. **时点成分**：某日只在当日成分中选股，截面 RPS 也只在当日成分间排名
2. **同池基准**：每个结果并排给出「同一时点池等权买入持有」。策略与基准吃同一批数据、同一个窗口，幸存者偏差大体相抵，可信的是二者之差而非任一方的绝对水平
3. **样本内外分离**：2020-01-01 切分，保留区在 UI 上默认盖住，点开次数计数

### 已知残留偏差

287 个 ticker 在 Yahoo 取不到价格（404 或无数据，串行重试后确认为持续性，非限流），全部排除，覆盖率 653/940。被收购者多以溢价离场（排除后偏低），破产者清零（排除后偏高），净偏差符号不定。因排除同时作用于策略与基准，对二者之差的影响远小于对绝对水平的影响。

### 性能与面板落盘缓存

冷启动原本约 17 秒，其中 **DB 读取 13.5 秒、信号与截面计算仅 1.8 秒**——瓶颈是 47MB 二进制的跨区传输，不是计算。单次回测 190~260ms，常驻 245MB heap。

这批面板是不变的存量行情：整块读走、从不按条件筛选，本质是文件而非数据库内容。
放在云 Postgres 里意味着每跑一次回测就重新下载一遍完整历史。Neon 免费档
**5GB/月出站额度**按 47MB 一次算只够约 106 次，调参搜索期间确实被打满，
超额后 Neon 直接挂起整个 compute（连 `SELECT 1` 都返回 `53000`，线上站点一并失效）。

因此加了本地落盘缓存 `src/lib/backtest/panelCache.ts`：
- 缓存文件 `.cache/backtest-panel.v8`（已 gitignore），用 `v8.serialize`，
  原生支持 `Uint8Array` 与 `Date`、零依赖。格式不保证跨 Node 大版本稳定，
  故读取失败、版本号不符一律当作未命中重新拉取，不抛错
- 快照**与选哪个池无关**，一份服务三个池子：面板查询本就没有 where 条件
  （要哪些标的靠成分区间在本地筛），成分表也小，于是连 `IndexMembership`
  一起整表取回、在内存里按 `index` 过滤
- `BACKTEST_PANEL_REFRESH=1` 强制重新拉取，日线回填之后用它刷新
- 写入失败只返回 false 并打日志：Vercel 之类的部署环境工作目录只读，
  那里本就不该依赖磁盘缓存（函数实例文件系统是临时的，进程内缓存已覆盖
  同一实例的重复请求），退回原有行为即可，不该让一次回测直接失败

效果：本地出站流量降到「首次一次」，准备段 17.7 秒 → **3.4 秒**（省掉的正是那 13.5 秒传输，
剩下的是信号与截面计算本身）。

注意这主要修的是**本地开发**——出站流量正是被反复的本地回测与参数搜索烧掉的。
线上若要同样免流量，需另做决策（面板提交进仓库让构建时打包，或放
Cloudflare R2——它出站永久免费），目前线上访问量低，未处理。

### 绕过数据库重建缓存

`npm run panel:cache`（`scripts/build-panel-cache.ts`）直接从公开源重建缓存，全程不碰数据库。

存在的理由：这批数据原本就是从公开源抓来的——日线来自 Yahoo，时点成分区间来自
GitHub 上那两个 CSV 仓库。所以配额打满、compute 被挂起时不必等下个计费周期。
抓取口径（20 年窗口、`MIN_BARS = 400`、失败即跳过）与 `backfill-sp500-panel` 完全一致，
区别只是终点从 Postgres 换成缓存文件，且不写 `hasBars`——缓存里只放抓到价格的标的，
这本身就等价于 `hasBars = true`。

可中断续跑：进度写在 `.partial` 暂存文件里，重跑跳过已抓到的。**只有完整跑完才
rename 到正式缓存路径**——否则中断会留下一个「可用但不完整」的缓存，回测静默地少一批标的。

实测 1024 个目标、并发 6，**2 分 39 秒**跑完，成功 701 只、失败 323 只（退市或样本不足），
缓存 59.8MB。

与数据库那份的等价性验证（对比同日从 DB 加载的同一配置）：
- 池内标的 **701 = 701**，日期轴 **5027 = 5027** 天，训练/保留区切分逐日相同
- 同池等权基准净值 **4.18x / 1.46x 逐位相同**——这是最强的一条：基准只取决于
  价格数据与成分区间，与 RPS 公式无关，它一致即说明面板等价
- 策略侧数字有差异（信号 2998 vs 3146）是因为两次之间 RPS 口径按规格退回，非数据差异

### 与线上策略的差异

`/lab` 的入场闸门是截面 RPS，`minRs` 置 0；线上 `rotation-radar` 用的是 `rotationRs` 的绝对饱和映射、闸门 30。两者不是同一口径：RPS≥50 会砍掉 84% 的成交，而 rotationRs≥30 只砍掉 19%。

### 参数搜索的结论

`npm run lab:search` 跑 1260 组网格，切分点固定在五年前。两张排序表指向完全不同的答案，这本身就是结论：

- **按最近五年超额排序**：前十二名全是二买 + RPS50，只有 192 笔，最好一组近五年 +27.21% 而早期十四年 **-7.51%**。且不同止损值给出逐位相同的结果，说明落在了参数不起作用的退化角落。这一列不可信
- **按两窗口较小值排序**：候选集中在一买 + RPS30 + 吊灯 2~2.5，样本 1100~1200 笔

细扫每个参数（`--stability`）后落在：**一买、RPS≥30、止损 4×ATR、吊灯 2×ATR、止盈 3R**

> 止盈随后已改为**不止盈**，见文末「出场砍到只剩一条规则」。本节其余数字是那次改动之前测的。

细扫结果决定了其中每一项，各轴形态很不一样：

- **RPS 门槛**是真平台。20~35 四档两窗口同时为正，30 在早期窗口是局部最高（+8.14%）。0 和 60 两端都转负，说明"只做强势股"这个方向本身有效，不是拟合出来的
- **初始止损**几乎不起作用。3.5 以上早期窗口一直在 +8% 附近、近五年一直在 +5.7% 附近，因为吊灯设在 2×ATR 比它紧得多，实际出场几乎总由吊灯触发（1792 笔里 1779 笔走止损通道）
- **吊灯止损**是最尖的一条轴，也是唯一需要小心的。上一轮选参把网格下界设在 2 而最优正好落在边界，这一轮把轴延伸到 1 重扫，确认 2 是内部最优：1.25 近五年 -0.71%、1.5 +0.03%、1.75 +2.73%、**2 +6.10%**、2.5 +5.67%、3 +0.09%。只有 2 和 2.5 两档站得住，是条窄脊而非平台
- **止盈**在 2.5R 以上是平的，6R 起与不止盈逐位相同。3R 折算成 12×ATR，1792 笔里只触发 13 次。取 3 是按判据落下来的，这一项本身不承载信息
- **转弱离场**（RPS 跌破阈值平仓）仍然不值得开。5~15 档近五年略好（+6.2~+6.5% vs 不开的 +6.10%）但早期窗口同时变差，两窗口方向不一致，是噪声

（次日开盘成交、无止盈）重算，夏普用本仓定义 `年化 ÷ 波动`，不减无风险利率：

**保留区策略超 SPY 是 -0.40%。** 即最近五年跑输买入持有 SPY，夏普也略低（0.64 vs 0.67），

训练区反过来，策略超 SPY +8.08%、夏普 0.76 对 0.39、回撤还小 16 个点（同池等权超 SPY +2.67%）。但两个窗口结论相反，
且训练区那个数有三处已知折扣：参数是在它上面搜出来的；池子缺 287 只 Yahoo 取不到的退市票，
有残留生存偏差；它包含 2008，而本引擎空仓日收益记 0，等价于崩盘年自动降敞口，
这让策略在下跌段结构性占优。beta 接近 1（持仓日 99%、纯多头、不对冲）。

复现方式：SPY 不是任何指数成分，被 `loadPreparedUniverse` 排除出池，且**重建本地缓存时
一并漏掉了**，所以这张表目前需要临时脚本现抓 SPY 日线才能重算，不能离线复现。
要长期可复现，得把 SPY 加进 `build-panel-cache.ts` 的抓取清单并重建缓存。

20 年里 15 年超额为正（早期 11/14、近期 4/6；符号检验单边原始 p≈2.1%，但计入本轮约 1350 次试错后完全不显著）。年度超额中位数早期 +6.85%、近期 +11.76%。机制上说得通：紧吊灯在下跌段跑得快（2008 超额 +10.10%、2018 +1.69%、2022 +10.71%），代价是在 V 型反转里反复被打（2009 −16.99%、2020 −7.89%、2025 −13.88%）。吊灯从 2.5 收紧到 2 把这个特征放大了：下跌年赚得更多，反转年亏得也更多。

**保留区已被污染**：吊灯选 2×ATR 是因为它在两个窗口上都最好，也就是用了保留区的信息；这已经是同一份保留区的第二轮选参，污染是累积的。+6.10% 不是干净的样本外估计，只能当上界看。

未计入的成本有两类：进出场约 0.4~0.9%/年（按 224 笔/年、单笔占组合 1%、往返 10~20bp 估），以及**组合层假设的每日等权再平衡**——约 100 个持仓每日调回等权，这部分完全没计价，实盘影响大于进出场成本。

### 第一阶段标的池初筛（已实现，默认关闭）

对应「全市场标的池流动性初筛」规格。面板加了 `volume` 列（654 只全覆盖、11MB），
`prepareUniverse` 里预算两个与参数无关的指标：50 日日均成交额、收盘价是否站上 MA200 **或** MA850。
阈值比较放在 `runBacktest`，因为准备段是带缓存的、不能依赖参数。

三道闸门只作用于**入场资格**，不改变基准——基准始终是完整时点成分池的等权买入持有，
否则基准跟着策略口径变，超额就不可比了。

**市值 ≥ 20 亿那条没实现**：面板只存价量，没有历史股本，而标普成分极少跌破 20 亿，
这条在本池内近乎空转。要实现得先建历史股本管道（SEC XBRL 只给最新值）。

| 配置 | 训练区超额 | 保留区超额 | 训练区成交 | 保留区成交 |
| --- | --- | --- | --- | --- |
| 基线（无初筛） | +6.03% | +5.70% | 1684 | 1118 |
| 只加趋势闸门 | **+8.06%** | **+4.68%** | 1190 | 898 |

**成交额与价格两条基本空转**：$30M 门槛只动了 2% 的成交（1684→1652），
价格 $5 门槛在标普成分内几乎无标的触发。留着是为了口径完整。

**趋势闸门是敞口调节器，不是选股器。** 这是本节最重要的结论，两个窗口的分歧可以完全解释：

| | 训练区 | 保留区 |
| --- | --- | --- |
| 持仓日占比 | 97% → **91%** | 100% → **100%** |
| 年化 | +16.64% → **+18.67%** | +13.84% → **12.81%** |
| 最大回撤 | −51.5% → **−33.4%** | −24.6% → −24.5% |
| 年化波动 | 22.1% → 19.6% | 18.2% → 18.6% |

训练区的全部增益来自 2007 与 2008 两年（2008 成交 248→11 笔，超额 +4.03%→+21.28%），
即「熊市里躺平」。保留区它从未降低过组合敞口（持仓日仍是 100%），
于是那五年它纯粹作为选股过滤器工作，结果是**亏 1 个点**。

分年度看，加闸门后 7 年改善、13 年变差。我原先的机制假设是「治 V 型反转」，
**这个假设被否掉了**：2009 从 −17.29% 恶化到 −23.28%（成交 98→20），
它没有让我们在 V 型反转里抄得更准，而是干脆没参与反弹。只有 2025 如预期改善（−13.76%→−8.57%）。

结论：它的价值集中在尾部事件，而样本里只有 2008 一次。**N=1 的证据无法验证一条防崩盘规则。**
但机制是清楚的（不在下跌趋势里抄底，等价于熊市自动降敞口），
且训练区把回撤从腰斩压到三分之一、同时年化还升了 2 个点，这个量级不能忽略。
默认关闭，因为按「两窗口同号且量级相近」的标准它不合格；
要开的话理由应该是控回撤，不是提收益。

另有一处口径缺陷需要记住：本引擎空仓日收益记 0（不计息），而基准始终满仓，
所以**任何降低敞口的规则都会在下跌年显得好、在上涨年显得差**。
趋势闸门主要就是一个敞口旋钮，用超额指标评价它天然有偏。

### RPS 转弱离场（实测无效，但已实现）

原策略只在入场看 RPS，开仓后完全不看。加了可调阈值的转弱离场（`rsExitBelow` / `rpsExit`）后实测：

紧吊灯（2.5×ATR，平均持仓 20 根）下，两个窗口不同意——早期十四年越用越差（无 +6.03% → 门槛 25 时 +2.93%），最近五年大致持平略好。松吊灯（8×ATR，平均持仓 82 根）下确实有一点用（门槛 30 时早期 −0.02% → +0.66%，持仓缩到 51 根），但量级远不及紧吊灯本身能做到的 +6.03%。

机制解释：RPS 由四个季度的回看加权而成，转向很慢；吊灯止损直接盯价格，反应快。两者做的是同一件事——尽早离场——而价格止损做得更好。**出场上快的打败慢的。**

保留该参数是为了让这个结论可复核，默认关闭。

### 交易层的一个机制耦合

`stopMult` 有两重作用，用 `/lab` 时要知道：

1. 只有 `stopMult < trailMult` 时它才是真正生效的止损。否则退出条件 `close < stop || close < trail` 中吊灯位更高、总是先触发，初始止损永不生效
2. 它同时定义 `1R = stopMult × ATR`，因此决定止盈距离

推论：关掉止盈且 `stopMult >= trailMult` 时，拖动止损滑块结果**逐位不变**（已验证：止损 3/3.5/4/5/6/8 全部给出 +0.92% / +2.62%）。UI 上按当前取值动态提示了这一点。

### 截面 RPS 改用绝对涨幅（已实现）

策略规格「阶段二」要求的是**绝对区间涨跌幅**加权后做全市场截面排名：

```
Score_raw = 0.10×Perf_21D + 0.40×Perf_63D + 0.30×Perf_126D + 0.20×Perf_252D
RPS_i     = PercentileRank(Score_raw_i, Universe) ∈ [1, 99]
```

原实现的周期与权重本就符合规格，唯一偏差是**每段都多除了一次 SPY 同期涨幅**，已改为绝对涨幅。

为什么不该除基准：相对强弱由**截面排名**那一步产生，不需要再除一次。
且除基准并不等价于一次单调变换——同一日里四段除的是四个**不同**的基准增长因子，
等于按 `1/gf_bench(L)` 重新加权四项，排名会因此改变。实测新旧排名的 Spearman
在 0.956~0.990 之间，`RPS>=30` 闸门上 6.1% 的股票日发生翻转：是口径校正，不是策略重构。
默认参数的含义因此不变，没有借机重新调参。

两处口径细节：
- 四段都是**累计**区间涨幅（`Perf_126D` = 收盘价 ÷ 126 根前的收盘价），
  不是各区间的分段涨幅。已加单测钉住这一点——两种理解在「长期横盘 + 末段拉升」
  的形态下会差出二十多个分点
- 实现用涨幅比 `close/base × 100`（走平得 100）而非规格里的 `Perf`。
  因权重和为 1，两者恒差常数 100 且对每只标的相同，截面排名完全一致，已加单测
- 分位映射保留「严格小于 + 半个并列」的中位排名法并夹到 [1, 99]，
  未照搬规格里的 `Floor(超越数量 / 总数 × 100)`：后者会让同分标的拿到不同分数，
  且给最弱的标的算出 0，与规格自己标注的 1~99 范围矛盾

连带影响：SPY 退出这条链路。`prepareUniverse` 与 `percentileRsBySymbol` 不再收基准参数，
`load.ts` 的 `BENCHMARK_TICKER` 与 `rotationRadar.ts` 的 `loadBenchmark` 一并删除。
SPY 现在被自然排除在池外——它不是任何指数的成分，没有 `IndexMembership` 行。
这也让下面那个「基准双下标」的 bug 类别彻底不存在了。

线上数据校验（`UNION` 池，701 只，5027 个交易日）：
- 逐日重算：NVDA 的 RPS 从 2015 年的 59.0 走到 2024 年的 99.0，AAPL 88.5 → 79.3 → 94.9 → 59.6
- 引擎的 `percentileRanksFast` 与参考实现 `percentileRank` 最大偏差 **4e-6**（Float32 存储精度）
- 分位分布均匀：p25 = 25.0 / 中位 49.9 / p75 74.7；越界 0 个；非成分被排名 0 只
- 历史合理性：2020-03-23 最弱是 APA/FANG/HAL/OXY/NCLH（能源 + 邮轮），
  2024-01-02 最强是 NVDA/CRWD/PDD/UBER、最弱是 PFE/PARA——对得上真实历史

上面这组数字（含 Spearman 与闸门翻转率）是在 **63/126/189/252、.4/.2/.2/.2** 的
IBD 官方口径下测的：那一版一度替换了规格口径，后按规格退回 21/63/126/252、.1/.4/.3/.2。
两版都是绝对涨幅，所以「除基准 vs 不除」这一结论不受影响；但逐日分位的**具体取值**
属于 IBD 那一版，未在规格口径下重测——当时 Neon 的数据传输配额已用满。

因此把原先靠一次性脚本验的那几条性质固化成了不依赖数据库的单测
（`tests/backtestEngine.test.ts` 的「截面 RPS 的逐日重算」）：
- 同一只标的在不同日期拿到不同分位，且强弱反转会被跟上
  （构造先弱后强与先强后弱两只，验证 21/63 日的大权重确实把反转打出来）
- 某一日的分位逐位等于按当日四周期加权分独立排名的结果
- 预热不足 252 根不评分；非成分日不评分，即便回看已齐
- 有数据但从不是成分的标的不参与排名，且不改变其他标的的分位

### 曾经的基准双下标 bug（已随上一节消失）

`percentileRs.percentileRsBySymbol` 算出了基准下标 `bi` 却把标的自己的下标传给 `alphaScoreAt` 去索引基准序列，晚上市 200 天的标的会读到 200 天前的基准价，涨跌结论可能整个反转。该路径在 `COMMERCIAL_SPEC.percentileRs` 开关后面且默认关闭，线上从未触发。

先用 `benchIndex` 参数修好，之后改成绝对涨幅口径，基准整个退出了计算，这类错位不再可能发生。

### RPS 回看落空的处理（已修）

原实现里，回看窗口不够长时那一段按 `perf = 1`（走平）计入。这等于断言
「这只股票在它上市之前走平」：牛市里基准同期涨 15%，那一段就变成跑输 15% 计入，
新上市或新分拆的标的（ABBV、ALLE 之类，标普池内 156 只起始日晚于日期轴起点）
在入池头一年会被系统性压低分位，熊市则反向抬高。

改为四段回看任一落空即不评分（`alphaScore` 返回 NaN，该标的当日不进截面）。
两处实现口径已统一：`backtest/engine.ts` 与 `scoring/percentileRs.ts`。

没有采用「按剩余权重归一化」这个更宽松的方案：那样一只刚上市 22 天的标的会拿
21 日动量冒充四周期复合分，而新上市标的初期常有暴涨，会被系统性推高——
只是把偏差换了个方向。四周期复合分就该等四段都齐了再算。

配套的两个细节：
- 入场闸门加了 `rps >= 1`（分位下界被夹到 1，故此即「已排名」）。
  只写 `rps >= rpsMin` 的话，`rpsMin = 0` 会把未排名的也放进来
- `rpsExit` 的取值把未排名日填 100 而非 0，否则转弱离场会在预热期无条件触发

### 交易日缺口（已定性，不修）

CVG 在 20 年窗口里缺 102 个交易日，但那是 **100 个互不相邻的单日缺口**，
成交稀疏当天没有成交、Yahoo 返回 null 被抓取层过滤掉了，不是数据错误。
影响是回看窗口被拉长约 2%（252 根 ≈ 257 个交易日），653 只里 4 只有此现象。

不做前向填充：凭空造出的走平 K 线会直接污染 ATR 与 MACD，代价大于收益。
改为在回填脚本里报告缺口异常的标的，让它从静默变成可见。

## 标的池换成纳斯达克 100（已实现，实测不适用）

时点成分数据来自 unliftedq/index-constitution，313 段区间 / 276 个 ticker，
2007–2026 每年都有真实变动记录（年均约 10 次，符合 NDX 实际换手率）。
已验证是真时点数据而非当前成分快照——NFLX 记录为 2010-12 入指、2012-12 被剔除、
2013-06 重新纳入，幸存者偏差的数据集不可能记录到那次剔除与回归。
可用标的 219/313 段有价格（70%），高于标普池的 55%（NDX 换手慢、成分更可能仍在交易）。

用标普池上调出来的那组默认参数实测：

| | 标普 500 | 纳斯达克 100 |
|---|---|---|
| 池内标的 | 653 只 | 193 只 |
| 采纳信号 | 2812 个 | 604 个 |
| 训练区超额 | **+6.10%** | **−13.21%** |
| 保留区超额 | **+5.47%** | **−15.43%** |
| 训练区持仓日 | 97% | 68% |
| 同池基准年化（训练） | +10.61% | +14.73% |

20 组参数扫描（RPS 0/50/70/80/90 × 止盈 无/1R/2R/3R）里**没有一组**两窗口同时为正。
看起来最好的几格（RPS 80，保留区 +8.92%~+13.18%）只有 22 笔成交，训练区全在 −7% 附近，
是小样本凑出来的数字。

两个结构性原因，都不是 bug：

1. **仓位填不满**。193 只标的、截面上同时只有 70~100 只，训练区持仓日只有 68%
   （标普 97%）。空仓日收益记 0，于是错过基准的复利，持仓时又照样吃满回撤
2. **基准本身就是动量篮子**。等权 NDX 训练区年化 +14.73%，比等权标普高 4 个点。
   NDX 是 100 只预先筛选出来的强势科技股，用动量策略去打一个已经满载动量的基准，
   等于跟自己的选股逻辑对赌——策略的超额本来就来自「在分散的池子里挑强势股」，
   池子本身即强势时这层价值就没了

因此默认池仍为标普 500，纳斯达克在 `/lab` 里可切换。注意基准恒为**同一池子**的
等权买入持有，所以两个池子的「超额」不能直接比大小。

## 买点回到通达信原式（已实现，卖点未做）

轮动 Pine 本身是从一份通达信公式移植来的。拿到原式逐条比对后，发现 Pine 在移植时
引入了两处失真，都在买入侧。已按原式修正，`logMacd.ts` 的对齐基准从此是**通达信原式**
而不是 Pine。

映射关系：原式的 `COND_BUY`（图上 'BUY'）对应本项目的**一买**，
`COND_BUY1`（图上 'B'）对应**二买**。

### 修正一：`INTPART` 不是 `math.floor`

原式量级规约用的是 `INTPART`（向零截断），Pine 写成了 `math.floor`（向下取整）。
通达信另有 `FLOOR` 可选，作者选的是前者，这不是笔误。两者在负数上差 1
（`INTPART(-37.5) = -37`，`floor(-37.5) = -38`），而底背离要求 `MACD < 0`、
DIF 通常也在零轴下方，所以这个差别几乎每次判断都会碰上。

**实测在当前池子上近乎无感**：信号数 2998 不变，成交 1792/1201 笔不变，
训练区超额 +8.14% → +8.13%。原因是比较式两侧都是负数、同向各偏 1，
绝大多数情况下比较结果被保留。真正会出事的是 `|LV_D2| < 1` 时——
`INTPART(LOG(0.5)) = 0` 而 `floor(-0.301) = -1`，规约位数整体差一个数量级——
但 DIF 是 `100 × (EMA12 − EMA26)`，百元股的量级在几十，700 只大盘股里碰不到。
换低价股池会显出来。

### 修正二：二买少了顶背离否决项

原式的 `COND_PSVN_DIS` 是四项合取，Pine 只实现了前三项，漏掉 `TOP_DAYS > DC_D1`，
即**死叉之后不许出现过顶背离**。Pine 里根本没定义 `TOP_D`，所以这条无从实现。

现已补上 `TOP_D`（`divergenceTop`）：`TP_DEA_D` 那根上实体上沿创 4 日新高而 DIF 未创新高。
`TOP_D` 本身不是卖点，只作二买的否决项。

从未出现过顶背离时 `barsSince` 为 null，比较取 false 即**否决**而非放行。这与本模块
其余 na 语义一致，实践中只影响序列开头的预热段（5000 根里顶背离出现上百次）。

实测（RPS≥30、止损 4、吊灯 2、止盈 3R、仅二买）：

| | 补否决前 | 补否决后 |
|---|---|---|
| 采纳信号 | 1408 | 1250 |
| 训练区成交 / 超额 | 851 笔 / −10.62% | 725 笔 / **−10.34%** |
| 保留区成交 / 超额 | 557 笔 / −0.83% | 525 笔 / **−2.65%** |
| 保留区盈亏比 | 2.01 | 2.05 |

砍掉约 11% 的信号，两窗口一升一降，方向不一致，属噪声级变化。**结论是这条否决项
不改变二买没用这个事实**——二买单独跑在两个窗口都是负超额，所以默认仍是
`useBuy2: false`。补它的理由是对齐规格，不是为了提升表现。

### 未做：整个卖出侧

原式有一套完整的 'S' 信号——`TOP_D_DIRECT` / `TOP_D_INDIRECT`（底背离的镜像，走 `HHV` 与金叉）、
`COND_BTM_SELL`、以及趋势破位的 `COND_TOP_SELL`（收盘跌破 `EMA(L,25) × 0.99` 且此前长期站稳）。
本项目用 ATR 吊灯止损 + 初始止损 + R 倍数止盈替代，原式里没有这套东西。

这是全部偏离里最大的一处，而且第六节调的那些参数调的正是这套**原式中不存在**的出场机制。
形态出场与波动率出场哪个更好没有实测过，是个待办。

### 也未做：`FILTER` 的去重语义

原式 `FILTER(X,10)` 按**已发出的信号**计抑制窗口，Pine 的 `ta.barssince(cond[1]) > 10`
按**原始条件成立**计。举例，原始条件在第 0/5/11 根成立：原式发出第 0 与第 11 根，
Pine 一个都不发（第 0 根 `barssince` 为 na；第 11 根距上次成立只有 6 根）。

Pine 版本明显更严，第一个信号永远不发，密集出现的原始条件会互相永久压制，
因此本项目的信号数少于原策略。此处按用户决定不改。

### 面板加了 `open` 列

`TP_P := MAX(C, O)` 要开盘价，而回测面板原本只存高/低/收。已加 `open` 列
（缓存 59.8MB → 71.8MB，`panelCache` 版本号 1 → 2），Prisma 侧为可空，
与 `volume` 同一套先例。为空时实体上沿退化为收盘价，只影响二买的否决项。

## 成交时点改为次日开盘（已实现）

来源是一份出场规格的截图，其第 4 条写「盘中收盘价跌破当前动态止损/止盈线时触发平仓事件，
**次日开盘无条件市价清仓**」。这条指出了此前实现的一个真问题。

### 为什么原来的填价拿不到

点火条件（底背离）与出场条件（`close < max(sl, trail)`）全部取自收盘价，而收盘价要等收盘
之后才存在。Pine 以及本项目此前的实现都按信号当根的收盘价成交，等于在知道收盘价的同时
还能按它成交。挂 MOC 单也做不到——MOC 必须在不知道收盘价时提交，无法以「收盘破线」为条件。

两腿同向偏乐观，而**开仓那腿更重**：底背离的信号根通常是局部低点，这个策略的全部优势就在买得低。

### 改法

`rotationTrade` 改成挂单模型：收盘产生 `pendingEntry` / `pendingExit`，次日开盘按
`bar.open ?? bar.close` 成交。ATR 一并留存（`pendingEntryAtr`），因为开盘时只知道到前一根的
ATR，止损与吊灯初值按真实成交价而非信号根收盘价计。`TradeDay.entered` / `exited` 的语义
随之从「触发日」变为「成交日」。

组合层的日收益口径必须同步改，否则会算错：建仓日只吃 `open→close`，清仓日只吃
`prevClose→open`，中间才是收盘到收盘。基准是买入持有、不涉及成交时点，仍按收盘到收盘计。

### 代价

| --- | --- | --- | --- | --- | --- | --- | --- |
| 收盘成交（旧） | 18.92% | +8.13% | -46.5% | 13.92% | +6.10% | -29.2% | -30.16% |
| 次日开盘成交 | 16.48% | +5.69% | -40.1% | 11.34% | +3.51% | -25.2% | -31.33% |

### 单笔风险约束（已实现，实测有害，默认关闭）

规格第 1 条：「按止损点位距离计算头寸，单笔最大允许风险 ≤ 基金总净值的 0.8%」。
已实现为 `riskBudgetPct`：仓位 = 该值 ÷ 止损距离占开仓价的百分比，权重之和封顶 1（不加杠杆），
不足的部分记现金、收益为 0。`null` 表示退回每日等权。等权走的是同一条加权路径
（各持仓权重记 1，缩回后正好是除以只数），已验证能精确复现改动前的数字。

| `riskBudgetPct` | 训练敞口 | 训练年化 | 训练超额 | 训练回撤 | 保留敞口 | 保留年化 | 保留超额 | 保留回撤 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| null（等权） | 95% | +16.48% | +5.69% | -40.1% | 99% | +11.34% | +3.51% | -25.2% |
| 0.8（规格值） | 53% | +6.66% | -4.13% | -23.8% | 75% | +8.68% | +0.86% | -14.4% |
| 5.0（敞口对齐） | 90% | +11.45% | +0.66% | -45.9% | 99% | +11.40% | +3.58% | -21.2% |

0.8% 是**基金级**风险政策，隐含假设并发持仓多到能铺满资金。本策略并发持仓不够
（止损距离约 10~16%，单笔权重 5~8%，要 12~20 个并发才满仓，训练区实际只有七八个），
于是一半时间在现金里而基准恒满仓。那一行看似风险调整后漂亮，但同样效果把一半钱存银行、
剩下一半跑等权也能得到，而且现实中现金还有利息（本引擎记 0）。**那不是定仓规则的功劳，
是降杠杆的功劳。** 要归因就得把敞口对齐。

对齐后（budget 5.0，敞口 90%/99%）结论是负的：训练区收益更低、回撤还更大，严格被支配；
保留区收益打平，只换到回撤从 -25.2% 到 -21.2%。

机制是清楚的。按止损距离（即波动率）把单笔五等分：

| | 止损距离 | 风险平价相对权重 | 单笔均值 | 最好一笔 | 收益 >30% 占比 |
| --- | --- | --- | --- | --- | --- |
| 训练 Q1 | 5.9% | 0.169 | +1.06% | +22% | 0.0% |
| 训练 Q5 | 26.5% | 0.038 | +2.46% | +45% | 3.1% |
| 保留 Q1 | 6.9% | 0.146 | +1.08% | +25% | 0.0% |
| 保留 Q5 | 17.5% | 0.057 | +4.15% | +63% | 6.7% |

单笔均值随止损距离单调上升，收益超过 30% 的交易全部落在后两组，最好那笔 +63% 在 Q5。
风险平价按定义给 Q5 最小权重（训练区比 Q1 低 4.4 倍），即系统性压低唯一产生大赢家的那一桶。

一个反直觉的细节，否则这个结论看着过于顺理成章：换成 R 倍数排序是反过来的
（训练 Q1 约 0.18R、Q5 约 0.09R），每单位风险的效率是紧止损的票更高。所以风险平价不是「错」，
它买到的是单笔风险效率、卖掉的是右尾；对一个靠右尾赚钱的策略这笔交易不划算。

副作用是 `stopMult` 第一次有了真实作用：启用风险预算后它决定每笔下多少钱，
而不再只经由 `takeProfitR × stopMult` 影响止盈距离。但既然默认关闭，第 307 行那个耦合仍然在。

### 新执行模型下的重搜（结论：不换默认值）

同一张 1260 组网格在次日开盘成交下重跑一遍。整体水平明显下移：近五年超额中位
+0.84%、p75 +2.61%、p90 +4.45%，两窗口同时为正的组从旧模型的比例掉到 28%。

按两窗口较小值排序的榜首是 `RPS40 止损3 吊灯4 止盈2R 二买`（早期 +5.67% / 近五年 +12.89%，
323 笔）。这一组不可用：RPS 轴上它是尖峰而非平台，相邻档 30 / 35 / 50 分别是 -0.32% /
-0.36% / -0.91%（早期），把 RPS 挪到 20 则只剩 +0.81% / +1.50%。优势在门槛取值上，不在二买信号上。

一买分支的整个面又平又低，各轴基本在 ±2% 内。分支内最好的一组是
`RPS30 止损4 吊灯2.5 止盈2R 一买`（早期 +4.25% / 近五年 +5.53%，1199 笔），邻域比二买那组
干净得多。它与现行默认值只差两档：吊灯 2 → 2.5、止盈 3R → 2R，代价是早期从 +5.69% 降到 +4.25%。
这个量级落在 1260 组搜索的 p75~p90 之间，与噪声不可区分，且保留区已是第三轮被用于择优，
故不换——换了只是把第四轮拟合叠上去。

一个容易过度推广的读数：二买分支的稳定性扫描显示吊灯轴单调偏好放宽（1 → -1.29%，
6 → +17.10%，近五年），但这不是普遍结论。一买分支上该轴的峰在 2~2.5，放宽到 4 掉到 +0.96%。
两个分支的最优吊灯宽度不同。

`stopMult` 仍然结构性失效：在 `止盈无 + 吊灯4` 的扫描里，初始止损从 4 到 8 的四档超额
完全相同（+0.68% / +1.61%），因为止损一旦松过吊灯位就永不触发。它在止盈开启时之所以看起来
有影响，是经由 `takeProfitR × stopMult × ATR` 这个耦合传导的，不是止损本身在起作用。

## 出场砍到只剩一条规则（已实现）

出场侧一直挂着五样东西，实测只有一样在干活。1792 笔的离场归因是止损 1779 / 止盈 13，
即吊灯移动止损做了 99.3% 的工作，其余是装饰：

- 初始止损 `stopMult=4` 比吊灯 `2` 宽，**永不触发**，只经由 1R 的定义影响止盈距离
- R 倍数止盈 `3R` 折算成 12×ATR，1792 笔里只碰到 13 次
- 阶梯收紧的四个常数，换成规格值也没差别（见上文）
- RPS 转弱离场、风险定仓，已经默认关闭

于是把止盈关掉，`takeProfitR` 默认值 3 → null。三组对照：

| | 训练年化 | 训练超额 | 保留年化 | 保留超额 | 保留回撤 |
| --- | --- | --- | --- | --- | --- |
| 止损4 吊灯2 止盈3R（旧默认） | +16.48% | +5.69% | +11.34% | +3.51% | -25.2% |
| **吊灯2 + 保本锁，无止盈（现默认）** | +16.20% | +5.41% | +11.19% | +3.37% | -25.2% |
| 吊灯2.5 + 保本锁，无止盈 | +13.65% | +2.86% | +11.52% | +3.69% | -22.5% |

止盈值 0.14 个保留区百分点，在噪声里。第三行拿回撤换 2.5 个训练区百分点，不划算。

这个改动与本文件记录的其他调参方向相反：它**减**自由度，且退回 Pine 原策略的行为
（原策略没有止盈）。去掉一个参数会让保留区估计更可信，而不是更不可信。

改完后出场归因是 1792 / 0，再没有名义存在、实际不触发的规则。代价是 `stopMult`
变得完全惰性——比吊灯宽故永不触发，此前仅剩的止盈距离通道也没了。参数保留是为了能测，
不是因为它在起作用；`/lab` 的滑块提示里已写明此时拖动它不会有任何变化。
